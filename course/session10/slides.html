Goal 1 · When Python helps

Explain when Python can help a research project.

  • A research package or collaborator’s model already uses Python.
  • The team’s data-processing workflow uses Python tools.
  • A suitable library provides the numerical or GPU operations we need.

Which part of the research task would Python help us do?

R remains our main analysis language. We choose tools for the task.

Large data: when memory becomes a constraint

Suppose a research team has 200 GB of patient-visit records and a laptop with 16 GB of RAM. How could they compute a summary by clinic?

  • Loading the entire table into memory is impractical.
  • Python can coordinate reading subsets and processing data in batches.
  • pandas also works primarily in memory. Switching languages alone does not remove the memory limit.

Large data: strategies and Python’s role

Strategy Patient-visit example
Read less data Select the needed years and columns
Process batches Accumulate clinic sums and observed counts
Query a database Return a small summary instead of all records

Python is useful when the team’s data pipeline or required tools already use it. R can use these strategies too.

The decision starts with the workload and available memory.

Speed: Python versus R

Python is not generally faster than R for large tables.

Task What determines speed?
Read a large file Reader, file format, data types, and disk speed
Add a column Vectorized calculation and unnecessary data copies
Calculate a mean Numerical implementation, data type, and missing values
Save a large file Writer, file format, compression, and disk speed

R has fast tools too: data.table::fread() / fwrite() for CSV and := for column updates. Both languages have vectorized numerical operations.

When a Python workflow can be faster

The comparison must name the implementation on both sides.

Task Python approach Compared with this R approach
Read a large CSV Optimized C/Arrow reader Base read.csv()
Repeated numerical calculations NumPy operations or compiled loops An interpreted loop over elements
Train a large neural network GPU operations through PyTorch CPU-only training

These are possible advantages, not guaranteed wins over optimized R. R also has optimized readers, compiled code, and GPU interfaces.

Measure the actual workflow: same data and results, including missing values, with reading, processing, and saving timed separately.

Deep learning: why Python is useful

A collaborator shares a Python neural-network model for research on medical images. What would we need to understand to use their code?

  • Images contain arrays of pixel values that become model inputs.
  • Libraries such as PyTorch provide tensors and tools for training models.
  • A tensor is a multidimensional array used for data and model parameters.
  • Python knowledge helps us read and adapt the collaborator’s workflow.

GPUs: why they help deep learning

  • Training repeatedly performs matrix operations on data and model parameters.
  • A GPU can perform many numerical operations in parallel.
  • Python libraries send supported operations to the GPU. Python syntax alone does not provide the acceleration.
  • Benefits depend on the workload. Data transfers and limited GPU memory also matter.

For this session: understand the use case. No GPU or extra software is required.

Goal 3 · Recognize Python data objects

Recognize lists, NumPy arrays, and pandas DataFrames.

Object Typical use Familiar R comparison
Python list Sequence that can mix types R list
NumPy array Typed numerical data and arithmetic Atomic vector or matrix
pandas DataFrame Rows and named columns Data frame / tibble

A pandas Series is one labeled column. A DataFrame can contain columns of different types.

Assignment and basic objects

age = 42
group = "treated"
observed = True
values = [4.1, 5.2, None]

Python uses = for assignment and indentation to define blocks. A Python list can contain mixed types; it is not a NumPy array.

Lists and arrays behave differently

values = [1, 2, 3]
values * 2                   # [1, 2, 3, 1, 2, 3]

x = np.array([1.0, 2.0, 3.0])
x * 2                        # array([2., 4., 6.])
x.mean()                     # 2.0
x <- c(1, 2, 3)
x * 2                        # 2 4 6
mean(x)                      # 2

Check: which Python object supports the arithmetic you intended?

Goal 4 · Translate one familiar analysis

Translate selection, transformation, and grouped summaries.

Run r-reference.R in R to load the matching data. In both languages:

  1. Keep all week-4 rows, including missing outcomes.
  2. Add a month column from week / 4.
  3. Summarize within randomized arm.
  4. Report total n, observed n, mean, and sample SD.

The output has one row per arm. Missing outcomes contribute to total n.

Column and row selection

visit[["marker"]]                  # a vector
visit["marker"]                    # a one-column data frame
visit[visit$week == 4, ]            # week-4 rows
visit["marker"]                    # a Series
visit[["marker"]]                  # a one-column DataFrame
visit.loc[visit["week"] == 4, :]    # week-4 rows, all columns

loc accepts column labels and a Boolean row condition.

Keep the analysis population intact

week4 <- visit[visit$week == 4, ]
nrow(week4)                         # 6
week4 = visit.loc[visit["week"] == 4].copy()
len(week4)                         # 6

Both keep six rows, including the two missing outcomes.

Dropping missing outcomes now would reduce the total denominator.

Add a derived column

week4$month <- week4$week / 4
week4 = week4.assign(month=week4["week"] / 4)
week4[["id", "week", "month"]]

The new month value is 1 for every retained row.

The transformation adds a column and keeps the same six rows.

The familiar R grouped summary

library(dplyr)

r_summary <- week4 |>
  summarise(
    n_total = n(),
    n_observed = sum(!is.na(marker)),
    mean_marker = mean(marker, na.rm = TRUE),
    sd_marker = sd(marker, na.rm = TRUE),
    .by = arm
  )

Count all rows for total n. Use observed outcomes for the mean and SD.

The corresponding pandas summary

summary = week4.groupby("arm", as_index=False).agg(
    n_total=("id", "size"),
    n_observed=("marker", "count"),
    mean_marker=("marker", "mean"),
    sd_marker=("marker", "std"),
)

size counts rows. count counts nonmissing values in the named column.

Each output name maps to a column and an operation.

Goal 5 · Indexing and missing values

Compare missing-value and indexing behavior with R.

Action R Python / NumPy
First element x[1] x[0]
First two elements x[1:2] x[0:2]
Negative index x[-1] drops the first x[-1] selects the last

Python positions start at 0. A positional slice excludes its stop value.

Predict the slice before running

x = np.array([10, 20, 30, 40])
x[1:3]
x[-1]
  • x[1:3] returns 20, 30: the stop position is excluded.
  • x[-1] returns the last element; it does not exclude position 1 as in R.

pandas labels and positions

week4.index.tolist()        # [1, 3, 5, 7, 9, 11]
week4.iloc[0:2]            # first two rows by position
week4.loc[1:3]             # labels 1 through 3, inclusive
  • iloc selects by position and excludes the slice’s stop.
  • loc selects by label and includes the ending label in a slice.
  • Filtering retains the original index labels. They need not start at 0.

Check: why would week4.loc[0] fail for this table?

Compound conditions need elementwise logic

This selects the treated week-4 rows, including any missing outcomes:

visit[visit$week == 4 & visit$arm == "treated", ]
visit.loc[
    (visit["week"] == 4) & (visit["arm"] == "treated")
]

In pandas, use & / | with parentheses around each condition. Python’s and / or cannot combine these Boolean Series.

Missing-value defaults differ

The control outcomes are 4.4, missing, and 4.8:

mean(c(4.4, NA, 4.8))                    # NA
mean(c(4.4, NA, 4.8), na.rm = TRUE)      # 4.6
pd.Series([4.4, np.nan, 4.8]).mean()      # 4.6
np.array([4.4, np.nan, 4.8]).mean()       # nan
np.nanmean([4.4, np.nan, 4.8])            # 4.6

The object and function determine the default. pandas skips missing values here. NumPy’s ordinary mean does not.

Python has several missing-value representations

Value Common context Check with pandas
None general Python object isna()
np.nan floating-point array/data isna()
pd.NA nullable pandas dtype isna()

Use pandas missing-value checks for DataFrame work; do not compare a value to np.nan with ==.

Goal 6 · Verify R and Python results

Verify equivalent R and Python results.

Compare Evidence for this analysis
Input and selected rows 12 visits, 6 week-4 rows, unique ID/week pairs
Groups and counts Both arms, total n = 3 and observed n = 2
Numerical results Matching means and sample SDs within a tolerance
Reproducibility Saved source runs from a fresh interpreter

We will turn these expectations into checks that fail when a result is wrong.

Reference results from the R analysis

The starter contains r_reference, matching the supplied R script:

r_reference = pd.DataFrame({
    "arm": ["control", "treated"],
    "n_total": [3, 3],
    "n_observed": [2, 2],
    "mean_marker": [4.6, 4.85],
    "sd_marker": [0.282842712474619, 0.353553390593274],
})

Keep the reference separate from the Python result you are checking.

Exact checks for rows and counts

assert visit.shape == (12, 4)
assert not visit.duplicated(["id", "week"]).any()
assert len(week4) == 6

actual = summary.sort_values("arm").reset_index(drop=True)
expected = r_reference.sort_values("arm").reset_index(drop=True)
for col in ["arm", "n_total", "n_observed"]:
    assert actual[col].tolist() == expected[col].tolist()

assert stops with an error if a condition is false. Sort both tables by arm so the rows represent the same groups.

Numerical checks with a stated tolerance

estimates = ["mean_marker", "sd_marker"]
np.testing.assert_allclose(
    actual[estimates].to_numpy(),
    expected[estimates].to_numpy(),
    rtol=0, atol=1e-12, equal_nan=False,
)
print("R and Python checks passed")

For this small example, each estimate must differ by at most 0.000000000001. Unexpected missing estimates fail the check.

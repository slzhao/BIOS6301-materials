1 · The block you have written four times

Look at what you have been doing

# session 6 — baseline SBP by arm
trial |> group_by(arm) |>
  summarise(n = n(), mean = mean(sbp_0), sd = sd(sbp_0))

# session 7 — the same, after the join
trial |> group_by(arm) |>
  summarise(n = n(), mean = mean(sbp_12), sd = sd(sbp_12))

# session 8 — weight, to annotate the figure
trial |> group_by(arm) |>
  summarise(n = n(), mean = mean(weight_kg), sd = sd(weight_kg))

# coursework — age, for the baseline table
trial |> group_by(arm) |>
  summarise(n = n(), mean = mean(age), sd = sd(age))

Four blocks. One name differs.

What copy-paste actually costs

Cost What it looks like in a week
Reading A reader has to diff four blocks to find the one word that differs
Changing The data gains missing values. You need na.rm = TRUE in four places, and you will find three
Naming The block has no name, so you cannot say what it does, reuse it, or check it
Divergence One copy already rounds to two digits and the others do not. Nobody decided that

Duplication is not an aesthetic problem. It is the mechanism by which two parts of one analysis come to disagree.

By the end of today that block is one line:

summarise_by_arm(trial, sbp_0)

2 · if is control flow, not ifelse()

Closing a loop from session 3

ifelse(test, yes, no) if (cond) ... else ...
Is a vectorized function control-flow keyword
Test length Any — one answer per element Exactly one TRUE or FALSE
Returns A vector as long as test Whatever the chosen branch returns
Used for Deriving a variable from a column Choosing what a script does
Taught in Session 3 Today

ifelse() derives a variable. if decides what the program does.

if, else if, else

if takes one TRUE or FALSE and picks a branch.

n_missing <- sum(is.na(trial_raw$sbp_12))

if (n_missing == 0) {
  "complete outcome data"
} else if (n_missing < 5) {
  "a few missing — a complete-case summary is defensible"
} else {
  "too much missing outcome data to summarise naively"
}
[1] "a few missing <U+2014> a complete-case summary is defensible"
  • The condition is a single logical value. Here, n_missing == 0.
  • else must sit on the same line as the closing }, or R decides the if has ended.
  • Braces are optional for one-line bodies. Use them anyway.

The error you will actually hit

if (trial$sbp_0 > 140) "high" else "normal"
Error in if (trial$sbp_0 > 140) "high" else "normal": the condition has length > 1

trial$sbp_0 has length 60. if wanted length one.

Two neighbours worth recognising:

if (NA > 1) "yes" else "no"
Error in if (NA > 1) "yes" else "no": missing value where TRUE/FALSE needed
sbp <- numeric(0)          # a filter that matched nobody
if (sbp > 140) "high"
Error in if (sbp > 140) "high": argument is of length zero

Which one do I want?

The question you are asking The tool
“What value does each patient get?” ifelse(), if_else(), case_when()
“What should this script do next?” if / else if / else

And if is an expression, so it returns a value:

label <- if (n_missing > 0) "complete-case" else "all randomised"
label
[1] "complete-case"

If the answer has one value per row, it is not a job for if. Not ever.

A function is three things

Formals — the arguments it accepts, and their defaults · body — the code it runs · environment — where it looks for names it does not define itself.

Your first function, from your own code

The duplicated block, in one place:

# Return n, mean, and SD of a numeric vector, rounded.
sbp_summary <- function(x, digits = 1) {
  round(c(n = length(x), mean = mean(x), sd = sd(x)), digits)
}

sbp_summary(trial$sbp_0)
    n  mean    sd 
 60.0 149.5  11.9 
sbp_summary(trial$sbp_12)
    n  mean    sd 
 60.0 141.6  15.1 
sbp_summary(trial$weight_kg, digits = 2)
    n  mean    sd 
60.00 83.22 15.76

Three calls, one definition. The name now says what the block does, which the block itself never did.

Arguments and defaults

# n counts non-missing values, so the reported n matches the mean.
sbp_summary <- function(x, digits = 1, na_rm = TRUE) {
  round(c(
    n    = sum(!is.na(x)),
    mean = mean(x, na.rm = na_rm),
    sd   = sd(x, na.rm = na_rm)
  ), digits)
}

sbp_summary(trial_raw$sbp_12)
    n  mean    sd 
 57.0 141.3  15.3 
sbp_summary(trial_raw$sbp_12, na_rm = FALSE)
   n mean   sd 
  57   NA   NA

A default is what the argument is when the caller says nothing. Choose the safe, common case — then let the caller override it.

How R matches arguments

Three ways, tried in this order: exact name, then partial name, then position.

sbp_summary(trial$sbp_0, 2)                 # position
     n   mean     sd 
 60.00 149.47  11.85 
sbp_summary(digits = 2, x = trial$sbp_0)    # exact name — order stops mattering
     n   mean     sd 
 60.00 149.47  11.85

Partial matching works, and is a trap:

report <- function(x, na_rm = FALSE, names = TRUE) "ok"
report(1, n = TRUE)
Error in report(1, n = TRUE): argument 2 matches multiple formal arguments

House rule: data argument by position, everything else by full name. Partial names break the day somebody adds an argument.

Return values, and the implicit return

A function returns the value of its last evaluated expression.

mean_sbp   <- function(x) mean(x)          # implicit return
mean_sbp_2 <- function(x) return(mean(x))  # identical, more typing
mean_sbp_3 <- function(x) { m <- mean(x) } # returns m, invisibly

mean_sbp(trial$sbp_0)
[1] 149.4667
mean_sbp_3(trial$sbp_0)      # prints nothing
print(mean_sbp_3(trial$sbp_0))
[1] 149.4667

Use return() for an early exit. For the value at the end, let it fall out.

What happens inside stays inside

centre_sbp <- function(x) {
  offset <- mean(x)      # local: created on the call, destroyed after
  x - offset
}

centred <- centre_sbp(trial$sbp_0)
round(head(centred, 4), 1)
[1] 10.5 12.5  7.5  7.5
exists("offset")
[1] TRUE

Every call gets a fresh environment. Locals cannot leak into your workspace, and two calls cannot interfere with each other.

<<- writes to the enclosing environment and defeats all of this. You will meet it in inherited code. Do not write it.

... and invisible()

... collects arguments you did not name and passes them on:

mean_sbp <- function(x, ...) mean(x, ...)

[1] NA
mean_sbp(trial_raw$sbp_12, na.rm = TRUE)

  cat("n =", nrow(data), "\n")

4 · Lexical scoping, and globals

Where R looks for a name

Step 2 is where the function was written, not where it was called from. That is what “lexical” means.

The global that vanishes

threshold <- 140

is_high <- function(sbp) sbp > threshold   # threshold is not an argument

sum(is_high(trial$sbp_0))
[1] 50

It works. Now restart R — or hand the script to a colleague:

rm(threshold)
sum(is_high(trial$sbp_0))
Error in is_high(trial$sbp_0): object 'threshold' not found

This is the honest failure. It is annoying, and it tells you immediately.

The global that is stale

threshold <- 140
sum(is_high(trial$sbp_0))
[1] 50

Fifty lines further down the document, somebody — possibly you, last Tuesday — writes:

threshold <- 160        # for the sensitivity analysis
sum(is_high(trial$sbp_0))
[1] 8

No error. No warning. A different number, and the function looks untouched.

Everything comes in through an argument

# Flag patients above a systolic threshold. Threshold is an argument so the
# result depends only on what the caller passed.
is_high <- function(sbp, threshold = 140) {
  sbp > threshold
}

sum(is_high(trial$sbp_0))
[1] 50
sum(is_high(trial$sbp_0, threshold = 160))
[1] 8

The rule: a function’s return value should depend only on its arguments. Nothing else.

The sensitivity analysis is now a second call, visible on the page, instead of a reassignment fifty lines away.

5 · Input validation

Fail loudly, or be wrong quietly

mean_weight <- function(weight_kg) mean(weight_kg)

mean_weight(trial_raw$weight_kg)   # one weight is recorded as -99
[1] 80.275
mean_weight(trial$weight_kg)       # the same cohort, repaired
[1] 83.22

80.3 kg against 83.2 kg. Both are plausible. Only one is right, and the function had no opinion about which.

Important

A function that fails loudly on bad input is safer than one that returns a plausible wrong answer.

stopifnot()

sbp_summary <- function(x, digits = 1) {
  stopifnot(is.numeric(x), length(x) > 0, digits >= 0)

  round(c(n = sum(!is.na(x)), mean = mean(x, na.rm = TRUE)), digits)
}

sbp_summary(trial$arm)
Error in sbp_summary(trial$arm): is.numeric(x) is not TRUE

Name the checks and you choose the message:

sbp_summary <- function(x, digits = 1) {
  stopifnot(
    "x must be a numeric vector" = is.numeric(x),
    "digits must not be negative" = digits >= 0
  )
  round(mean(x, na.rm = TRUE), digits)
}

sbp_summary(trial$arm)
Error in sbp_summary(trial$arm): x must be a numeric vector

stop() and guard clauses

# Mean weight, refusing sentinel codes. Site 3 used -99 for "not recorded",
# and averaging those understates the mean by about 3 kg.
mean_weight <- function(weight_kg) {
  if (any(weight_kg < 20, na.rm = TRUE)) {
    stop("weight_kg contains values below 20: check for sentinel codes",
         call. = FALSE)
  }
  mean(weight_kg, na.rm = TRUE)
}

mean_weight(trial_raw$weight_kg)
Error: weight_kg contains values below 20: check for sentinel codes

A guard clause is a check at the top that exits early. It keeps the happy path unindented and the failure cases visible.

How much validation is enough

Check Because
Type and shape is.numeric(), is.data.frame(), length(), column names present
Values that cannot be real Negative weights, ages over 120, proportions above 1
What your code silently assumes Sorted rows, one row per patient, non-empty groups

Do not re-check what R already checks. mean("a") errors on its own.

Rule of thumb: validate what a collaborator’s file could plausibly get wrong. Two or three checks is usually right.

6 · Functions that take data frames

Data argument first

When the column names are fixed, nothing special is needed:

# Add change from baseline. Fails if the two SBP columns are absent, because
# mutate() would otherwise create a column full of nothing useful.
add_change <- function(data) {
  stopifnot(is.data.frame(data),
            all(c("sbp_0", "sbp_12") %in% names(data)))

  data |> mutate(change = sbp_12 - sbp_0)
}

trial_raw |> add_change() |> summarise(mean_change = mean(change, na.rm = TRUE))
  mean_change
1   -7.614035

Data first, so the function drops into a pipeline like any dplyr verb.

The wrinkle: { var }

When the column itself is the argument, dplyr needs to be told:

summarise_by_arm <- function(data, outcome) {
  data |>
    group_by(arm) |>
    summarise(
      n    = sum(!is.na({{ outcome }})),
      mean = round(mean({{ outcome }}, na.rm = TRUE), 1)
    )
}

summarise_by_arm(trial_raw, sbp_12)

7 · Refactoring, and house style

Before: the script we all wrote

# baseline
tab_0 <- trial |> group_by(arm) |>
  summarise(n = n(), mean = round(mean(sbp_0), 1), sd = round(sd(sbp_0), 1))

# 12 weeks
tab_12 <- trial |> group_by(arm) |>
  summarise(n = n(), mean = round(mean(sbp_12), 1), sd = round(sd(sbp_12), 1))

# change — and this one has NAs, so it needs na.rm
tab_ch <- trial |> group_by(arm) |>
  summarise(n = n(), mean = round(mean(change, na.rm = TRUE), 1),
            sd = round(sd(change), 1))     # <- na.rm missing here

ggplot(trial, aes(arm, sbp_0)) + geom_boxplot() + labs(y = "SBP baseline")
ggplot(trial, aes(arm, sbp_12)) + geom_boxplot() + labs(y = "SBP 12 wk")
ggplot(trial, aes(arm, change)) + geom_boxplot() + labs(y = "Change")

Six blocks, two shapes, one bug — and n is wrong in the third block for the same reason.

After: three functions

# n counts patients contributing to the mean, not patients randomised.
summarise_by_arm <- function(data, outcome, digits = 1) {
  stopifnot(is.data.frame(data), "arm" %in% names(data))

  data |>
    group_by(arm) |>
    summarise(
      n    = sum(!is.na({{ outcome }})),
      mean = round(mean({{ outcome }}, na.rm = TRUE), digits),
      sd   = round(sd({{ outcome }}, na.rm = TRUE), digits)
    )
}

# One boxplot of an outcome by arm, labelled for a clinical reader.
plot_by_arm <- function(data, outcome, y_label) {
  ggplot(data, aes(arm, {{ outcome }}, fill = arm)) +
    geom_boxplot(alpha = 0.7, width = 0.5) +
    labs(x = NULL, y = y_label) +
    theme(legend.position = "none")
}

summarise_by_arm(trial_raw, change)
# A tibble: 2 x 4
  arm           n  mean    sd
  <chr>     <int> <dbl> <dbl>
1 Placebo      28  -1.9   6.9
2 Treatment    29 -13.2   9.1

Verify the refactor

A refactor that changes the output is not a refactor. Check.

old <- trial |>
  group_by(arm) |>
  summarise(n = sum(!is.na(sbp_0)),
            mean = round(mean(sbp_0), 1),
            sd = round(sd(sbp_0), 1))

new <- summarise_by_arm(trial, sbp_0)

identical(old, new)
[1] TRUE
all.equal(old, new)
[1] TRUE

identical() is exact and unforgiving. all.equal() tolerates floating-point difference — which is why it is the right one for numbers. Both in session 12.

House style for functions

Rule In practice
Verbs for functions, nouns for objects summarise_by_arm(), not arm_summary()
snake_case, no exceptions plot_by_arm, not plotByArm
One job per function If the name needs “and”, it is two functions
About 30 lines Longer means it is doing more than one thing
Data argument first So it pipes
Validate inputs Two or three checks, at the top
One line above saying what it does What it takes, what it returns
Comments say why The code already says what

All of this is in style-guide.md, §7. Code quality is graded on it.

Summary

  • if controls one decision; vectorized conditionals classify many values.
  • A function is an interface: arguments in, one predictable result out.
  • Local objects and explicit arguments avoid stale global dependencies.
  • Guard clauses turn silent wrong answers into informative failures.
  • Refactoring is complete only after the new result matches a trusted result.

Complete-case filtering is explicit here for teaching. It changes the population being analysed and may introduce bias; it is not a universal missing-data strategy.

Read a model formula

f <- sbp_12 ~ sbp_0 + age + arm
f
sbp_12 ~ sbp_0 + age + arm

The response is left of ~; the terms on the right specify predictors. An intercept is included by default. In formulas, + adds model terms rather than adding the columns numerically.

Use data = analysis so the intended source of variables is clear.

Factors determine the comparison

analysis$arm <- factor(analysis$arm, levels = c("Control", "Treatment"))
levels(analysis$arm)
[1] "Control"   "Treatment"
contrasts(analysis$arm)
          Treatment
Control           0
Treatment         1

With the treatment contrasts used here, Control is the reference. armTreatment represents the Treatment-versus-Control coefficient conditional on the other terms in this additive model.

Changing the reference changes coefficient interpretation, not the fitted values.

2 · Prediction and diagnostics

Construct prediction data deliberately

new_people <- data.frame(sbp_0 = c(140, 155), age = c(55, 65),
  arm = factor(c("Control", "Treatment"), levels = levels(analysis$arm)))
predict(fit, newdata = new_people)
       1        2
136.0147 144.4334

Match predictor names, units, and factor levels. Do not substitute fitted(fit) for predictions on new rows; fitted values describe the training observations.

Mean-response and prediction intervals

mean_ci <- predict(fit, new_people, interval = "confidence")
person_pi <- predict(fit, new_people, interval = "prediction")
round(cbind(mean_ci, prediction_lower = person_pi[, "lwr"],
                     prediction_upper = person_pi[, "upr"]), 2)
     fit    lwr    upr prediction_lower prediction_upper
1 136.01 133.60 138.43           122.97           149.06
2 144.43 142.07 146.80           131.39           157.47

The confidence interval concerns the conditional mean response. The prediction interval concerns an individual future response and also includes residual variation. Both depend on the model’s assumptions.

Unsupported predictions

  • A new factor level may prevent prediction.
  • Extrapolation can return a number even far outside the training data.
  • A response-derived predictor may be unavailable at deployment.
  • A narrow model-based interval does not measure every source of uncertainty.
range(analysis$sbp_0)
[1] 103.4681 180.0144
range(new_people$sbp_0)
[1] 140 155

Inspect prediction inputs before interpreting outputs.

Residuals versus fitted values

Look for curvature, changing spread, and unusual observations. A pattern suggests follow-up questions; absence of a visible pattern is not proof of adequacy.

3 · Held-out prediction

The prediction target

Predict 12-week SBP for a new participant from baseline variables. Assessment outcomes are reserved for scoring after predictions are fixed.

The coefficient table used 77 complete cases. For prediction, return to all 80 participants and learn an imputation rule within each training fold. These workflows use different samples and missing-data rules. Label both.

Five folds stratified by arm

make_folds <- function(arm, k = 5L) {
  stopifnot(!anyNA(arm), length(k) == 1L, k >= 2L,
            k == as.integer(k), all(table(arm) >= k))
  fold <- integer(length(arm))
  for (i in split(seq_along(arm), arm))
    fold[i] <- sample(rep(seq_len(k), length.out = length(i)))
  fold
}

Each participant appears in one assessment fold and four training folds. Stratification balances arm composition; it does not remove dependence.

Inspect folds before fitting

One split: learn preprocessing from training rows

train <- cv_data[fold != 1, ]
assess <- cv_data[fold == 1, ]
replacement <- mean(train$sbp_0, na.rm = TRUE)
stopifnot(is.finite(replacement))

fold_fit <- lm(sbp_12 ~ sbp_0 + age + arm,
               data = train, na.action = na.fail)

       3        4        5
141.5674 153.4028 141.5373

The same training mean fills missing values in training and assessment rows. Mean imputation illustrates information flow; it is not a general missing-data solution.

One prediction per participant

Preallocate missing predictions and an assessment counter. Each fold fits its own model.

pred <- rep(NA_real_, nrow(data))
seen <- integer(nrow(data))
for (k in sort(unique(fold))) {
  test <- fold == k
  # Learn preprocessing and fit using data[!test, ].
  # Predict data[test, ] and write into pred[test].
  seen[test] <- seen[test] + 1L
}

Check that every counter is one and every prediction is finite.

A reusable prediction function

The lab supplies the scaffold. These lines belong inside its fold loop:

train <- data[!test, ]; assess <- data[test, ]
m <- mean(train$sbp_0, na.rm = TRUE)
if (!is.finite(m)) stop("training baseline entirely missing")
train$sbp_0[is.na(train$sbp_0)] <- m
assess$sbp_0[is.na(assess$sbp_0)] <- m
fold_fit <- lm(sbp_12 ~ sbp_0 + age + arm,
               data = train, na.action = na.fail)
pred[test] <- predict(fold_fit, newdata = assess)

The function returns predictions in the original participant order.

Score predictions against a simple benchmark

held_out <- cv_predict(cv_data, fold)
benchmark <- rep(NA_real_, nrow(cv_data))
for (k in sort(unique(fold)))
  benchmark[fold == k] <- mean(cv_data$sbp_12[fold != k])
rmse <- function(observed, predicted) {
  stopifnot(length(observed) == length(predicted),
            all(is.finite(observed)), all(is.finite(predicted)))
  sqrt(mean((observed - predicted)^2))
}
scores <- c(model = rmse(cv_data$sbp_12, held_out),
            benchmark = rmse(cv_data$sbp_12, benchmark))
scores
    model benchmark
 6.832214 13.210881

Pool participant squared errors before taking the square root. Use identical folds for the model and the training-mean benchmark.

4 · Leakage and validation design

A deliberately leaky comparison

leaky <- cv_data
leaky$sbp_0[is.na(leaky$sbp_0)] <- mean(leaky$sbp_0, na.rm = TRUE)
c(valid = scores[["model"]],
  leaky = rmse(cv_data$sbp_12, cv_predict(leaky, fold)))
   valid    leaky
6.832214 6.827172

Global imputation lets assessment covariates influence the learned rule. Leakage need not improve the score in a particular sample. Audit information flow.

Diagnose leakage before comparing scores

Step Valid location
Fixed, prespecified unit conversion Can be applied to all rows
Mean imputation or scaling estimated from data Training fold
Choose features using outcome associations Training fold, with selection validated
Select a model or tuning parameter Inner validation, separate from final evaluation
Compute RMSE Held-out outcomes after predictions are fixed

A fixed rule is different from a rule estimated using assessment data.

Grouped and temporal validation

Deployment question Appropriate split idea
Predict a new participant Keep all visits of a participant together
Predict at a new clinic Hold out clinics
Predict future outcomes Train on earlier observations; assess later observations

Random row folds answer the wrong question if the same participant appears on both sides.

Selection and final evaluation

Trying many models and reporting the lowest CV error uses the evaluation data to make a selection. The selected score can be optimistic.

Use a prespecified candidate, an untouched test set, or nested cross-validation:

  1. An outer split reserves data for evaluation.
  2. Inner training splits choose features and tuning parameters.
  3. Refit the selected procedure on outer training data; predict outer assessment data.

After evaluation, a final model can be fitted to the intended full training set.

Practice: find the information leak

A student fills missing baseline values using all participants, chooses the best of 20 formulas by CV, and reports that formula’s minimum CV error.

Which steps used assessment information? Where should preprocessing happen? What evaluation data remain available after selecting the formula?

Practice: a valid evaluation plan

  • Estimate preprocessing within training data.
  • Prespecify the model for today’s exercise.
  • For model selection, reserve untouched evaluation data or use nested CV.
  • For repeated visits, keep each participant entirely on one side of a split.
  • Repeating folds measures split sensitivity, not independent sampling uncertainty.

5 · Reproducible handoff

Record both analysis workflows

predictions <- data.frame(id = cv_data$id, fold = fold,
  observed = cv_data$sbp_12, prediction = held_out, benchmark = benchmark)
analysis_bundle <- list(formula = formula(fit),
  analysed_ids = analysis$id, excluded_ids = trial$id[!keep],
  coefficients = results, predictions = predictions, rmse = scores,
  input_seed = 6301, fold_seed = 1651, rng = RNGkind(),
  missing_policy = "Complete-case descriptive fit; training-fold mean imputation for CV",
  session = sessionInfo())

Document the input and code revision with the saved results.

Save inspectable outputs

dir.create("output", showWarnings = FALSE)
saveRDS(analysis_bundle, "output/analysis-bundle.rds")
write.csv(results, "output/coefficients.csv", row.names = FALSE)
write.csv(predictions, "output/held-out-predictions.csv", row.names = FALSE)
writeLines(capture.output(sessionInfo()), "output/session-info.txt")

Read the bundle back and check its IDs, coefficients, and predictions. The lab also saves RMSE and a README with the rerun instructions.

Package versions are part of the environment

sessionInfo() records the active R session but does not recreate its packages. renv adds a project library and a lockfile describing package dependencies.

# Optional: run interactively in a dedicated project, outside report rendering.
renv::init()
renv::snapshot()
# In a clone with the committed lockfile:
renv::restore()

These setup commands are optional. A lockfile records dependencies, while the README documents data access, the R version, and system requirements.

A reproducible delivery check

  1. Open a clean R session in the documented project environment.
  2. Obtain the specified input and run the analysis from the documented entry point.
  3. Confirm sample counts, key uniqueness, coefficient names, and prediction checks.
  4. Render the report and inspect tables and figures.
  5. Confirm that the outputs identify their input, code, and environment versions.

Use a colleague’s rerun to test the instructions, not only your current workspace.

Boxplots with participant-level values

boxplot(sbp_12 ~ arm, data = trial, outline = FALSE,
        ylab = "Week 12 SBP (mmHg)", xlab = "")
stripchart(sbp_12 ~ arm, data = trial,
           vertical = TRUE, method = "jitter",
           pch = 19, col = "steelblue", add = TRUE)
  • outline = FALSE hides the boxplot’s outlier symbols. Box borders and whiskers remain.
  • stripchart() then draws all observations, including values beyond the whiskers.
  • Together, these calls show each observation once, without duplicate outlier symbols.

Bar charts use counts or summaries

site_counts <- table(trial$site_f)
barplot(site_counts, col = "steelblue",
        xlab = "Recruiting site", ylab = "Number of participants")

table() calculates the counts. barplot() draws their heights. A histogram instead bins a numeric variable such as blood pressure.

Optional: two distribution diagnostics

Plot What it shows How to read it
Empirical CDF (ECDF) The observed cumulative distribution At a given SBP, read the proportion of participants at or below it
Normal Q–Q plot Sample quantiles against theoretical normal quantiles Points near a straight line suggest an approximately normal distribution
  • The ECDF uses every observation, with no histogram bins.
  • In a normal Q–Q plot, systematic curvature or tail departures suggest departures from normality.

Optional: ECDF and normal Q–Q examples

saved_par <- par(mfrow = c(1, 2), mar = c(4, 4, 2, 1))
plot(ecdf(trial$sbp_0), main = "Cumulative proportion",
     xlab = "Baseline SBP (mmHg)", ylab = "Proportion at or below x")
qqnorm(trial$sbp_0, main = "Normal Q-Q plot")
qqline(trial$sbp_0, col = "steelblue")
par(saved_par)

Left: proportion at or below each SBP value. Right: sample versus normal quantiles.

A roughly straight Q–Q pattern supports approximate normality. This is a visual assessment, without a p-value.

hist(trial$sbp_0)

  • par() affects the current graphics device.
  • Restore settings after the multi-panel display.
  • If separate panels need direct comparison, choose common axis limits.

Raster and vector figures

PNG: raster image PDF: vector graphics
Stores A grid of coloured pixels Drawing instructions for lines, shapes, and text
When enlarged Individual pixels can become visible Vector elements remain sharp as they scale
Size settings Width, height, and pixel density Physical page width and height

A PDF has no single overall DPI for its vector elements.

A PDF can also contain raster images. Those images retain their pixel-resolution limits.

Resolution: pixels and physical size

DPI means dots per inch. For raster export, R uses this setting as pixels per inch (PPI).

Pixel width = width in inches × DPI

A 6 × 4 inch PNG Pixel dimensions
150 DPI 900 × 600 pixels
300 DPI 1800 × 1200 pixels
600 DPI 3600 × 2400 pixels

At fixed physical size, higher DPI creates more pixels. At fixed pixel dimensions, changing DPI changes the physical size, without adding detail.

Saving a base R figure

dir.create("output", showWarnings = FALSE)
png("output/base-sbp.png", width = 6, height = 4,
    units = "in", res = 300)
plot(trial$sbp_0, trial$sbp_12,
     xlab = "Baseline SBP (mmHg)", ylab = "Week 12 SBP (mmHg)")
dev.off()

The file device receives drawing commands until dev.off() closes it. This PNG has 1800 × 1200 pixels: 6 × 4 inches at res = 300.

For a 6 × 4 inch vector PDF, open pdf("output/base-sbp.pdf", width = 6, height = 4) instead. No res or dpi argument.

A quick panel of distributions

par(mfrow = c(1, 4), mar = c(4, 4, 2, 1))
hist(trial$age,       main = "age")
hist(trial$weight_kg, main = "weight_kg")

Four columns on one screen. You are not making a figure — you are checking that the file is what you think it is. crp is right-skewed and you now know it before you fit anything.

Two plotting workflows

  • Base graphics: draw to a graphics device, then add points, lines, or labels. Many functions share options such as col, xlab, and ylim.
  • ggplot2: build a plot object, then add or change layers and scales. Grouping, legends, and facets follow shared rules.
  • Both can produce reproducible, publication-quality figures. Choose the workflow that makes your analysis easy to understand and maintain.

The pipe and the plus sign have different jobs

trial |>
  filter(site == 1) |>
  ggplot(aes(sbp_0, sbp_12)) +

  • + adds plotting components to the ggplot object.
  • Put + at the end of a line when continuing the expression.

For shapes 21–25, fill controls the interior and colour controls the border. For most other point shapes, use colour. For bars, fill colours the interior.

What do the intervals mean?

Interval Describes
Mean ± SD Spread of individual measurements around their mean
Mean ± SE Estimated sampling variability of the mean
Confidence interval Uncertainty about a population parameter under a model
Prediction interval Uncertainty about a new individual observation

The same geom_errorbar() can draw any of these. Its inputs do not tell the reader which one you intended. State the meaning and method in the caption.

The earlier mean ± 1.96 * SE examples use an approximate 95% confidence interval. The longitudinal ribbon gives intervals at each visit, not a model of change.

Uncertainty: an estimate needs an interval

by_arm <- trial |>
  group_by(arm) |>
  summarise(mean_sbp = mean(sbp_12),
            se = sd(sbp_12) / sqrt(n()))

ggplot(by_arm, aes(arm, mean_sbp)) +
  geom_pointrange(aes(ymin = mean_sbp - 1.96 * se,
                      ymax = mean_sbp + 1.96 * se))

A layer can use its own data

ggplot(trial, aes(arm, sbp_12)) +
  geom_point(position = position_jitter(width = 0.1, height = 0,
                                        seed = 6301), alpha = 0.3) +
  geom_point(data = by_arm, aes(x = arm, y = mean_sbp),
             inherit.aes = FALSE, shape = 18, size = 5,
             colour = "#0072B2")

Grey points use participant data. Blue diamonds use the summary table. inherit.aes = FALSE makes the summary layer use only its own mappings.

Relationships: points and a smooth

ggplot(trial, aes(age, sbp_12, colour = arm)) +
  geom_point(alpha = 0.7) +
  geom_smooth(method = "lm", se = TRUE, alpha = 0.15)

method = "lm" specifies a linear fit. With method = NULL, ggplot2 chooses loess or GAM according to the largest group’s size. The band describes uncertainty in the fitted mean, not a prediction interval for an individual.

Layer-specific mappings

ggplot(trial, aes(sbp_0, sbp_12)) +
  geom_point(aes(colour = arm)) +
  geom_smooth(method = "lm", se = FALSE, colour = "black") +
  scale_colour_manual(values = arm_col)

Colour belongs only to the points here. The smooth uses all participants together. Putting colour = arm in the global aes() would fit one line per arm.

One line per participant

group = id connects each participant’s own measurements. The lines overlap: how could we compare the two arms without hiding individual trajectories?

Faceting: when and why

Faceting repeats the same plot for subsets of the data in labelled panels.

Use facets when you want to… Why panels help
Compare arms, sites, or other groups Each subset has its own space
See patterns hidden by overlapping marks Groups no longer cover one another
Apply the same display to several groups One specification controls every panel

Keep a shared scale when comparing levels or spread. Use a single panel when direct overlap is the main question and only a few groups need distinguishing.

facet_wrap(): one panel per group

p_lines + facet_wrap(~ arm, nrow = 1)
  • ~ arm assigns each observation to its arm’s panel.
  • nrow = 1 places the two panels in a row.
  • The default scales = "fixed" keeps the axes comparable.

facet_grid(): rows and columns

ggplot(trial, aes(sbp_0, sbp_12)) +
  geom_point() +
  facet_grid(arm ~ site_f) +
  labs(x = "Baseline SBP (mmHg)",
       y = "Week 12 SBP (mmHg)")

arm ~ site_f means rows = arm, columns = site. Read across a row to compare sites; down a column to compare arms within a site.

Fixed and free facet scales

scales = "free_y" lets each panel choose its y range. This can reveal detail within a panel, but the same vertical position can represent different values.

Which facet scale fits the question?

CHOOSE AND EXPLAIN

“Is week 12 SBP generally higher at one site than another?”

Would you choose fixed y scales or free y scales across the site panels?

Fixed scales. The question compares levels across sites; equal heights should represent equal SBP values.

Mean trajectories and their uncertainty

by_week <- trial_long |>
  group_by(arm, week) |>
  summarise(m = mean(sbp),
            se = sd(sbp) / sqrt(n()),
            .groups = "drop")
ggplot(by_week, aes(week, m)) +
  geom_ribbon(aes(ymin = m - 1.96 * se,
                  ymax = m + 1.96 * se),
              fill = "grey75") +

The ribbon shows approximate pointwise 95% confidence intervals for each arm mean, not the range containing 95% of participants.

6 · Refining the display

What does a scale control?

aes() maps a variable to an aesthetic. A scale controls how that variable is represented and labelled.

Function Controls
scale_x_continuous() Numeric x-axis ticks and labels
scale_x_discrete() Category order and labels
scale_y_log10() A logarithmic y-axis
scale_color_manual() Colors assigned to categories
scale_fill_viridis_c() A continuous fill-color gradient

Read the name as scale → aesthetic → type. color and colour are aliases.

scale_x_continuous(): meaningful tick marks

p_visit <- ggplot(filter(by_week, arm == "Placebo"),
                  aes(week, m)) +
  geom_line() + geom_point() +
  labs(y = "Mean SBP (mmHg)", title = "Placebo arm")
p_visit +
  scale_x_continuous(
    name = "Study visit",
    breaks = c(0, 6, 12),
    labels = c("Baseline", "Week 6", "Week 12"))

breaks chooses tick locations; labels supplies the text at those ticks. These settings do not add, remove, or move observations.

Axis settings do different jobs

Argument Job Example
name Axis title "Week 12 SBP (mmHg)"
breaks Tick positions seq(100, 180, 20)
labels Tick text or formatting scales::label_number(accuracy = 1)
limits Permitted values on the scale c(120, 160) 
scale_y_continuous(
  name = "Week 12 SBP (mmHg)",
  breaks = seq(100, 180, 20),
  labels = scales::label_number(accuracy = 1))

Limits are not just tick settings: they can exclude values before a statistical layer is calculated. We will compare this with coordinate zoom.

scale_x_discrete(): category order and labels

ggplot(trial, aes(arm, sbp_12)) +
  geom_boxplot() +
  scale_x_discrete(
    limits = c("Treatment", "Placebo"),
    labels = c(Treatment = "Active treatment",
               Placebo = "Placebo")) +
  labs(x = NULL, y = "Week 12 SBP (mmHg)")

Use a discrete scale for categories. Named labels match the actual data values. Include all intended categories in limits; omitted categories are excluded.

Log scales: equal ratios, equal distances

Use a log scale for positive values spanning a wide range, especially when ratios are more informative than absolute differences.

Values Linear axis Log10 axis
1 → 10 Increase of 9 One tenfold step
10 → 100 Increase of 90 One tenfold step

scale_y_log10() spaces values by their logarithms and labels ticks in the original units. There is no general scale_log10() call: choose x or y.

Check first: zero and negative values have no finite real log10 value. Do not add an arbitrary constant just to make the plot run.

scale_y_log10(): see the same positive data

p_crp + scale_y_log10(breaks = c(0.3, 1, 3, 10, 30))

The same values are shown. Low values are easier to distinguish; large values occupy less space. Tick labels still show CRP, not log10(CRP).

Will these give the same boxplot?

PREDICT, THEN DISCUSS

p_box <- ggplot(trial, aes(arm, sbp_12)) + geom_boxplot()
# A
p_box + coord_cartesian(ylim = c(120, 160))
# B
p_box + scale_y_continuous(limits = c(120, 160))

Which keeps all observations in the boxplot calculation?

A. Coordinate zoom changes the visible window after calculation. In B, out-of-range values become missing first, so the boxplot can change.

Zoom and scale limits give different summaries

Compare the median and box edges, not just the frame. Use coord_cartesian() for a closer view; filter explicitly when exclusion is part of the analysis and explain the criterion.

Color: what information should it carry?

Color can identify a group, show an ordered magnitude, or emphasize a selected feature. Decide its job before choosing a palette.

Data meaning Palette idea Example
Unordered categories Distinct hues Placebo and treatment
Low to high Sequential gradient Age or mean SBP
Below/above a reference Diverging gradient Negative/positive change

Hue distinguishes colors; lightness runs from dark to light. Use axes for the primary numerical comparison when precise reading matters.

color and fill control different parts

ggplot(trial, aes(arm, sbp_12, fill = arm)) +
  geom_boxplot(color = "grey25") +
  labs(x = NULL, y = "Week 12 SBP (mmHg)",
       fill = "Randomized arm")
  • fill = arm inside aes() maps arm to the box interiors.
  • color = "grey25" outside aes() gives every box the same border color.
  • For ordinary points and lines, use color; filled point shapes 21–25 also use fill.

scale_color_manual(): name the category colors

arm_colors <- c(Placebo = "#D55E00",
                Treatment = "#0072B2")
ggplot(trial, aes(sbp_0, sbp_12,
                  color = arm)) +
  geom_point(size = 2) +
  scale_color_manual(
    values = arm_colors,
    name = "Randomized arm") +
  labs(x = "Baseline SBP (mmHg)",
       y = "Week 12 SBP (mmHg)")

The names in values match data values. Reuse the same mapping across figures so “Treatment” does not change color between slides.

scale_fill_manual(): the same groups, filled marks

ggplot(trial, aes(arm, sbp_12, fill = arm)) +
  geom_boxplot(color = "grey25") +
  scale_fill_manual(
    values = arm_colors,
    guide = "none") +
  labs(x = NULL, y = "Week 12 SBP (mmHg)")

Choose the scale that matches the mapped aesthetic: fill → scale_fill_*(). Here the x-axis already identifies each arm, so the fill legend is redundant.

Continuous color: scale_color_viridis_c()

ggplot(trial, aes(sbp_0, sbp_12,
                  color = age)) +
  geom_point(size = 2.5) +
  scale_color_viridis_c(name = "Age (years)") +
  labs(x = "Baseline SBP (mmHg)",
       y = "Week 12 SBP (mmHg)")

The color bar represents a numeric range. _c means continuous; _d means discrete. Use a continuous gradient for age, not a separate color per year.

Continuous fill: a site-by-arm heatmap

site_summary <- trial |>
  group_by(site_f, arm) |>
  summarise(mean_sbp = mean(sbp_12),
            .groups = "drop")
ggplot(site_summary,
       aes(arm, site_f, fill = mean_sbp)) +
  geom_tile(color = "white") +
  scale_fill_viridis_c(
    name = "Mean SBP\n(mmHg)") +
  labs(x = NULL, y = NULL)

scale_fill_viridis_c() controls the tile interiors. A heatmap shows patterns across combinations; use a dot plot or numeric labels for precise comparisons.

Diverging color: a meaningful midpoint

ggplot(trial, aes(sbp_0, sbp_12,
                  color = sbp_12 - sbp_0)) +
  geom_point(size = 2.8) +
  scale_color_gradient2(
    low = "#2166AC", mid = "grey90",
    high = "#B35806", midpoint = 0,
    name = "Change\n(mmHg)") +
  labs(x = "Baseline SBP (mmHg)",
       y = "Week 12 SBP (mmHg)")

Zero means no change. Two color directions distinguish decreases from increases. A midpoint needs a scientific meaning, not just visual symmetry.

What survives a grayscale printout?

CHOOSE A REPAIR

A scatterplot uses color alone to identify treatment arms. Some readers cannot distinguish those hues, and a grayscale printout loses the distinction.

What would preserve the arm information?

Add point shape, direct labels, or separate labelled panels. A suitable palette helps; an additional encoding preserves group identity.

Accessible color: palette plus shape

ggplot(trial,
       aes(sbp_0, sbp_12,
           color = arm, shape = arm)) +
  geom_point(size = 2.5) +
  scale_color_manual(
    values = arm_colors,
    name = "Randomized arm") +
  labs(shape = "Randomized arm",
       x = "Baseline SBP (mmHg)",
       y = "Week 12 SBP (mmHg)")

The blue/orange pair comes from the Okabe–Ito palette. Shape supplies a second cue. Check the plot at its final size and without color.

7 · Critiquing and improving a figure

A figure review starts with the question

Question: how does week 12 SBP differ between the randomized arms?

Check Ask the reader
Comparison What quantity, groups, and time point are shown?
Evidence Are marks participants, summaries, or both?
Scale Does the axis support the intended comparison?
Uncertainty What do the intervals represent?
Readability Can you identify groups, units, and sample size?

Give feedback as: “This choice could suggest …; I would change ….”

Critique: what could a reader misunderstand?

Think, then compare with a neighbor. Name two specific problems and explain the impression each could create.

Diagnose the choice, then choose a repair

Choice in the figure What it hides or suggests Repair
Bars clipped above zero Exaggerated length comparison Start bars at zero, or use points
Only two arm means Within-arm variation is invisible Show participant values
No defined intervals Precision cannot be assessed Add and define mean confidence intervals
“SBP results” / “SBP” Summary, visit, and units unclear Name all three
Duplicate fill legend Extra lookup without new information Use the labelled x positions

The repair follows the reading task—not a rule that every plot needs every layer.

Revised figure: individuals and defined summaries

Read it: compare the arm means, then the spread and overlap of participants. The intervals describe each mean; they are not intervals for individual SBP.

Build the revision in two layers

ggplot(trial, aes(arm, sbp_12)) +
  geom_point(
    position = position_jitter(width = 0.12, height = 0, seed = 8),
    alpha = 0.55, color = "grey45") +
  geom_pointrange(
    data = by_arm,
    aes(y = mean_sbp, ymin = mean_sbp - 1.96 * se,
        ymax = mean_sbp + 1.96 * se),
    color = "#0072B2")
  • First layer: 60 participant rows, with horizontal jitter only.
  • Second layer: two summary rows, one mean and interval per arm.
  • Labels and caption explain what each layer represents.

Does every y-axis need to start at zero?

COMPARE ENCODINGS

The revised SBP plot has a y-axis above zero. Is that necessarily misleading?

No. Points encode position on a labelled axis, so a focused range can help. Bars encode length from a baseline; cutting off zero distorts that length.

Choose a range that preserves relevant variation and reference values. For change, zero is often an important no-change reference.

Labels explain the measurement

labs(
  title = "Week 12 SBP by randomized arm",
  subtitle = "Synthetic data; 30 participants per arm",
  x = NULL,
  y = "Week 12 SBP (mmHg)",
  caption = "Grey points: participants. Blue: mean and approximate 95% CI.")

Title: comparison and time point. Axes: variable and units. Caption: marks, summaries, and interval meaning.

A descriptive title reports what is displayed. Avoid a causal or clinical claim that the plotted analysis does not establish.

Direct labels for a few lines

ggplot(by_week, aes(week, m, color = arm)) +
  geom_line() +
  geom_text(data = filter(by_week, week == 12),
            aes(x = 12.5, label = arm),
            hjust = 0, show.legend = FALSE) +
  scale_color_manual(values = arm_colors,
                     guide = "none") +
  scale_x_continuous(breaks = c(0, 6, 12)) +
  coord_cartesian(xlim = c(0, 18)) +
  labs(x = "Week", y = "Mean SBP (mmHg)")

Labels at the line ends remove repeated legend lookup. They work well for a few separated lines; a legend or facets may be clearer when labels collide.

Themes: make the data easy to see

theme_minimal(base_size = 13) +
  theme(panel.grid.major.x = element_blank(),
        panel.grid.minor = element_blank())

Both themes are valid. Keep guides that help readers estimate values; remove clutter without removing units, labels, or useful reference lines.

Choosing an alternative display

Reading task A useful choice Why
Rank category counts precisely Sorted bars or dots Positions/lengths share an axis
Show a few parts of a whole Bars, or a clearly labelled pie State the denominator
Compare trends in different outcomes Separate panels with a shared time axis Each outcome keeps its units

A second y-axis is appropriate for a defined one-to-one conversion of the same quantity. Arbitrarily rescaling two outcomes can change their apparent alignment.

Can your revision answer these questions?

READ AS A NEW VIEWER

  1. What does one mark represent?
  2. Which groups and measurement are being compared?
  3. What does the interval or reference line mean?
  4. What conclusion is supported—and what is still uncertain?

If the figure cannot answer one of these, revise the relevant layer, label, scale, or caption before changing decorative details.

Plot debugging: connect the symptom to the cause

Symptom Check
Legend says “blue” Was a constant placed inside aes()?
A fill scale changes nothing Is the geom using color instead of fill?
Group colors change between figures Are manual colors named consistently?
Panel patterns look identical Are facet axes fixed or free? Read the ticks
A summary changes after axis limits Did scale limits remove observations?
“Removed rows” warning Inspect missing, nonfinite, and out-of-range values

Run the plot one layer at a time. Read warnings before hiding them with na.rm = TRUE.

Same code, different-sized figures?

THINK, THEN VOTE

Two collaborators run:

ggsave("figure.png", plot = p_final)

Their RStudio plot panes have different dimensions.

Could the saved figures have different dimensions too?

Yes. Without explicit width and height, the export can use the current graphics device’s size.

Specify width, height, and units; choose DPI for a raster export.

ggsave(), with the arguments filled in

dir.create("output", showWarnings = FALSE)
ggsave(
  filename = "output/fig-sbp-arm.png",
  plot     = p_final,
  width    = 6.5,     # inches - the column width of your journal
  height   = 4, units = "in",
  dpi      = 300,     # pixels per inch for this raster PNG
  bg       = "white"
)

Why explicit export settings matter

Argument Leave it out and you get
width, height The last size of your plot pane. Irreproducible by construction
dpi PNG pixel density defaults to 300; it does not set vector PDF sharpness
bg Background comes from the plot theme and may be transparent
.pdf / .svg extension Vector marks scale without pixelation; embedded raster layers still have finite resolution

PNG versus PDF with ggsave()

# Raster: 6 x 4 inches at 300 DPI = 1800 x 1200 pixels
ggsave("output/figure.png", plot = p_final,
       width = 6, height = 4, units = "in", dpi = 300)

# Vector: 6 x 4 inch page; no raster DPI is needed
ggsave("output/figure.pdf", plot = p_final,
       width = 6, height = 4, units = "in")

For PDF at a fixed size in inches, changing dpi does not sharpen vector lines or text.

With units = "px", ggsave() uses dpi to convert pixel dimensions to physical size, even for PDF. Prefer inches or cm for vector exports.

Why the plot pane is not a workflow

Export → paste

Right-click, copy, paste into Word.

Nothing records what produced it. The data changes, the figure does not, and no warning appears anywhere.

ggsave() in the document

The figure is regenerated when its code executes during rendering.

The script records the data and plotting steps. Check data versions and caching settings so the figure stays aligned with the analysis.

A pasted figure is the same class of error as a number typed by hand — and it is harder to spot, because a stale figure still looks like a figure.

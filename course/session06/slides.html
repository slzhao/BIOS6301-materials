2 · The pipe

The pipe, mechanically

x |> f(y) is exactly f(x, y). Nothing more.

round(mean(trial$sbp_0), 1)
[1] 149.5
trial$sbp_0 |> mean() |> round(1)
[1] 149.5

Read |> as “and then”. It moves the innermost thing in a nested call to the front, where you read first.

%>% — because you will read it everywhere

# magrittr / tidyverse pipe — needs library(magrittr) or library(dplyr)
trial %>% filter(age > 70) %>% summarise(m = mean(sbp_0))

# native pipe — base R since 4.1, nothing to load
trial |> filter(age > 70) |> summarise(m = mean(sbp_0))
%>% |>
Comes from the magrittr package base R, since 4.1 (2021)
Placeholder . — anywhere, repeatable _ — named argument only
Bare function name x %>% mean works x |> mean is an error; needs mean()

Write |>. Read %>%. Ninety percent of the dplyr code written before 2021 uses %>%, and that includes most of the internet.

Four design principles

Principle Consequence
Data comes first Every verb pipes
Functions are verbs The code says what it does: filter, arrange
Data frame in, data frame out Any verb can follow any verb
Columns are bare names No trial$ on every line

Consistency is the feature. Learning the fifth verb costs nothing once you know the first four, because all four rules hold for all of them.

One grammar

select, rename, relocate which columns, and their names df[, cols], names()
filter, distinct, slice which rows df[i, ], subset(), duplicated()
arrange row order order()
mutate adds columns transform(), df$new <-
summarise, count collapses rows aggregate(), table()

filter() and missing values

nrow(trial |> filter(sbp_12 < 120))
[1] 5
nrow(trial[trial$sbp_12 < 120, ])
[1] 8

Five versus eight. NA < 120 is NA in both dialects — but filter() keeps only TRUE, while [ returns a row of NAs for every NA in the index.

The forgotten ungroup()

trial |>
  group_by(arm, sex) |>
  summarise(n = n(), .groups = "drop") |>
  mutate(pct = round(100 * n / sum(n), 1))
# A tibble: 4 x 4
  arm       sex       n   pct
  <chr>     <chr> <int> <dbl>
1 Placebo   F        15  25

3 Treatment F        17  28.3
4 Treatment M        13  21.7

.groups = "drop" in summarise(), or ungroup() on the next line. Pick one and use it every time you group by more than one variable.

Every grouped summary gets an n

trial |>
  group_by(arm) |>
  summarise(
    n_rand   = n(),                   # randomised
    n_seen   = sum(!is.na(sbp_12)),   # actually measured at 12 weeks
    mean_sbp = round(mean(sbp_12, na.rm = TRUE), 1),
    .groups  = "drop"
  )
# A tibble: 2 x 4
  arm       n_rand n_seen mean_sbp
  <chr>      <int>  <int>    <dbl>
1 Placebo       30     28     148 
2 Treatment     30     29     135.

n() counts rows. sum(!is.na(x)) counts observations. When they differ, the difference is a finding.

Grouped mutate() — the thing aggregate() cannot do

trial |>
  group_by(arm) |>
  mutate(sbp_0_centred = round(sbp_0 - mean(sbp_0), 1)) |>
  ungroup() |>
  select(id, arm, sbp_0, sbp_0_centred) |> head(3)
# A tibble: 3 x 4
  id    arm     sbp_0 sbp_0_centred
  <chr> <chr>   <dbl>         <dbl>
1 P001  Placebo   160           9.8
2 P002  Placebo   162          11.8
3 P003  Placebo   157           6.8

Sixty rows out, not two. The group mean is computed per arm and recycled back across every row in that arm.

Summary

  • Packages, namespaces, tibbles, and pipes explain the tidyverse workbench.
  • The dplyr verbs express row, column, ordering, derivation, and summary operations.
  • Grouped metadata changes the meaning of later verbs.
  • n() and observed n answer different denominator questions.
  • Base R and dplyr can express the same statistical inclusion rule.

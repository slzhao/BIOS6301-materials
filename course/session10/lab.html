Session 10 guided lab

Six learning goals, one analysis in R and Python

Note

Complete Goals 1–6 in order using the same participant-visit data as the slides. The core lab uses the NumPy and pandas packages prepared before class. Large data, speed, machine learning, GPU computing, and research software are discussion only. No additional installation or hardware is required.

Files and working folder

Work in your personal BIOS6301-mywork project folder in Positron. Copy these files from BIOS6301-materials/course/session10/starter/ into your project’s work/session10/ folder:

  • Python starter: python-intro.py

Edit your copies, leaving the course originals unchanged. Keep Python code in the .py cells or .qmd Python chunks and run the .R reference in an R session. The two languages have separate objects even when the objects have the same names.

Use the Session 10 slides as a reference. Record explanations as comments in the matching goal cells of your Python script.

The Quarto file demonstrates that Python works interactively in a familiar document format. Open it in Source mode, select Python, and run its {python} chunks in order. The code is the same as the .py cells. Use .py for the Goal 2 script check, then run Setup and Synthetic data from the .qmd file and inspect visit.head() in the Python Console. For later goals, choose one format and record explanations in comments or Markdown. Restart Python and run all cells/chunks in order for the final check. Rendering a report is not required; no additional installation is assigned.

Goal 5 · Compare missing-value and indexing behavior with R

Positions and labels

Use the four-element x in the Goal 5 cell. Predict each result before running it:

Expression What to explain
Python x[1:3] and R c(10, 20, 30, 40)[1:3] Starting position and slice endpoint
Python x[-1] and R c(10, 20, 30, 40)[-1] Last element versus exclusion
week4.index.tolist() Labels retained after filtering
week4.iloc[0:2] and week4.loc[1:3] Positions versus labels

Explain why week4.loc[0] would fail. If you try it in the Console, leave the failing expression commented out in the saved script.

Compound conditions

Create a separate object treated_week4 containing rows where week == 4 and arm == "treated". Use & and parentheses around both conditions. Keep the original six-row week4 table for the analysis.

Explain why pandas uses & instead of Python’s and for these two Series. Confirm that treated_week4 has three rows, including one missing outcome.

Missing-value defaults

For outcomes 4.4, missing, and 4.8, predict and compare:

  • In R: mean(c(4.4, NA, 4.8)) and the same call with na.rm = TRUE.
  • In Python: pd.Series([4.4, np.nan, 4.8]).mean().
  • In Python: np.array([4.4, np.nan, 4.8]).mean() and np.nanmean([4.4, np.nan, 4.8]).

Use isna() or notna() to identify missing outcomes in pandas, rather than testing equality with np.nan.

Completion check: explain each result in terms of the object, indexing rule, or function default. Do not assume that pandas and NumPy means behave alike.

Goal 6 · Verify equivalent R and Python results

Compare structure and counts exactly

The starter supplies r_reference, which you can reproduce with the R script. Keep it separate from summary.

  1. Assert the expected input dimensions, key uniqueness, and six retained week-4 rows.
  2. Independently count total and observed rows in each arm using simple Boolean conditions. Compare these counts with summary.
  3. Sort summary and r_reference by arm, then reset their indexes.
  4. Compare arm, n_total, and n_observed exactly. The group labels must match before you compare the numerical columns.

Compare estimates within a tolerance

Compare mean_marker and sd_marker using np.testing.assert_allclose(). For this small example use rtol=0, atol=1e-12, and equal_nan=False. Explain why a numerical tolerance is useful and why counts should match exactly.

Diagnose a plausible error

Make a separate wrong_week4 that drops missing marker values, and summarize it as wrong_summary. Do not replace the correct analysis objects.

  • Which columns still agree with the R reference?
  • Which check would reject this table?
  • Record the answer in a comment. Keep any deliberately failing assertion commented out so the completed script can run successfully.

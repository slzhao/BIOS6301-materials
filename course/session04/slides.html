1 · Four containers

Two questions, four answers

Every R data structure answers two questions: how many dimensions, and must everything be the same type?

One type only Mixed types allowed
1 dimension vector list
2 dimensions matrix data.frame
  • A matrix is a vector with a dim attribute. Nothing more.
  • A data frame is a list of equal-length columns. Nothing more.

Those two sentences are the whole session. Everything else follows from them.

A matrix is a vector with a shape

sbp <- as.matrix(trial[, c("sbp_0", "sbp_6", "sbp_12")])
rownames(sbp) <- trial$id
dim(sbp)
[1] 60  3
sbp[1:3, ]
     sbp_0 sbp_6 sbp_12
P001   144   145    160
P002   119   109    103
P003   155   158    157
round(colMeans(sbp, na.rm = TRUE), 1)
 sbp_0  sbp_6 sbp_12 
 149.5  144.8  141.7

Matrices are strict about type

Ask for a character column and a numeric column in the same matrix:

as.matrix(trial[, c("id", "age")])[1:3, ]
     id     age 
[1,] "P001" "57"
[2,] "P002" "63"
[3,] "P003" "55"

The ages are now "57", "63", "55" — text. Coercion, exactly as in session 3, silently.

This is why clinical data lives in data frames. One identifier column would turn your entire dataset into strings.

Lists hold anything

result <- list(
  study = "SBP-12",
  n     = nrow(trial),
  arms  = c("Placebo", "Treatment"),
  sbp_0 = trial$sbp_0
)
str(result)
List of 4
 $ study: chr "SBP-12"
 $ n    : int 60
 $ arms : chr [1:2] "Placebo" "Treatment"
 $ sbp_0: num [1:60] 144 119 155 146 179 147 158 152 169 135 ...

Different types, different lengths, all in one object. Every model object in R — everything lm() or t.test() gives you back — is a list.

[ and [[ on a list

class(result["n"])
[1] "list"
class(result[["n"]])
[1] "integer"
Notation Gives you Think
result["n"] a list of length 1 a smaller version of the same thing
result[["n"]] the value inside reach in and take it out
result$n the value inside [[ with less typing

The pigeonholes: [ gives you a pigeonhole, [[ gives you what is in the pigeonhole. [ on a list always returns a list.

A data frame is a list of columns

length(trial)
[1] 10
nrow(trial)
[1] 60
class(trial[[2]])
[1] "character"

length() on a data frame counts columns, because a data frame is a list and its elements are its columns. It just happens to enforce that all of them have the same length.

Consequence: everything you just learned about [ versus [[ on lists applies unchanged to data frame columns.

2 · Factors

A factor is integers wearing labels

head(trial$grade, 4)
[1] severe severe mild   severe
Levels: mild moderate severe life-threatening
levels(trial$grade)
[1] "mild"             "moderate"         "severe"           "life-threatening"
head(as.integer(trial$grade), 4)
[1] 3 3 1 3

Stored as 3 3 1 3. Displayed as severe severe mild severe. The labels live in the levels attribute, and R looks them up when it prints.

The levels are the point

table(trial$grade)

            mild         moderate           severe life-threatening 
              29               18               13                0

Nobody was life-threatening. The level is still there — and that is correct. The study protocol defined four grades; your sample happened to contain three.

table(droplevels(trial$grade))

    mild moderate   severe 
      29       18       13

The catastrophe

dose_mg came off the CRF as text. Somebody needs it numeric.

wrong <- as.numeric(as.factor(trial$dose_mg))
data.frame(text = trial$dose_mg, wrong = wrong)[31:36, ]
   text wrong
31   40     4
32   40     4
33   40     4
34   20     3
35    5     5
36   10     2

40 mg became 4. 20 mg became 3. 5 mg became 5, which is right by accident and makes it harder to spot.

How bad, quantitatively

mean(as.numeric(as.factor(trial$dose_mg)))   # wrong
[1] 2.333333
mean(as.numeric(as.character(trial$dose_mg))) # right
[1] 8.666667

The fix

as.numeric(as.character(x)) — go back to the text, then to the number. Better still: never let it become a factor.

And check afterwards. as.numeric() on genuinely non-numeric text gives NA with a warning — so sum(is.na(x)) before and after tells you whether the conversion lost anything.

Where factors come from now

Source Factors?
data.frame(...) in R ≥ 4.0 No. Character stays character
read.csv() in R ≥ 4.0 No
Anything written before 2020 Probably yes — stringsAsFactors defaulted to TRUE
haven::read_dta(), read_sav() Labelled columns; factor-adjacent
factor(), cut(), table() Yes, by construction

R 4.0.0 (April 2020) changed the default. Inherited scripts predate it — and they were written with the old behaviour assumed.

3 · Indexing a data frame

Rows first, then columns

trial[1:3, c("id", "arm", "sbp_12")]
    id     arm sbp_12
1 P001 Placebo    160
2 P002 Placebo    103
3 P003 Placebo    157
trial[trial$age > 80, c("id", "age")]
     id age
10 P010  87

df[i, j] — i is rows, j is columns, and the comma is not optional. A blank means “all of them”.

Four ways to ask for a column

class(trial$age)
[1] "numeric"
class(trial[["age"]])
[1] "numeric"
class(trial[, "age"])
[1] "numeric"
class(trial["age"])
[1] "data.frame"

Three hand you a vector. The fourth hands you a one-column data frame — [ with a single argument is list indexing, and [ on a list returns a list.

mean(trial["age"])
Warning in mean.default(trial["age"]): argument is not numeric or logical:
returning NA
[1] NA

The drop surprise

class(trial[, c("age", "sbp_0")])
[1] "data.frame"
class(trial[, "age"])
[1] "numeric"

Same notation, different class, because the result had one column.

class(trial[, "age", drop = FALSE])
[1] "data.frame"

$ is convenient, and slightly dangerous

head(trial$ag, 3)
[1] 57 63 55

There is no column called ag. $ partially matched it to age.

trial$sbp
NULL

Ambiguous — sbp_0, sbp_6, sbp_12 — so you get NULL, silently. And NULL propagates: mean(trial$sbp) is NA, not an error.

Selecting rows by condition

low <- trial[trial$sbp_12 < 120, c("id", "arm", "sbp_12")]
nrow(low)
[1] 11
head(low, 4)
       id     arm sbp_12
2    P002 Placebo    103
NA   <NA>    <NA>     NA
12   P012 Placebo    110
NA.1 <NA>    <NA>     NA

The condition is a logical vector of length 60, and [ keeps the rows where it is TRUE. Exactly session 3’s logical indexing, applied to the row position.

The NA row trap

trial[trial$sbp_12 < 120, c("id", "sbp_12")][1:4, ]
       id sbp_12
2    P002    103
NA   <NA>     NA
12   P012    110
NA.1 <NA>     NA

Three patients have a missing sbp_12. NA < 120 is NA, not FALSE — and [ returns a row of NAs for every NA in the index.

nrow(trial[trial$sbp_12 < 120, ])
[1] 11
nrow(trial[which(trial$sbp_12 < 120), ])
[1] 8

4 · Three base verbs

subset()

subset(trial, arm == "Treatment" & age > 70,
       select = c(id, age, sbp_12))
     id age sbp_12
36 P036  75     97
38 P038  77    140
45 P045  73    105
55 P055  71    112
56 P056  78    161
60 P060  76    150

Columns unquoted, rows as a plain condition, and NA rows dropped for you. Compare the alternative:

trial[which(trial$arm == "Treatment" & trial$age > 70), c("id", "age", "sbp_12")]

subset()’s two hazards

nrow(subset(trial, arm = "Treatment"))
Warning: In subset.data.frame(trial, arm = "Treatment") :
 extra argument 'arm' will be disregarded
[1] 60

One = instead of ==. A warning, and all 60 rows back.

subset() is a convenience for interactive work. In a script that matters, [ with an explicit condition is more predictable — R’s own documentation says so.

trial <- transform(trial,
  change = sbp_12 - sbp_0,
  responder = sbp_12 < 130
)
head(trial[, c("id", "sbp_0", "sbp_12", "change", "responder")], 3)
    id sbp_0 sbp_12 change responder
1 P001   144    160     16     FALSE
2 P002   119    103    -16      TRUE
3 P003   155    157      2     FALSE

The equivalent, and what you will see far more often:

trial$change <- trial$sbp_12 - trial$sbp_0
trial$responder <- trial$sbp_12 < 130

Sorting with order()

head(trial[order(trial$sbp_12), c("id", "arm", "sbp_12")], 4)
     id       arm sbp_12
36 P036 Treatment     97
2  P002   Placebo    103
45 P045 Treatment    105
12 P012   Placebo    110
head(trial[order(trial$arm, -trial$sbp_0), c("id", "arm", "sbp_0")], 3)
     id     arm sbp_0
5  P005 Placebo   179
9  P009 Placebo   169
20 P020 Placebo   167

order() returns positions, which you then use to index. Multiple keys sort in the order given; negate a numeric key to reverse it.

sort, order, rank

x <- c(30, 10, 20)
sort(x)
[1] 10 20 30
order(x)
[1] 2 3 1
rank(x)
[1] 3 1 2
Function Returns Read as
sort(x) the values, rearranged “give me the sorted values”
order(x) positions, in sorted order “where do I find them”
rank(x) each value’s position when sorted “what place did each come in”

5 · Split–apply–combine

The pattern

Split the data by a grouping variable · apply a summary to each piece · combine the answers into one table. Almost every table in almost every paper is this.

tapply()

tapply(trial$sbp_12, trial$arm, mean)
  Placebo Treatment 
       NA        NA

Three missing values, so both means are NA. The NA is information, not an obstacle:

tapply(trial$sbp_12, trial$arm, mean, na.rm = TRUE)
  Placebo Treatment 
 146.8929  136.6552 
round(tapply(trial$sbp_12, list(trial$arm, trial$sex), mean, na.rm = TRUE), 1)
              F     M
Placebo   145.0 149.4
Treatment 134.4 138.8

aggregate(): the formula interface

aggregate(sbp_12 ~ arm, data = trial, FUN = mean)
        arm   sbp_12
1   Placebo 146.8929
2 Treatment 136.6552
aggregate(cbind(sbp_0, sbp_12) ~ arm + sex, data = trial, FUN = mean)
        arm sex    sbp_0   sbp_12
1   Placebo   F 147.2500 145.0000
2 Treatment   F 149.1429 134.3571
3   Placebo   M 150.2500 149.4167
4 Treatment   M 150.8000 138.8000

Read ~ as “by”. Left of it: what to summarise. Right of it: what to group by. + on the right adds grouping variables; cbind() on the left adds outcomes.

aggregate() drops rows quietly

aggregate(sbp_12 ~ arm, data = trial, FUN = length)
        arm sbp_12
1   Placebo     28
2 Treatment     29

28 and 29, not 30 and 30. The formula interface defaults to na.action = na.omit — rows with a missing outcome vanish before FUN runs.

aggregate(sbp_12 ~ arm, data = trial, FUN = mean,
          na.rm = TRUE, na.action = na.pass)
        arm   sbp_12
1   Placebo 146.8929
2 Treatment 136.6552

Counting: table() and friends

table(trial$arm, trial$grade)
           
            mild moderate severe life-threatening
  Placebo     16        6      8                0
  Treatment   13       12      5                0
round(prop.table(table(trial$arm, trial$sex), margin = 1), 2)
           
               F    M
  Placebo   0.53 0.47
  Treatment 0.47 0.53

margin = 1 gives row proportions, 2 gives columns, and omitting it divides by the grand total. Getting the margin wrong is the most common table error in submitted work.

You are learning the pattern, not the syntax

aggregate(sbp_12 ~ arm, data = trial, FUN = mean, na.rm = TRUE)
        arm   sbp_12
1   Placebo 146.8929
2 Treatment 136.6552

The same question in session 6 — not executed here, you have not been taught it:

trial |>
  group_by(arm) |>
  summarise(sbp_12 = mean(sbp_12, na.rm = TRUE))

Split, apply, combine. The syntax changes in session 6. The idea does not.

6 · Inspection discipline

str() first, always

str(trial[, c("id", "arm", "age", "sbp_12", "dose_mg", "grade")])
'data.frame':   60 obs. of  6 variables:
 $ id     : chr  "P001" "P002" "P003" "P004" ...
 $ arm    : chr  "Placebo" "Placebo" "Placebo" "Placebo" ...
 $ age    : num  57 63 55 51 62 58 51 53 55 87 ...
 $ sbp_12 : num  160 103 157 143 176 142 NA 155 159 129 ...
 $ dose_mg: chr  "0" "0" "0" "0" ...
 $ grade  : Factor w/ 4 levels "mild","moderate",..: 3 3 1 3 1 1 2 1 3 3 ...

Six columns, six lines. Name, type, and the first few values — everything you need to know whether your next line will work.

Five checks on any new data frame

dim(trial)
[1] 60 12
colSums(is.na(trial[, c("age", "sbp_0", "sbp_12", "dose_mg")]))
    age   sbp_0  sbp_12 dose_mg 
      0       0       3       0
  1. str() — types, and are they what you expected
  2. dim() — is the row count the number of patients you were promised
  3. summary() — impossible minima and maxima
  4. table() on every categorical column, with useNA = "ifany"
  5. colSums(is.na(...)) — where the holes are, before anyone asks

When it goes wrong

Symptom Cause Fix
argument is not numeric or logical: returning NA df["x"] where you wanted df[["x"]] Use $ or [[
Rows of NA with rownames like NA.1 NA in a logical row index which(), or subset()
undefined columns selected Row/column arguments swapped Rows first, then columns
incorrect number of dimensions [i, j] on a vector or a list Check str(); it is not 2-d
Numbers become small integers as.numeric(as.factor(x)) as.numeric(as.character(x))
Filter returns 0 rows for no reason Column name typo → $ gave NULL names(df), then [[
Grouped n smaller than expected aggregate() dropped NA rows Add a FUN = length check

Summary

  • Choose a container whose contract matches the operation.
  • A data frame is a list of equal-length columns; a matrix has one type.
  • [ preserves a container while [[ extracts one component.
  • State row meaning and keys before subsetting or summarizing.
  • Every grouped summary needs denominators and checks.

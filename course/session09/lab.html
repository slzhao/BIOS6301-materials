Session 9 guided lab

Discuss, revise, and verify with Posit Assistant

One report, one review cycle

Use Posit Assistant in Positron, connected to GitHub Copilot as the model provider. Posit Assistant supplies the conversation and tools. Copilot supplies access to the selected model. R runs the analysis.

The core lab takes about 35–40 minutes. Improve a supplied SBP scatterplot and repair a week-12 summary, then verify both in one rendered report. The four levels in the lecture describe different requests; you do not need to complete four separate analyses here.

Step Your task Approximate time
Set up Copy two files and connect the provider 5 minutes
Discuss Predict the problem, then use Ask 8 minutes
Revise Request a bounded edit and inspect the changes 10 minutes
Verify Run independent checks and render the report 12 minutes

1. Set up

  1. Open your BIOS6301-mywork folder in Positron. From the separate course materials folder, copy the Quarto starter and sbp-demo.csv into work/session09/. If you prefer R Markdown, use the Rmd starter instead. Choose one document format.
  2. Select your R interpreter. The lab uses the familiar ggplot2 and dplyr packages. Install either if missing before continuing.
  3. Open the copied document and Render it (or Knit the Rmd). Its read.csv("sbp-demo.csv") path is relative to the document’s folder. When running chunks interactively, check that the R working directory is work/session09/. Do not add a machine-specific absolute path to the report.
  4. If not already connected, open the Command Palette and run Authentication: Configure Language Model Providers. Select GitHub Copilot, sign in, and open Posit Assistant. Confirm the provider and selected model. Keep the usual Normal approval setting.

The CSV contains the same 60 synthetic patients used in class: id, arm, sbp_0, sbp_6, and sbp_12. Each row is one patient. SBP is in mmHg. Keep the original CSV unchanged.

If AI access is unavailable, use the supplied candidates and make the revisions yourself. Other tools remain permitted under the course policy, but the instructions below use our class configuration.

2. Discuss in Ask mode

Read the starter’s two candidates. Before asking AI, write one sentence predicting what the summary’s n counts after missing SBP rows are removed.

Select Ask (/ask). Use @ to reference your copied document and CSV, then send:

Read these two files. Explain which columns represent baseline and week-12 SBP. Explain why assigning the plot to p does not explicitly display it. Does the prepared summary report all patients or only patients with observed week-12 SBP? Suggest the smallest corrections. Do not change files.

Record whether the explanation agrees with your prediction and how the assistant obtained the column names.

Note

Reading a CSV does not require running R. Ask can read its header and values with a file tool. It cannot run names(trial) or other R code to inspect a live object. Automatic session context supplies object names/types, not their values. If needed, run an R check yourself and paste its output. A saved CSV can differ from an object you have transformed in memory.

3. Request a bounded revision

Save your prediction. Leave Ask using /normal, then send this implementation plan in Posit Assistant:

In my copied lab document, fill only the Revised plot and Corrected summary sections. Plot sbp_0 on x and sbp_12 on y, color by arm, label both axes in mmHg, and explicitly print the plot. Use complete pairs for the plot only. Summarize week-12 SBP by arm as n_total, n_observed, mean_sbp, and sd_sbp. Count all patients in n_total and use observed SBP for the mean and SD. Keep the CSV, original candidates, my prediction, verification code, and disclosure unchanged. Render or knit the document if the tools are available; otherwise tell me what to run. Report what you actually changed and ran.

Inspect the file differences before accepting the result. Check that the agent changed only the intended sections. If something is wrong, request one focused correction and inspect again. An agent’s statement that it ran the report is not enough: look for the command result or render it yourself.

This implements a supplied plan, matching level 3 in the lecture. Adding arm colors alone is a level-1 edit. The same interface can handle either scope.

4. Verify and explain

Run the starter’s supplied base-R checks yourself and compare them with the revised analysis. Check the rendered output as well as the code.

  • Plot: baseline on x, week 12 on y, labels in mmHg, and arm colors. There are 57 complete pairs and 3 omitted patients. Points can overlap, so use the count rather than trying to count visible dots.
  • Summary: two rows, one per arm. Total counts are 30 and 30. Observed week-12 counts are 28 Placebo and 29 Treatment.
  • Meaning: excluding a missing week-12 value from a mean must not exclude that patient from the total count. Explain this in your own words.

Save and render/knit the document from the beginning. Keep one source document and its HTML report, containing your prediction, the preserved candidates, revised plot and summary, verification results, and a short disclosure. Record Posit Assistant, GitHub Copilot as provider, and the displayed model name if available. Describe your own review and corrections.

Optional: develop a plan from a question

After the core report is complete, use Plan (/plan) and reference the CSV:

How does SBP change over the three visits, and how does that pattern differ by arm? Propose a short descriptive analysis plan. Explain how you would handle missing visits and repeated measurements. Do not implement it yet.

Identify one analytical decision you would question or change. This is level 4: developing a plan from a question. Plan mode can write a plan file; it differs from Ask’s enforced read-only behavior. No additional analysis is required.

Inline completion, next-edit suggestions, and the full three-visit implementation remain lecture demonstrations. The demo script and reference script are optional follow-up materials. Custom functions and edge-case testing are not part of this core lab.

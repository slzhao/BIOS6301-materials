Session 13 guided lab · Repeat checked operations

Work in BIOS6301-mywork.Rproj. Copy the starter from the separate BIOS6301-materials clone into work/session13/ in your personal repository. Choose Quarto or R Markdown. Render or Knit your copy. All supplied inputs are synthetic.

1. Start with a checked operation

The starter supplies the Session 11 helpers, following the contract protected in Session 12, and the same marker table. Run the supplied checks before iterating. one_summary(x) must return a numeric vector named n, mean, and sd. Use observed n; return numeric NA for the mean with no observations and for SD with fewer than two observations. Reject invalid input through safe_mean().

2. Loops and allocation

Build a matrix with three rows and one column per marker. Preallocate it with row names n, mean, sd and marker column names. Fill it using seq_along(markers) and markers[[j]]. Preserve a 3-by-0 matrix for zero columns. First practice the simpler scalar case with one safe_mean() result per column.

3. Vectorized operations

For the supplied numeric matrix, compute one row mean using each of a preallocated loop, apply(..., 1, mean), and rowMeans(). Use the same missing-value rule in all three. Verify numerical equivalence before measuring. Add a character ID column to a copy, inspect as.matrix(), and explain why the mixed data frame is not a safe input for numeric matrix summaries.

4. Lists and typed outputs

  1. Apply one_summary() with lapply() and vapply() using c(n = 0, mean = 0, sd = 0) as the template. Compare against the loop’s values, names, types, and dimensions.
  2. Check ordinary, all-missing, one-observation, and zero-column cases.
  3. Replace a marker with a character vector. Show that the helper rejects it. Explain why an output template alone cannot detect every invalid input.
  4. Use a named list of unequal-length numeric vectors with lapply() and vapply(..., safe_mean, numeric(1)). Different input lengths do not imply different output lengths when the operation returns one mean.

5. Base R and optional purrr

Use Map(change_summary, baseline_columns, followup_columns) for the two supplied paired lists. Check list lengths and matching names before mapping, then compare with a preallocated list filled by a loop. Each helper checks its paired vectors.

Optional equivalents: map(markers, one_summary) returns a list; map_dbl(markers, safe_mean) returns one number per marker. map_dbl() cannot hold all three statistics from one_summary() in one element. For paired lists, compare map2() with Map().

6. Choose and combine results

Create one data-frame row per marker, including the marker name and three statistics. Collect the rows in a preallocated list and bind once. State the zero-column output schema explicitly. Explain when an ordinary loop is clearer than an independent mapping, especially when the next step uses the previous state.

7. Verify and measure

Compare the supplied growing and preallocated square-root loops on the same input, checking equality first. Warm up both implementations and record at least five repetitions with system.time(). Do the same for the row-summary implementations. Report input dimensions, R version, repetition count, and observed variation. A zero elapsed time can be below timer resolution; do not claim infinite speedup.

Record object.size() for the input and final outputs. Explain that these are stored object-size estimates, not peak memory measurements. Recommend a solution using correctness, output shape, readability, and your actual measurements.

Exit evidence

Submit the checked helpers, iteration results, empty/invalid cases, equivalence checks, timing context, and recommendation. No hypothesis tests, confidence intervals, or simulation study design are required in this programming lab.

Optional bounded-loop practice

Starting at x = 1, repeatedly divide by two until x < 0.01, with an explicit maximum iteration count. Record whether the threshold or iteration limit ended the loop. Explain why the next input depends on the previous output.

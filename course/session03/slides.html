1 · Everything is a vector

There are no scalars

R has no single-number type. 42 is a vector of length one.

length(42)
[1] 1
length("hello")
[1] 1
x <- c(4, 9, 16)
sqrt(x)
[1] 2 3 4

sqrt(x) did not loop. The function applied to the whole vector at once. That is what “vectorized” means, and it is why R code for data analysis contains so few loops.

Four types you will actually use

Type Looks like typeof() Holds
logical TRUE, FALSE, NA "logical" Conditions, flags, filters
integer 1L, 1:10 "integer" Counts, indices, IDs
double 1, 3.14, 1e-8 "double" Everything measured
character "F", "P001" "character" Labels, IDs, free text 
c(typeof(TRUE), typeof(1L), typeof(1), typeof("F"))
[1] "logical"   "integer"   "double"    "character"

There are two more — complex and raw. You will not meet them this term.

Integer or double?

typeof(3)
[1] "double"

Use doubles. Write 3, not 3L. Integers matter in three places: memory for very large data, 1:n sequences, and reading someone else’s code.

Means Comes from Test with

Inf Infinite — too big, or divided by zero 1/0, exp(1000) is.infinite()

NA is contagious

creat <- as.numeric(creat_raw)
mean(creat)
[1] NA
mean(creat, na.rm = TRUE)
[1] 0.9385455
sum(is.na(creat))
[1] 5

na.rm = TRUE is not a fix. It is a decision — to analyse a different set of patients than the one you enrolled. Report how many you dropped.

NA == NA is not TRUE

NA == NA
[1] NA
creat[7] == NA
[1] NA

Two unknown values. Are they equal? Unknowable. So R returns NA.

is.na(creat[7])
[1] TRUE
NA & FALSE
[1] FALSE
NA | TRUE
[1] TRUE

3 · Coercion

One vector, one type

An atomic vector holds one type. Combine types and R does not complain — it picks the type that can hold everything.

Coercion runs left to right only. One character element and the whole vector is character. There is no way back that R will find for you.

c(1, 2, "3")

c(1, 2, "3")
[1] "1" "2" "3"
typeof(c(TRUE, 1L))
[1] "integer"
typeof(c(1L, 1.5))
[1] "double"
typeof(c(1.5, "a"))
[1] "character"

No error. No warning. No message. The quotes in the output are the only evidence anything happened.

Where this actually bites

Three cells in a creatinine column hold the text "NA". Two hold "<0.30".

str(creat_raw)
 chr [1:60] "1.49" "0.54" "0.7" "1.27" "0.64" "1.11" "NA" "1.39" "0.75" "1" ...
creat_raw[c(7, 12)]
[1] "NA"    "<0.30"
mean(creat_raw)
Warning in mean.default(creat_raw): argument is not numeric or logical:
returning NA
[1] NA
sum(creat_raw > 1.2)
[1] 14

Nine patients have a creatinine above 1.2. The count says fourteen: as text, both "NA" and "<0.30" sort above "1.2".

as.numeric() and what it costs

creat <- as.numeric(creat_raw)
Warning: NAs introduced by coercion
sum(is.na(creat))
[1] 5

R warned. But look at the count: five NAs, from three "NA" cells and two "<0.30" cells. The warning does not say which.

creat_raw[is.na(creat)]
[1] "NA"    "<0.30" "NA"    "NA"    "<0.30"

After every coercion: print the values that became NA. One line, and it turns a warning into information.

The one coercion that is a gift

TRUE is 1 and FALSE is 0, so arithmetic on logicals is counting.

sum(arm == "Treatment")
[1] 30
mean(sex == "F")
[1] 0.5166667
sum(is.na(creat))
[1] 5
round(100 * mean(sbp_0 > 140), 1)
[1] 78.3

sum() of a logical is how many. mean() of a logical is what proportion. You will use both constantly.

Sentinel values

The source system codes “not recorded” as -99.

mean(weight_kg)
[1] 68.72667
range(weight_kg)
[1] -99.0 114.4
weight_kg[weight_kg == -99] <- NA
mean(weight_kg, na.rm = TRUE)
[1] 80.70714

The first number is a plausible adult weight. It is wrong, and nothing warned you. No coercion, no error, no NA — a valid mean of invalid numbers.

4 · Names and indexing

Names

A vector’s elements can carry names, and names are a way to index.

sbp <- c(P001 = 152, P002 = 138, P003 = 161, P004 = 144)
names(sbp)
[1] "P001" "P002" "P003" "P004"
sbp["P003"]
P003 
 161 
sbp[c("P001", "P004")]
P001 P004 
 152  144 
sbp["P999"]
<NA> 
  NA

A name that does not exist gives NA, not an error. Silent again.

Four ways to subset

By Looks like Returns
Position x[c(1, 3)] Elements 1 and 3
Negation x[-1] Everything except element 1
Logical x[x > 140] Elements where the condition is TRUE
Name x["P003"] The element called P003

One operator, [, and four meanings, decided by what type you put inside it.

Position, and negation

sbp_0[1:3]
[1] 160 163 154
sbp_0[c(1, 60)]
[1] 160 160
length(sbp_0[-1])
[1] 59
length(sbp_0[-(1:10)])
[1] 50
sbp_0[c(-1, 2)]
Error in sbp_0[c(-1, 2)]: only 0's may be mixed with negative subscripts

The workhorse: logical subsetting

high <- sbp_0 > 160
head(high, 8)
[1] FALSE  TRUE FALSE FALSE FALSE FALSE FALSE  TRUE
length(sbp_0[high])
[1] 13
mean(sbp_12[arm == "Treatment"])
[1] 133.9
mean(sbp_12[arm == "Placebo"])
[1] 147.2

arm == "Treatment" is a logical vector of length 60, used as a mask over a different vector of length 60. This one line is the base-R equivalent of filter() plus summarise().

x[NA], x[FALSE], x[0]

x <- c(a = 10, b = 20, c = 30)
x[NA]
<NA> <NA> <NA> 
  NA   NA   NA 
x[FALSE]
named numeric(0)
x[0]
named numeric(0)
x[10]
<NA> 
  NA

x[NA] returns three NAs — the logical NA is recycled to length 3. x[FALSE] returns nothing at all. These are different failures with very different symptoms.

Subsetting on the left of <-

w <- c(78.2, -99, 91.5, -99, 84.0)
w[w == -99] <- NA
w
[1] 78.2   NA 91.5   NA 84.0
sbp_flag <- rep("normal", 5)
sbp_flag[c(152, 138, 161, 144, 130) > 140] <- "high"
sbp_flag
[1] "high"   "normal" "high"   "high"   "normal"

The same four ways of subsetting work on the left-hand side. This is how you repair a column in place.

which()

which() converts a logical vector into positions.

which(sbp_0 > 175)
[1] 46
id[which(sbp_0 > 175)]
[1] "P046"
which.max(sbp_0)
[1] 46
id[which.max(sbp_0)]
[1] "P046"

which() silently drops NAs. That is convenient, and it is a difference from logical subsetting you must know about.

%in%: the one that never returns NA

c(1, NA, 3) == 1
[1]  TRUE    NA FALSE
c(1, NA, 3) %in% 1
[1]  TRUE FALSE FALSE
sites <- c("VUMC", "MCV", "typo", NA)
sites %in% c("VUMC", "MCV")
[1]  TRUE  TRUE FALSE FALSE

Use %in% for set membership, == for a single comparison. %in% always returns TRUE or FALSE — never NA — which makes it safe inside [.

5 · Recycling

The rule

When two vectors have different lengths, R repeats the shorter one to match.

c(10, 20, 30) + 1
[1] 11 21 31
sbp_0[1:4] * 2
[1] 320 326 308 300

You have been relying on this since your first line of R. x * 2 is a length-60 vector plus a length-one vector, recycled sixty times.

c(1, 2, 3, 4) + c(10, 20)
[1] 11 22 13 24

When it divides evenly, R says nothing

Two arms, sixty patients. You want a per-arm baseline correction.

correction <- c(2, 5)             # Placebo, Treatment
adjusted <- sbp_0 - correction
adjusted[1:6]
[1] 158 158 152 145 153 144

Intended: subtract 2 from the 30 placebo patients, 5 from the 30 treatment patients. Actual: alternating 2, 5, 2, 5 down all sixty rows.

60 is a multiple of 2, so no warning. Every patient got a number. Half of them got the wrong one.

When it does not, R warns

c(1, 2, 3) + c(10, 20)
Warning in c(1, 2, 3) + c(10, 20): longer object length is not a multiple of
shorter object length
[1] 11 22 13

longer object length is not a multiple of shorter object length — a warning, not an error. The result is still returned and assigned.

This warning is one of the most valuable messages R produces. If you have warning: false in your YAML and have never read your warnings once, you will never see it.

6 · Vectorized conditionals

ifelse() is a function. if is not.

ifelse(test, yes, no) if (cond) ... else ...
Is a vectorized function control-flow keyword
Test length Any — one answer per element Exactly one TRUE or FALSE
Returns A vector as long as test Whatever the chosen branch returns
Used for Deriving a variable from a column Choosing what a script does
Taught in Today Session 11

They look alike, share four letters, and do unrelated jobs. Today we use ifelse(). if does not appear on any slide in this session.

ifelse()

bp_group <- ifelse(sbp_0 > 140, "high", "normal")
head(bp_group, 6)
[1] "high" "high" "high" "high" "high" "high"
table(bp_group)
bp_group
  high normal 
    47     13 
adjusted <- sbp_0 - ifelse(arm == "Treatment", 5, 2)
adjusted[c(1, 2, 31, 32)]
[1] 158 161 150 130

The second line is the recycling bug from block 5, fixed — because the condition is length 60, so the answer is length 60.

Three ways ifelse() surprises you

ifelse(c(TRUE, FALSE, NA), "yes", "no")
[1] "yes" "no"  NA   
ifelse(c(TRUE, FALSE), c(1, 2, 3), 0)
[1] 1 0
ifelse(c(FALSE, TRUE), 1, "x")
[1] "x" "1"

NA in the test gives NA out · the result is as long as the test, not the branches · and the branches are coerced to one type.

Borrowed — session 6: if_else()

library(dplyr)

# Errors instead of coercing:
if_else(c(TRUE, FALSE), 1, "x")
#> Error: Can't combine `true` <double> and `false` <character>.

# Errors instead of truncating:
if_else(c(TRUE, FALSE), c(1, 2, 3), 0)
#> Error: `true` must have size 2, not size 3.

# And gives you somewhere to put the missing values:
if_else(c(TRUE, FALSE, NA), 1, 0, missing = -1)
#> [1]  1  0 -1

dplyr::if_else() is ifelse() with the three surprises turned into errors. You meet dplyr properly in session 6 — this is here so you recognise it.

Borrowed — session 6: case_when()

# Conditions are checked top to bottom; first match wins.
bp_group <- case_when(
  is.na(sbp_0)  ~ "missing",
  sbp_0 >= 160  ~ "stage 2",
  sbp_0 >= 140  ~ "stage 1",
  sbp_0 >= 130  ~ "elevated",
  .default      = "normal"
)

The base R way

bp_group <- rep("normal", length(sbp_0))
bp_group[sbp_0 >= 130] <- "elevated"
bp_group[sbp_0 >= 140] <- "stage 1"
bp_group[sbp_0 >= 160] <- "stage 2"
bp_group[is.na(sbp_0)] <- "missing"

7 · Where this leaves you

Everything today was a silent wrong answer

Session 1: the two ways an analysis fails. It won’t run — annoying, honest. It runs and is wrong — dangerous.

Today’s bug What R said What you got
c(1, 2, "3") Nothing A character vector
creat_raw > 1.2 Nothing 14 patients above 1.2. There are 9
"<0.30" coerced A warning you will skim Two patients silently missing
mean(weight_kg) with -99 Nothing A plausible, wrong mean
sbp_0 - c(2, 5) Nothing Half the cohort mis-adjusted
x["P999"] Nothing NA where you expected a value
ifelse(cond, 1, "x") Nothing Numbers turned into text

Seven bugs. One warning between them. This is why class(), str(), range(), and length() are habits and not commands.

Summary

  • Atomic vectors have one type and R coerces toward a common type.
  • NA propagates; test it with is.na() rather than equality.
  • Logical indexing expresses inclusion rules directly.
  • Recycling can return plausible results without an error.
  • ifelse() is vectorized classification; scalar control flow arrives in Session 11.

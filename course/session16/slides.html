1 · An analysis workflow

One synthetic study

head(trial[, c("id", "arm", "sbp_0", "sbp_12", "response")], 4)
    id     arm    sbp_0   sbp_12 response
1 P001 Control 180.0144 172.4916        0
2 P002 Control 160.3498 160.5407        0
3 P003 Control 144.7369 158.8301        0
4 P004 Control 161.3452 158.3983        0

One row represents one participant. Baseline and 12-week SBP are continuous; response is a separately generated binary teaching outcome.

All data are synthetic. The examples teach computing interfaces, not a clinical analysis recommendation.

Define the target before fitting

Task Target Computing evidence
Adjusted mean comparison Model coefficient for treatment at specified covariates Formula, sample, contrast, interval
Predict 12-week SBP Outcome for a new participant Predictor availability and held-out error
Model a binary response Probability of response = 1 Outcome coding and prediction scale

These tasks can use similar functions while answering different questions.

Make the analysis population explicit

vars <- c("id", "arm", "sbp_0", "age", "sbp_12", "response")
keep <- complete.cases(trial[, vars])
analysis <- trial[keep, vars]
c(available = nrow(trial), analysed = nrow(analysis), excluded = sum(!keep))
available  analysed  excluded
       80        77         3 
trial$id[!keep]
[1] "P005" "P029" "P061"
stopifnot(!anyDuplicated(analysis$id))

Complete-case filtering is explicit here for teaching. It changes the population being analysed and may introduce bias; it is not a universal missing-data strategy.

A checkable analysis contract

  • Input: one row per participant; specified units and factor levels.
  • Sample: record exclusions and reasons, retaining identifiers.
  • Fit: a stated formula and fitting procedure.
  • Output: estimates or predictions with their target and uncertainty.
  • Evidence: diagnostic checks, held-out evaluation when relevant, and provenance.

An error-free lm() call establishes only that the computation completed.

2 · Formulas and model objects

Read a model formula

f <- sbp_12 ~ sbp_0 + age + arm
f
sbp_12 ~ sbp_0 + age + arm

The response is left of ~; the terms on the right specify predictors. An intercept is included by default. In formulas, + adds model terms rather than adding the columns numerically.

Use data = analysis so the intended source of variables is clear.

Formula operators

Formula fragment Model terms
x + z Main effects of x and z
x * z x + z + x:z
x:z Interaction term
x + I(x^2) Linear and literal squared x terms
x - 1 Remove the intercept

The formula ^ has special term-expansion meaning. Use I() when ordinary arithmetic is intended. Include interactions because the scientific question requires them, not simply because the syntax is available.

Factors determine the comparison

analysis$arm <- factor(analysis$arm, levels = c("Control", "Treatment"))
levels(analysis$arm)
[1] "Control"   "Treatment"
contrasts(analysis$arm)
          Treatment
Control           0
Treatment         1

With the treatment contrasts used here, Control is the reference. armTreatment represents the Treatment-versus-Control coefficient conditional on the other terms in this additive model.

Changing the reference changes coefficient interpretation, not the fitted values.

X <- model.matrix(f, data = analysis)

Factors become numeric contrast columns. Collinear columns can make coefficients unidentifiable even when the formula looks reasonable.

State the outcome’s units, reference category, sample size, and adjustment terms. An adjusted coefficient is not automatically a causal effect.

Verify rows and fitted values

stopifnot(nobs(fit) == nrow(analysis),
  nrow(model.frame(fit)) == nrow(analysis),
  isTRUE(all.equal(as.numeric(X %*% coef(fit)), as.numeric(fitted(fit)))))

This independently checks the link between the matrix, coefficients, and fitted values. It does not establish that the model assumptions are appropriate.

Practice: a silent sample change

A report says “80 participants.” The fitted object reports 77 observations. The analyst used the default missing-value handling in lm().

Which variables and identifiers should be checked? Which denominator belongs beside the reported coefficient table?

Practice: inspect the fitted sample

Compare the required variables, the complete-case indicator, nobs(fit), and model.frame(fit). Record the excluded IDs and the missing fields.

Report the sample actually used by the model. For comparisons between models, also check whether different formulas cause different rows to be included.

3 · Prediction and diagnostics

Construct prediction data deliberately

new_people <- data.frame(sbp_0 = c(140, 155), age = c(55, 65),
  arm = factor(c("Control", "Treatment"), levels = levels(analysis$arm)))
predict(fit, newdata = new_people)
       1        2
136.0147 144.4334

Match predictor names, units, and factor levels. Do not substitute fitted(fit) for predictions on new rows; fitted values describe the training observations.

Mean-response and prediction intervals

mean_ci <- predict(fit, new_people, interval = "confidence")
person_pi <- predict(fit, new_people, interval = "prediction")
round(cbind(mean_ci, prediction_lower = person_pi[, "lwr"],
                     prediction_upper = person_pi[, "upr"]), 2)
     fit    lwr    upr prediction_lower prediction_upper
1 136.01 133.60 138.43           122.97           149.06
2 144.43 142.07 146.80           131.39           157.47

The confidence interval concerns the conditional mean response. The prediction interval concerns an individual future response and also includes residual variation. Both depend on the model’s assumptions.

Unsupported predictions

  • A new factor level may prevent prediction.
  • Extrapolation can return a number even far outside the training data.
  • A response-derived predictor may be unavailable at deployment.
  • A narrow model-based interval does not measure every source of uncertainty.
range(analysis$sbp_0)
[1] 103.4681 180.0144
range(new_people$sbp_0)
[1] 140 155

Inspect prediction inputs before interpreting outputs.

Residuals versus fitted values

Look for curvature, changing spread, and unusual observations. A pattern suggests follow-up questions; absence of a visible pattern is not proof of adequacy.

Quantile and influence diagnostics

Investigate flagged records and model sensitivity. Do not delete a participant only because a diagnostic is large.

Preserve identifiers in diagnostics

diagnostics <- data.frame(id = analysis$id, fitted = fitted(fit),
  residual = residuals(fit), cook = cooks.distance(fit))
head(diagnostics[order(diagnostics$cook, decreasing = TRUE), ], 3)
     id   fitted  residual       cook
48 P048 123.6897  20.33375 0.23009097
63 P063 118.6843  13.30352 0.09322739
80 P080 133.1987 -17.48357 0.07514031

Row numbers can change after filtering or sorting. An ID makes a diagnostic traceable to its original record.

Diagnostics and validation differ

Evidence Question
Residual plots and influence Where might the fitted model be inadequate or sensitive?
Cross-validation from Session 15 How well does the fitting procedure predict held-out observations?
External evaluation Does performance transfer to the target setting?

Good training fit is not a substitute for held-out evaluation.

4 · Binary outcomes

A binomial model in R

table(analysis$response)

 0  1
46 31 
binary_fit <- glm(response ~ sbp_0 + arm,
  family = binomial(), data = analysis, na.action = na.fail)
coef(binary_fit)
 (Intercept)        sbp_0 armTreatment
  3.69733903  -0.03322019   1.42751727

Here response is numeric 0/1 and the target event is explicitly response = 1. The default binomial link is logit; coefficients are on the log-odds scale.

Link scale and response scale

eta <- predict(binary_fit, newdata = new_people, type = "link")
prob <- predict(binary_fit, newdata = new_people, type = "response")
data.frame(log_odds = eta, probability = prob)
     log_odds probability
1 -0.95348786   0.2781839
2 -0.02427348   0.4939319
stopifnot(isTRUE(all.equal(unname(plogis(eta)), unname(prob))),
          all(prob >= 0 & prob <= 1))

Omitting type returns link-scale predictions for this GLM. Always label the scale.

Coefficients and probabilities

c(log_odds_coefficient = coef(binary_fit)["armTreatment"],
  conditional_odds_ratio = exp(coef(binary_fit)["armTreatment"]))
  log_odds_coefficient.armTreatment conditional_odds_ratio.armTreatment
                           1.427517                            4.168337

Exponentiating a logit coefficient gives a conditional odds ratio for that term, not a risk ratio or probability difference. Predicted probabilities depend on the other covariates as well.

Statistical interpretation requires the model specification and study design.

Inspect fitting problems

c(converged = binary_fit$converged,
  finite_coefficients = all(is.finite(coef(binary_fit))))
          converged finite_coefficients
               TRUE                TRUE 
range(fitted(binary_fit))
[1] 0.09255983 0.84391180

Warnings, very large coefficients, or probabilities near 0 and 1 can require investigation, including sparse cells or separation. A convergence flag alone does not establish reliable inference.

Use methods guidance for a remedy; do not suppress warnings until the output looks clean.

5 · Numerical computation

Three numerical tasks

Task R function Result to check
Minimize or maximize a scalar function on an interval optimize() Location, objective, and boundaries
Find a zero of a continuous function uniroot() Root, residual, and bracket
Integrate a function over a range integrate() Value, reported numerical error, and known checks

Statistical software performs such calculations internally. A transparent one-dimensional example makes the computational contract visible.

Write a negative log-likelihood

counts <- c(0, 1, 2, 1, 4, 3, 2, 0, 5, 2)
poisson_nll <- function(lambda, y) {
  if (length(lambda) != 1L || !is.finite(lambda) || lambda <= 0)
    return(Inf)
  -sum(dpois(y, lambda = lambda, log = TRUE))
}
poisson_nll(2, counts)
[1] 17.9738

For independent Poisson counts, log-probabilities add. The negative sign makes maximum likelihood a minimization problem. These counts share the same exposure.

Inspect the objective

A plot can reveal a wrong sign, a poor search interval, or multiple minima. It complements numerical checks; it does not prove the global solution.

Optimize and verify a known answer

opt <- optimize(poisson_nll, interval = c(.001, 10), y = counts)
c(numerical = opt$minimum, analytic = mean(counts), objective = opt$objective)
numerical  analytic objective
 1.999996  2.000000 17.973803 
stopifnot(abs(opt$minimum - mean(counts)) < 1e-3)

For these Poisson observations, the maximum-likelihood mean is the sample mean. Agreement checks this implementation against a result available independently.

Boundaries and tolerances

narrow <- optimize(poisson_nll, interval = c(.001, 1), y = counts)
c(wrong_search_result = narrow$minimum, known_solution = mean(counts))
wrong_search_result      known_solution
           0.999934            2.000000

The algorithm searches the interval supplied. A result near a boundary requires checking the interval and the parameter space.

If every count is zero, the Poisson optimum is the boundary lambda = 0; the positive-only objective above needs a separate boundary rule.

Root finding as an inverse calculation

target <- function(z) pnorm(z) - .975
c(left = target(0), right = target(4))
       left       right
-0.47500000  0.02496833 
root <- uniroot(target, interval = c(0, 4), tol = 1e-8)
c(root = root$root, residual = target(root$root), reference = qnorm(.975))
        root     residual    reference
1.959964e+00 2.430356e-11 1.959964e+00

For a continuous function, opposite endpoint signs bracket at least one root. Check the equation at the returned value, not only the convergence message.

Numerical integration

area <- integrate(dnorm, lower = -1.96, upper = 1.96)
c(numerical = area$value, reported_error = area$abs.error,
  cdf_difference = pnorm(1.96) - pnorm(-1.96))
     numerical reported_error cdf_difference
  9.500042e-01   1.047410e-11   9.500042e-01

The integrand must accept a vector of inputs and return corresponding values. The reported error concerns numerical approximation, not sampling uncertainty.

Practice: classify the failure

  1. A likelihood optimizer returns the upper limit of a narrow search interval.
  2. A root finder receives endpoints where the function has the same sign.
  3. Increasing simulation replicates does not change a mistaken likelihood formula.

For each, identify what should be inspected before increasing iteration limits.

Practice: check the mathematical contract

  1. Plot the objective, inspect the parameter space, and expand a justified interval.
  2. Check continuity, the equation, and a bracket containing a sign change.
  3. Validate the formula against a known case; more repetition cannot repair it.

Numerical tolerance, Monte Carlo error, and sampling uncertainty describe different problems.

6 · Structured text

A narrow identifier grammar

specimen_raw <- c(" P001-W00 ", "P010-W12", "P020-W99", "P999-W04",
                  "junkP003-W12", "P004-W4", NA, "P005-W12")
specimen_raw
[1] " P001-W00 "   "P010-W12"     "P020-W99"     "P999-W04"     "junkP003-W12"
[6] "P004-W4"      NA             "P005-W12"

The specification is P + three digits + -W + two digits. Permitted visits are 0, 4, 12, and 26, and the participant must exist in the registry.

Shape, allowed values, and registry membership are separate checks.

Anchors and capture groups

pattern <- "^(P[0-9]{3})-W([0-9]{2})$"
normalized <- toupper(trimws(specimen_raw))
stringr::str_match(normalized, pattern)
     [,1]       [,2]   [,3]
[1,] "P001-W00" "P001" "00"
[2,] "P010-W12" "P010" "12"
[3,] "P020-W99" "P020" "99"
[4,] "P999-W04" "P999" "04"
[5,] NA         NA     NA
[6,] NA         NA     NA
[7,] NA         NA     NA
[8,] "P005-W12" "P005" "12"

^ and $ require the complete string to match. Parentheses capture the participant ID and visit. The returned matrix preserves one row per input, including missing values and nonmatches.

Escaping and literal punctuation

x <- c("report.csv", "reportXcsv")
data.frame(x, loose = grepl(".csv$", x),
  literal_dot = grepl("\\.csv$", x),
  raw_string = grepl(r"(\.csv$)", x))
           x loose literal_dot raw_string
1 report.csv  TRUE        TRUE       TRUE
2 reportXcsv  TRUE       FALSE      FALSE

R string parsing and regex parsing are separate layers. A raw string removes R’s backslash doubling; it does not remove the regex engine’s special syntax. Use literal matching when no pattern language is needed.

Preserve rows in base R extraction

parts <- regmatches(normalized, regexec(pattern, normalized))
id_base <- vapply(parts, function(z)
  if (length(z) == 3L) z[2] else NA_character_, character(1))
id_stringr <- stringr::str_match(normalized, pattern)[, 2]
stopifnot(identical(unname(id_base), unname(id_stringr)))

A failed match is retained as missing. Do not drop nonmatches and then attach the shorter result to the original data by position.

An auditable parser

parse_specimen <- function(x, known_ids) {
  stopifnot(is.character(x), is.character(known_ids))
  clean <- toupper(trimws(x))
  m <- stringr::str_match(clean, "^(P[0-9]{3})-W([0-9]{2})$")
  id <- m[, 2]; week <- as.integer(m[, 3])
  status <- ifelse(is.na(x), "missing", ifelse(is.na(id), "bad format",
    ifelse(!id %in% known_ids, "unknown ID",
      ifelse(!week %in% c(0L, 4L, 12L, 26L), "invalid visit", "ok"))))
  data.frame(raw = x, normalized = clean, id, week, status)
}

The first failing rule supplies status; the raw value remains available for review.

Test near misses and semantic failures

parsed <- parse_specimen(specimen_raw, trial$id)
expected <- c("ok", "ok", "invalid visit", "unknown ID",
              "bad format", "bad format", "missing", "ok")
stopifnot(nrow(parsed) == length(specimen_raw),
          identical(parsed$status, expected))
parsed[, c("raw", "id", "week", "status")]
           raw   id week        status
1    P001-W00  P001    0            ok
2     P010-W12 P010   12            ok
3     P020-W99 P020   99 invalid visit
4     P999-W04 P999    4    unknown ID
5 junkP003-W12 <NA>   NA    bad format
6      P004-W4 <NA>   NA    bad format
7         <NA> <NA>   NA       missing

P020-W99 has the right shape but an invalid visit. A regex alone cannot verify the study protocol or registry membership.

Review before joining

table(parsed$status, useNA = "ifany")

   bad format invalid visit       missing            ok    unknown ID
            2             1             1             3             1 
accepted <- parsed[parsed$status == "ok", ]
review <- parsed[parsed$status != "ok", ]
stopifnot(nrow(accepted) + nrow(review) == nrow(parsed))

Check uniqueness of the intended key before joining. Multiple specimens at the same participant-visit may be legitimate; determine whether a specimen ID is also needed.

Keep pattern matching within its scope

  • A valid-looking identifier is not evidence of a valid study record.
  • A text mention is not equivalent to a confirmed condition or medication use.
  • Clinical negation and ambiguous instructions need domain-aware review.
  • Date strings need date parsing and calendar validation, already introduced earlier.

Use a documented grammar for structured text. Keep uncertain records visible.

7 · Reproducible handoff

Record what produced the result

analysis_bundle <- list(
  formula = formula(fit), analysed_ids = analysis$id,
  excluded_ids = trial$id[!keep], coefficients = results,
  seed = 6301, rng = RNGkind(), session = sessionInfo())
names(analysis_bundle)
[1] "formula"      "analysed_ids" "excluded_ids" "coefficients" "seed"
[6] "rng"          "session"

Also record the input version, analysis-code revision, and missing-data policy. In this teaching example the generator and seed define the synthetic input.

Save objects and plain tables

dir.create("output", showWarnings = FALSE)
saveRDS(analysis_bundle, "output/analysis-bundle.rds")
write.csv(results, "output/coefficients.csv", row.names = FALSE)
write.csv(review, "output/specimen-review.csv", row.names = FALSE)
writeLines(capture.output(sessionInfo()), "output/session-info.txt")

RDS preserves R structure; CSV supports inspection in other tools. The report explains the result. The source and input specification make it reproducible.

Package versions are part of the environment

sessionInfo() records the active R session but does not recreate its packages. renv adds a project library and a lockfile describing package dependencies.

# Optional: run interactively in a dedicated project, not during report rendering.
renv::init()
# After confirming the project works:
renv::snapshot()
# In a clone with the committed lockfile:
renv::restore()

These commands are a setup workflow, not required execution in today’s lab.

What to version and what to document

Keep in project history Document separately
Analysis source and input specification Data access and permitted storage
renv.lock, activation files, and settings Required R version and system dependencies
Tests and a concise README How to regenerate expensive results

Follow renv’s generated ignore rules; do not commit its installed package library. A lockfile records dependencies, not the data, operating system, or complete machine.

A reproducible delivery check

  1. Open a clean R session in the documented project environment.
  2. Obtain the specified input and run the analysis from the documented entry point.
  3. Confirm sample counts, key uniqueness, coefficient names, and prediction checks.
  4. Render the report and inspect tables and figures.
  5. Confirm that the outputs identify their input, code, and environment versions.

Use a colleague’s rerun to test the instructions, not only your current workspace.

Exit check

Explain each discrepancy before accepting the result:

  • The model sample is smaller than the report’s denominator.
  • A binomial prediction is negative because it is on the link scale.
  • An optimizer returns a boundary because the interval excludes the solution.
  • A specimen ID matches the pattern but is absent from the registry.
  • The report runs locally but its package environment is undocumented.

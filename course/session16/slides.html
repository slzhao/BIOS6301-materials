1 · Text is data, and it arrives broken

The column that will not be a number

Six rows of a real-shaped dose field from an EHR extract:

dose
[1] "10 mg BID"              "2.5mg daily"           
[3] " 20 MG bid "            "lisinopril 10 mg PO QD"
[5] "5mg q.d."               "one tablet daily"      
as.numeric(dose)
Warning: NAs introduced by coercion
[1] NA NA NA NA NA NA

The dose is in there. It is just wrapped in a drug name, a unit, a frequency, and somebody’s spacebar.

2 · Seven verbs, two dialects

Detect: is the pattern there?

# stringr
str_detect(dose, "mg")
str_subset(dose, "BID")
# the base R way
grepl("mg", dose)
[1]  TRUE  TRUE FALSE  TRUE  TRUE FALSE
grep("BID", dose, ignore.case = TRUE, value = TRUE)
[1] "10 mg BID"   " 20 MG bid "

grepl() returns a logical vector the same length as the input — so it goes straight into subset(), filter(), or [. grep() returns positions, or the matching values with value = TRUE.

Extract: pull the match out

# stringr
str_extract(dose, "[0-9.]+")
# the base R way, and it has a trap
m <- regexpr("[0-9.]+", dose)
regmatches(dose, m)
[1] "10"  "2.5" "20"  "10"  "5"

Six strings in, five out. regmatches() drops non-matches instead of returning NA, so the result no longer lines up with your data frame.

out <- rep(NA_character_, length(dose))
out[m > 0] <- regmatches(dose, m)
as.numeric(out)
[1] 10.0  2.5 20.0 10.0  5.0   NA

Replace: first, or all

# stringr
str_replace(dose, " +", " ")       # first run of spaces only
str_replace_all(dose, " +", " ")   # every run
# the base R way
sub(" +", " ", dose)
[1] "10 mg BID"              "2.5mg daily"           
[3] " 20 MG bid "            "lisinopril 10 mg PO QD"
[5] "5mg q.d."               "one tablet daily"      
gsub(" +", " ", dose)
[1] "10 mg BID"              "2.5mg daily"           
[3] " 20 MG bid "            "lisinopril 10 mg PO QD"
[5] "5mg q.d."               "one tablet daily"

sub() is str_replace(). gsub() is str_replace_all(). The g is for global, and forgetting it is the most common string bug in R.

Split: one field into many

# stringr
str_split(comorb, " *[;,|] *")
# the base R way — note what comes back
parts <- strsplit(comorb, " *[;,|] *")
parts[1:3]
[[1]]
[1] "HTN"  "T2DM"

[[2]]
[1] "hypertension" "CKD stage 3" 

[[3]]
[1] "HTN" "DM2" "CKD"
lengths(parts)
[1] 2 2 3 2 2 2 1

Slice, trim, pad

# stringr
str_sub(icd, 1, 1)                  # the ICD-10 chapter letter
str_trim(icd)
str_pad(c("12345", "7"), 7, pad = "0")
# the base R way
substr(icd, 1, 1)
[1] "I" "E" "i" "E" " " "Z" "H"
trimws(icd)
[1] "I10"     "E11.9"   "i10"     "E119"    "I10"     "Z79.899" "HTN"    
sprintf("%07d", as.integer(c("12345", "7")))
[1] "0012345" "0000007"

formatC(x, width = 7, flag = "0") pads with spaces when x is character. sprintf("%07d", ...) on an integer is the reliable base idiom.

3 · Escaping and the double backslash

The double-backslash problem

The regex for “a digit” is \d. But R will not let you type that.

p <- "\d+"
Error: '\d' is an unrecognized escape in character string (<input>:1:8)
p <- "\\d+"
p            # what R stores, shown as source
[1] "\\d+"
cat(p)       # what the regex engine actually receives
\d+
nchar(p)
[1] 3

What has to be escaped

You want to match Write in R Because
any digit "\\d" \d is a regex class
whitespace "\\s" \s is a regex class
a word character "\\w" letters, digits, _
a literal dot "\\." bare . means any character
a literal ( "\\(" bare ( opens a group
a literal [ "\\[" bare [ opens a class
a literal backslash "\\\\" two layers, two doublings 
c(grepl(".", "no dot here"),
  grepl("\\.", "no dot here"),
  grepl(".", "no dot here", fixed = TRUE))
[1]  TRUE FALSE FALSE

Raw strings

R 4.0 added a syntax that turns off the backslash doubling entirely.

r"(\d+\s*mg)"          # a raw string: what you see is what R stores
[1] "\\d+\\s*mg"
grepl(r"(\d+)", dose)
[1]  TRUE  TRUE  TRUE  TRUE  TRUE FALSE

r"(...)" — the delimiter is r"( and )". If your pattern contains )", use r"[...]" or r"{...}" instead.

Copy a pattern from regex101 into r"( )" and it works unchanged. That is the whole reason to know this exists.

4 · Regex proper

A pattern is a description of a set of strings

Read this out loud, left to right:

"^[A-Z][0-9]{2}(\\.[0-9]{1,4})?$"
Piece Means
^ start of the string — nothing before this
[A-Z] exactly one capital letter
[0-9]{2} exactly two digits
(...) a group, so the ? applies to the whole thing
\\. a literal dot
[0-9]{1,4} one to four digits
? the group is optional
$ end of the string — nothing after this

That is a valid ICD-10 code: I10, E11.9, Z79.899.

Character classes

Class Matches Note
[abc] one of a, b, c
[a-z] [A-Z] [0-9] a range
[^0-9] anything except a digit ^ inside [ ] means “not”
\\d \\w \\s digit · word character · whitespace
\\D \\W \\S the negations capital = “not”
. any single character except newline
[[:alpha:]] [[:punct:]] POSIX classes portable, verbose 
gsub("[^0-9]", "", mrn)      # keep only the digits
[1] "0012345" "12345"   "0012345" "0012345" "12345"

Quantifiers

Quantifier Means Example
* zero or more "mg *"
+ one or more "[0-9]+"
? zero or one "\\.?"
{n} exactly n "[0-9]{2}"
{n,} n or more "[0-9]{3,}"
{n,m} between n and m "[0-9]{1,4}" 
v <- c("E11", "E11.9", "E11.90", "E1", "")
rbind(strict  = grepl("^[A-Z][0-9]{2}$", v),
      relaxed = grepl("^[A-Z][0-9]{2}\\.?[0-9]*$", v))
        [,1]  [,2]  [,3]  [,4]  [,5]
strict  TRUE FALSE FALSE FALSE FALSE
relaxed TRUE  TRUE  TRUE FALSE FALSE

Anchors and boundaries

# unanchored: "is it in there anywhere?"
grepl("[0-9]{3}", c("P001", "site 1004 visit", "P01"))
[1]  TRUE  TRUE FALSE
# anchored: "is that the whole string?"
grepl("^P[0-9]{3}$", c("P001", "site 1004 visit", "P01"))
[1]  TRUE FALSE FALSE

\\b is a word boundary — the edge between a word character and anything else.

rbind(loose = grepl("MI", comorb, ignore.case = TRUE),
      tight = grepl("\\bMI\\b", comorb, ignore.case = TRUE))
       [,1]  [,2]  [,3]  [,4] [,5]  [,6]  [,7]
loose FALSE FALSE FALSE  TRUE TRUE FALSE FALSE
tight FALSE FALSE FALSE FALSE TRUE FALSE FALSE

Alternation and groups

| means or. Parentheses control what it applies to.

grepl("BID|TID|daily", dose, ignore.case = TRUE)
[1]  TRUE  TRUE  TRUE FALSE FALSE  TRUE
# the parentheses matter
v <- c("HTN", "HTN x", "x hypertension")
rbind(grouped   = grepl("^(HTN|hypertension)$", v),
      ungrouped = grepl("^HTN|hypertension$",   v))
          [,1]  [,2]  [,3]
grouped   TRUE FALSE FALSE
ungrouped TRUE  TRUE  TRUE

^HTN|hypertension$ means “starts with HTN” or “ends with hypertension” — almost never what was intended.

Capture groups

Parentheses do a second job: they remember what they matched.

m <- regexec("([0-9.]+) *(mg|mcg)\\b", dose, ignore.case = TRUE)
regmatches(dose, m)[1:3]
[[1]]
[1] "10 mg" "10"    "mg"   

[[2]]
[1] "2.5mg" "2.5"   "mg"   

[[3]]
[1] "20 MG" "20"    "MG"

Element 1 of each result is the whole match; elements 2 and 3 are the two groups. The stringr equivalent is str_match(dose, ...), which returns a matrix — one column per group — and keeps non-matches as NA.

The card to keep

^ start \\d digit
$ end \\w word character
. any character \\s whitespace
* 0 or more \\b word boundary
+ 1 or more [abc] one of these
? 0 or 1 [^abc] none of these
{n,m} between n and m (...) group and capture
*? +? lazy versions (?:...) group only
| or \\1 backreference

Nine rows. That is the whole language for everything you will do this year.

5 · Clinical free text, end to end

Five steps, every time

Step 1 is the one people skip, and step 5 is the one that catches the mistake step 1 would have prevented.

Dose strings

sort(table(trial$dose_raw), decreasing = TRUE)[1:6]

           12.5 mg QHS               5mg q.d.             10 mg  bid 
                     7                      7                      6 
lisinopril 10 mg PO QD       one tablet daily             20 MG bid  
                     6                      6                      5 
d <- tolower(trimws(gsub(" +", " ", trial$dose_raw)))     # normalise
m <- regexec("([0-9.]+) ?mg\\b", d)                       # extract
mg <- vapply(regmatches(d, m),
             function(p) if (length(p)) as.numeric(p[2]) else NA_real_,
             numeric(1))
c(n = length(mg), missing = sum(is.na(mg)), median = median(mg, na.rm = TRUE))
      n missing  median 
     60       9      10

ICD-10 codes

icd
[1] "I10"     "E11.9"   "i10"     "E119"    " I10 "   "Z79.899" "HTN"    
norm  <- sub("\\.$", "", toupper(trimws(icd)))    # normalise
valid <- grepl("^[A-Z][0-9][0-9A-Z](\\.[0-9A-Z]{1,4})?$", norm)
data.frame(raw = icd, norm, valid)
      raw    norm valid
1     I10     I10  TRUE
2   E11.9   E11.9  TRUE
3     i10     I10  TRUE
4    E119    E119 FALSE
5    I10      I10  TRUE
6 Z79.899 Z79.899  TRUE
7     HTN     HTN FALSE

E119 fails — and it should. Some extracts drop the decimal point, and E119 is not a code; it is E11.9 with information removed.

What a regex is bad at

Problem Why regex is wrong Use instead
Nested or paired structure It cannot count depth A parser
Dates in mixed formats The hard part is meaning, not shape lubridate — session 5
“Not X” in a clinical note Negation is language, not syntax A human, or clinical NLP
A fixed, known string Slower and can misfire ==, %in%, fixed = TRUE
A fixed-width field Position is simpler and safer substr()

Every row here is a case where the regex appears to work on your data and fails on somebody else’s.

6 · Testing a pattern, and making it a function

Never trust a pattern you have not tried to break

# stringr: highlights every match, in the Viewer
str_view(dose, "[0-9.]+ ?mg")
  • regex101.com — paste the pattern and the strings; it explains every token and shows what each group captured. Set the flavour to PCRE.
  • Build the pattern against a vector that contains the cases that should fail, not only the ones that should pass.

A pattern tested only on strings that match is not tested.

The test-case habit

# Return the milligram dose from a free-text prescription string, or NA.
extract_dose_mg <- function(x) {
  stopifnot(is.character(x))
  x <- tolower(trimws(gsub(" +", " ", x)))
  m <- regexec("([0-9.]+) ?mg\\b", x)
  vapply(regmatches(x, m),
         function(p) if (length(p)) as.numeric(p[2]) else NA_real_,
         numeric(1))
}

stopifnot(
  identical(extract_dose_mg("10 mg BID"),        10),
  identical(extract_dose_mg("2.5mg daily"),      2.5),
  identical(extract_dose_mg("one tablet daily"), NA_real_),
  identical(extract_dose_mg("100mcg daily"),     NA_real_)
)

Summary

  • Start with literal string operations; add regex only when the rule is patterned.
  • R string escaping and regex escaping are separate layers.
  • Anchors distinguish finding a pattern from validating a complete value.
  • Test near misses and missing values, not only examples that should match.
  • Turn a validated pattern into reusable, documented code.

1 · Base graphics, briefly

Base graphics in four functions

par(mfrow = c(1, 3), mar = c(4, 4, 2, 1))
hist(trial$sbp_0, main = "hist", xlab = "SBP baseline")
boxplot(sbp_12 ~ arm, data = trial, main = "boxplot", xlab = "")
plot(trial$sbp_0, trial$sbp_12, main = "plot", xlab = "Session 0",
     ylab = "Session 12")

par(mfrow = c(1, 3)) splits the device into a 1 × 3 grid. It is device state: it stays set until you change it back.

The one base-graphics habit worth keeping

par(mfrow = c(1, 4), mar = c(4, 4, 2, 1))
hist(trial$age,       main = "age")
hist(trial$weight_kg, main = "weight_kg")
hist(trial$sbp_0,     main = "sbp_0")
hist(trial$crp,       main = "crp")

Four columns, one screen, five seconds. You are not making a figure — you are checking that the file is what you think it is. crp is right-skewed and you now know it before you fit anything.

Why we then move on

Base graphics Consequence
Each function has its own arguments hist(breaks=), boxplot(names=), plot(pch=) — nothing transfers
A plot is a sequence of side effects on a device You cannot store it, modify it, or return it from anything
Grouping means splitting the data yourself Colour by arm is your job, and so is the legend
Faceting has no equivalent You manage mfrow and the axis limits by hand
Styling is argument soup Twenty arguments and a par() call to get one journal figure

None of this is a bug. Base graphics is thirty years old, it draws anything, and it is in every R installation. It simply has no grammar — no shared vocabulary that composes.

2 · The grammar of graphics

A plot is a specification

Wilkinson’s idea, by way of Wickham: stop naming chart types. Describe the mapping from data to visual channels, and the chart type falls out.

Instead of Say
“a grouped bar chart” x = arm, y = mean, fill = sex, bars, dodged
“a scatter plot with a trend line” x = Session 0, y = Session 12, points and a smooth
“a boxplot” x = arm, y = SBP, boxplot statistic

There is no list of chart types to memorise. There is a small set of components that combine, which is why the learning curve is worth it: the fifth plot type costs you nothing new.

Seven components, plus a theme

Component Question it answers Code
data What is being plotted? ggplot(trial, ...)
aesthetics Which variable drives which channel? aes(x = arm, y = sbp_12)
geoms What marks appear? geom_point(), geom_col()
stats What is computed before drawing? stat_smooth(), the count in a histogram
scales How do data values become positions, colours, sizes? scale_y_log10()
coords What is the coordinate system? coord_flip(), coord_cartesian()
facets How is the plot split into panels? facet_wrap(~ site_f)
themes What does everything not data-driven look like? theme_minimal()

Only data, aesthetics and one geom are required. Everything else has a default that is usually right.

Minimum viable ggplot, then a layer

ggplot(trial, aes(sbp_0, sbp_12)) +
  geom_point()
ggplot(trial, aes(sbp_0, sbp_12)) +
  geom_point(alpha = 0.6) +
  geom_smooth(method = "lm")

Same data, same aesthetics, one more layer. The second geom inherits both.

aes() means map. Outside means set

ggplot(trial, aes(sbp_0, sbp_12,
                  colour = arm)) +
  geom_point()
ggplot(trial, aes(sbp_0, sbp_12)) +
  geom_point(colour = "steelblue")

Inside aes(): colour carries information, and you get a legend. Outside: colour is decoration, and no legend is possible.

3 · Layers in practice

Distributions: histogram and density

ggplot(trial, aes(sbp_0)) +
  geom_histogram(binwidth = 8,
                 fill = "grey35")
ggplot(trial, aes(sbp_0)) +
  geom_density(fill = "grey80")

Set binwidth in the units of the variable — “8 mmHg” is a decision you can defend. bins = 30 is a default you cannot.

The base R way: hist(trial$sbp_0) · plot(density(trial$sbp_0))

Distributions compared: boxplot and violin

ggplot(trial, aes(arm, sbp_12)) +
  geom_boxplot(width = 0.5)
ggplot(trial, aes(arm, sbp_12)) +
  geom_violin(fill = "grey85")

A boxplot shows five numbers. A violin shows a density. Neither shows n, and neither would look different if half the data were missing.

The base R way: boxplot(sbp_12 ~ arm, data = trial)

Show the data, not only the summary

ggplot(trial, aes(arm, sbp_12)) +
  geom_boxplot(width = 0.45, outlier.shape = NA) +
  geom_jitter(width = 0.12, alpha = 0.7, size = 2)

outlier.shape = NA stops the boxplot drawing outliers that geom_jitter() already drew. Two marks for one observation is a real error, not a style choice.

Comparisons: bars, and position adjustments

ggplot(trial, aes(site_f, fill = sex)) +
  geom_bar(position = "dodge")
position = Shows Good for
"stack" (default) Counts, one bar per group Totals
"dodge" Counts, side by side Comparing subgroups
"fill" Proportions, all bars to 1 Composition — but hides n

Relationships: points and a smooth

ggplot(trial, aes(age, sbp_12, colour = arm)) +
  geom_point(alpha = 0.7) +
  geom_smooth(method = "lm", se = TRUE, alpha = 0.15)

method = "lm" is a model you have chosen. The default, "loess", is a model you have not — and the band is a confidence band for the fit, not a prediction interval.

Uncertainty: an estimate needs an interval

by_arm <- trial |>
  group_by(arm) |>
  summarise(mean_sbp = mean(sbp_12),
            se = sd(sbp_12) / sqrt(n()))

ggplot(by_arm, aes(arm, mean_sbp)) +
  geom_pointrange(aes(ymin = mean_sbp - 1.96 * se,
                      ymax = mean_sbp + 1.96 * se))

Uncertainty over time: the ribbon

by_week <- trial_long |>
  group_by(arm, week) |>
  summarise(m = mean(sbp), se = sd(sbp) / sqrt(n()),
            .groups = "drop")

ggplot(by_week, aes(week, m, colour = arm, fill = arm)) +
  geom_ribbon(aes(ymin = m - 1.96 * se, ymax = m + 1.96 * se),
              alpha = 0.2, colour = NA) +
  geom_line(linewidth = 1) +
  scale_x_continuous(breaks = c(0, 6, 12))

Facets: the same plot, split

ggplot(trial, aes(sbp_0, sbp_12, colour = arm)) +
  geom_point(alpha = 0.8) +
  facet_wrap(~ site_f, nrow = 1)

facet_wrap(~ x) wraps one variable into panels · facet_grid(a ~ b) makes a matrix of two · scales = "free_y" lets each panel set its own axis, which breaks comparability.

Scales: where the transformation belongs

ggplot(trial, aes(arm, crp)) +
  geom_jitter(width = 0.1)
ggplot(trial, aes(arm, crp)) +
  geom_jitter(width = 0.1) +
  scale_y_log10()

scale_y_log10() transforms the scale and keeps the axis in original units. aes(y = log10(crp)) transforms the data and labels the axis log10(crp). Prefer the scale.

4 · Design principles

The perceptual hierarchy

How accurately a reader can decode a quantity, best first:

Rank Channel Use it for
1 Position on a common scale The number that carries your argument
2 Length Second choice; needs a zero baseline
3 Angle, slope Trends, reluctantly
4 Area Rough magnitude only
5 Colour intensity, saturation A third variable, not the main one

Position beats length beats area beats colour. Put your primary comparison on a shared axis, and never encode the effect you care about in colour.

Critique: what is wrong here?

Take thirty seconds. Name three things.

The same data, honestly

Two chart types to refuse

Pie charts ask the reader to compare angles and areas — ranks 3 and 4. Rank the four sites from that. Now imagine a bar chart.

Dual axes are worse, because the reader cannot check them:

# do not
p + scale_y_continuous(
  sec.axis = sec_axis(~ . * 3.2, name = "CRP")
)

The crossing point is set by your choice of scaling. Two facets, or two panels, say the same thing without the implied claim.

Colour-blind-safe, on purpose

# categorical - built in to R since 4.0
palette.colors(8, "Okabe-Ito")
#> #000000 #E69F00 #56B4E9 #009E73 #F0E442 #0072B2 #D55E00 #CC79A7
scale_colour_manual(values = palette.colors(3, "Okabe-Ito"))

# ordered or continuous - built in to ggplot2
scale_colour_viridis_d()   # discrete
scale_fill_viridis_c()     # continuous

Then print it in greyscale. If the groups stop being distinguishable, colour was doing work that shape or a direct label should have been doing.

Label the thing, not the legend

A legend makes the reader look away, decode, and look back — for every series. A label next to the line costs them nothing.

Ink that is not information

Every mark on a figure is either carrying information or competing with it.

Remove Because
Heavy grid lines, panel background They are as visually loud as the data
A legend that repeats the x axis Zero information
A third dimension on a 2-D quantity Distorts area and hides marks
Decorative colour Spends the strongest labelling channel on nothing
Gridlines on a categorical axis There is nothing to read off

theme_minimal() gets you most of the way for free. The rest is deletion, and the test is: remove it. Did the figure lose anything?

5 · Publication output

Finish it: labs() and a theme

p_final <- ggplot(trial, aes(arm, sbp_12)) +
  geom_jitter(width = 0.12, alpha = 0.45, colour = "grey40") +
  geom_pointrange(data = by_arm,
                  aes(y = mean_sbp,
                      ymin = mean_sbp - 1.96 * se,
                      ymax = mean_sbp + 1.96 * se),
                  colour = "#0072B2") +
  labs(x = NULL, y = "SBP at 12 weeks (mmHg)",
       caption = "Mean and 95% CI. n = 30 per arm.") +
  theme_minimal(base_size = 13)
p_final

ggsave(), with the arguments filled in

ggsave(
  filename = here::here("output", "fig-sbp-arm.png"),
  plot     = p_final,
  width    = 6.5,     # inches - the column width of your journal
  height   = 4,
  dpi      = 300,     # 300 for raster; journals ask for 300-600
  bg       = "white"
)
Argument Leave it out and you get
width, height The last size of your plot pane. Irreproducible by construction
dpi 300 by default, but state it — reviewers ask
bg A transparent background that prints as grey in Word
.pdf / .svg extension Vector output: infinitely scalable, and what a typesetter wants

Why the plot pane is not a workflow

Export → paste

Right-click, copy, paste into Word.

Nothing records what produced it. The data changes, the figure does not, and no warning appears anywhere.

ggsave() in the document

The figure is regenerated from the data on every render.

It cannot disagree with the analysis, because there is only one copy of the truth.

A pasted figure is the same class of error as a number typed by hand — and it is harder to spot, because a stale figure still looks like a figure.

patchwork: several panels, one figure

library(patchwork)

p_box  <- ggplot(trial, aes(arm, sbp_12)) + geom_boxplot()
p_scat <- ggplot(trial, aes(sbp_0, sbp_12)) + geom_point()
p_time <- ggplot(by_week, aes(week, m, colour = arm)) + geom_line()

(p_box | p_scat) / p_time +
  plot_annotation(tag_levels = "A")

| side by side · / stacked · plot_annotation(tag_levels = "A") labels the panels A, B, C the way a journal wants them.

Not installed on this machine — install.packages("patchwork").

Summary

  • Choose a figure from the statistical question and observation unit.
  • A ggplot is a specification of mappings, layers, scales, coordinates, facets, and theme.
  • Mapping a variable differs from setting a display property.
  • Show distributions and uncertainty rather than only summary bars.
  • Exported dimensions, labels, accessibility, and reproducibility are part of the figure.

1 · Base R graphics

The teaching data

All observations in this session are synthetic.

A plot starts with a question

Question Useful starting plot
What values and unusual observations occur? Histogram or dot plot
How do participant values differ by arm? Boxplot with individual points
How does baseline relate to follow-up? Scatterplot
How does one participant change over time? Connected points, grouped by ID
How many participants come from each site? Bar chart of counts

The same plotting function may answer different questions. Labels and the observation unit tell the reader which question you mean.

A labelled scatterplot in base R

plot(trial$sbp_0, trial$sbp_12,
     xlab = "Baseline SBP (mmHg)",
     ylab = "Week 12 SBP (mmHg)",
     main = "Baseline and follow-up",
     pch = 19, col = "steelblue")

plot(x, y) puts the first numeric vector on x and the second on y.

Common base R plotting arguments

Argument Meaning Example
pch Point symbol pch = 19 for a filled circle
col Colour col = "steelblue"
cex Symbol/text size multiplier cex = 1.3
lty, lwd Line pattern and width lty = 2, lwd = 2
xlab, ylab, main Axis labels and title ylab = "SBP (mmHg)"

Use ?plot.default and ?par to look up options as needed.

Adding a reference line

plot(trial$sbp_0, trial$sbp_12,
     xlab = "Baseline SBP (mmHg)", ylab = "Week 12 SBP (mmHg)",
     xlim = c(90, 190), ylim = c(90, 190), pch = 19)
abline(a = 0, b = 1, lty = 2, col = "grey40")

a is the intercept and b is the slope. Below the line, follow-up is lower than baseline. This line represents equality, not a fitted regression.

Colours and a legend by treatment arm

plot(trial$sbp_0, trial$sbp_12, pch = 19,
     col = arm_col[trial$arm],
     xlab = "Baseline SBP (mmHg)", ylab = "Week 12 SBP (mmHg)")
legend("topleft", legend = names(arm_col),
       col = arm_col, pch = 19, bty = "n")

arm_col is a named vector: c(Placebo = "#D55E00", Treatment = "#0072B2"). Indexing it by arm assigns the same colour consistently.

New plot or added marks?

Creates a new plot Adds to the current plot
plot() points()
hist() lines()
boxplot() abline()
barplot() text(), legend()

For example, points(x, y, col = "red") adds observations to existing axes. Calling plot(x, y) again normally starts a new plot.

Connected measurements from one participant

weeks <- c(0, 6, 12)
values <- c(trial$sbp_0[1], trial$sbp_6[1], trial$sbp_12[1])
plot(weeks, values, type = "b", pch = 19,
     xlab = "Week", ylab = "SBP (mmHg)", xaxt = "n")
axis(1, at = weeks)

type = "p" draws points, "l" draws lines, and "b" draws both. Base R connects points in supplied order, so arrange time first.

Histogram bins change the picture

saved_par <- par(mfrow = c(1, 2), mar = c(4, 4, 2, 1))
hist(trial$sbp_0, breaks = seq(80, 210, 5),
     main = "5-mmHg bins", xlab = "Baseline SBP (mmHg)")
hist(trial$sbp_0, breaks = seq(80, 220, 20),
     main = "20-mmHg bins", xlab = "Baseline SBP (mmHg)")
par(saved_par)

A vector in breaks specifies bin boundaries. A single number requests an approximate number of bins. A pattern should not depend on one convenient choice.

Boxplots with participant-level values

boxplot(sbp_12 ~ arm, data = trial, outline = FALSE,
        ylab = "Week 12 SBP (mmHg)", xlab = "")
stripchart(sbp_12 ~ arm, data = trial,
           vertical = TRUE, method = "jitter",
           pch = 19, col = "steelblue", add = TRUE)

The formula outcome ~ group splits the outcome by group. The added dots expose individual variation. outline = FALSE avoids drawing extreme observations twice.

Bar charts use counts or summaries

site_counts <- table(trial$site_f)
barplot(site_counts, col = "steelblue",
        xlab = "Recruiting site", ylab = "Number of participants")

table() calculates the counts. barplot() draws their heights. A histogram instead bins a numeric variable such as blood pressure.

Optional: distribution diagnostics

saved_par <- par(mfrow = c(1, 2), mar = c(4, 4, 2, 1))
plot(ecdf(trial$sbp_0), main = "Cumulative proportion",
     xlab = "Baseline SBP (mmHg)", ylab = "Proportion at or below x")
qqnorm(trial$sbp_0, main = "Normal Q-Q plot")
qqline(trial$sbp_0, col = "steelblue")
par(saved_par)

An empirical CDF needs no bins. A Q-Q plot compares sample quantiles with a reference distribution. A roughly straight pattern is not proof of normality.

Multiple panels and graphics state

saved_par <- par(mfrow = c(1, 2))  # one row, two columns
hist(trial$sbp_0)
hist(trial$sbp_12)
par(saved_par)                    # restore changed settings
  • par() affects the current graphics device.
  • Restore settings after the multi-panel display.
  • If separate panels need direct comparison, choose common axis limits.
  • par(mfrow = c(1, 1)) resets the layout, but does not reset every other option.

Saving a base R figure

dir.create("output", showWarnings = FALSE)
png("output/base-sbp.png", width = 6, height = 4,
    units = "in", res = 300)
plot(trial$sbp_0, trial$sbp_12,
     xlab = "Baseline SBP (mmHg)", ylab = "Week 12 SBP (mmHg)")
dev.off()

The file device receives drawing commands until dev.off() closes it. Use pdf("output/base-sbp.pdf", width = 6, height = 4) for vector output.

Base graphics in four functions

par(mfrow = c(1, 3), mar = c(4, 4, 2, 1))
hist(trial$sbp_0, main = "hist", xlab = "SBP baseline")
boxplot(sbp_12 ~ arm, data = trial, main = "boxplot", xlab = "")
plot(trial$sbp_0, trial$sbp_12, main = "plot", xlab = "Week 0",
     ylab = "Week 12")
par(mfrow = c(1, 1))

par(mfrow = c(1, 3)) splits the device into a 1 × 3 grid. It is device state: it stays set until you change it back.

A quick panel of distributions

par(mfrow = c(1, 4), mar = c(4, 4, 2, 1))
hist(trial$age,       main = "age")
hist(trial$weight_kg, main = "weight_kg")
hist(trial$sbp_0,     main = "sbp_0")
hist(trial$crp,       main = "crp")
par(mfrow = c(1, 1))

Four columns, one screen, five seconds. You are not making a figure — you are checking that the file is what you think it is. crp is right-skewed and you now know it before you fit anything.

Two plotting workflows

  • Base graphics: draw to a graphics device, then add points, lines, or labels. Many functions share options such as col, xlab, and ylim.
  • ggplot2: build a plot object, then add or change layers and scales. Grouping, legends, and facets follow shared rules.
  • Both can produce reproducible, publication-quality figures. Choose the workflow that makes your analysis easy to understand and maintain.

2 · Building a first ggplot

Our ggplot2 route

We will keep returning to the same synthetic blood-pressure study.

  1. Build a plot: baseline versus follow-up.
  2. Choose displays: distributions and arm comparisons.
  3. Add summaries: means, intervals, and fitted trends.
  4. Show repeated visits: one line per participant.
  5. Refine and export: scales, labels, accessibility, and file size.

A plot is a specification

Question: How does baseline blood pressure relate to week 12?

  • Data: one row per participant.
  • x: baseline SBP.
  • y: week 12 SBP.
  • Marks: one point per participant.
ggplot(trial, aes(x = sbp_0, y = sbp_12)) +
  geom_point()

We describe the data and its visual mappings, then choose how to draw it.

Seven components, plus a theme

The first four determine the data shown in a layer.

Component In our study
Data Participant records in trial
Aesthetics aes(x = sbp_0, y = sbp_12)
Geom geom_point() draws each participant
Stat Points use raw values; a histogram counts bins

Most early examples need only data, mappings, and a geom.

Scales, coordinates, facets, and theme

The remaining components control how the plot appears.

Component Role Example
Scales Translate values to positions or colours Logarithmic y axis
Coordinates Define the plotting space and view Zoom into a region
Facets Repeat a plot for subsets One panel per site
Theme Style non-data elements Fonts and grid lines

We will add these after the basic plot answers the scientific question.

A first ggplot: axes, then points

ggplot(trial, aes(sbp_0, sbp_12))
ggplot(trial, aes(sbp_0, sbp_12)) +
  geom_point()

Data and mappings establish the axes. The geom adds visible marks.

The pipe and the plus sign have different jobs

trial |>
  filter(site == 1) |>
  ggplot(aes(sbp_0, sbp_12)) +
  geom_point() +
  labs(x = "Baseline SBP (mmHg)",
       y = "Week 12 SBP (mmHg)")
  • |> passes the filtered data into ggplot().
  • + adds plotting components to the ggplot object.
  • Put + at the end of a line when continuing the expression.
  • ggplot(...) |> geom_point() does not mean “add a point layer.”

A ggplot object can be revised

p_scatter <- ggplot(trial, aes(sbp_0, sbp_12)) +
  geom_point()
p_scatter + labs(x = "Baseline SBP (mmHg)",
                 y = "Week 12 SBP (mmHg)")

p_scatter + ... displays a revised plot. To keep that version, assign it: p_scatter <- p_scatter + labs(...).

aes() means map. Outside means set

ggplot(trial, aes(sbp_0, sbp_12,
                  colour = arm)) +
  geom_point()
ggplot(trial, aes(sbp_0, sbp_12)) +
  geom_point(colour = "steelblue")

Inside aes(): colour carries information, and you get a legend. Outside: colour is fixed, and this setting does not create a mapped legend.

Colour, fill, and shape

ggplot(trial, aes(sbp_0, sbp_12, fill = arm)) +
  geom_point(shape = 21, colour = "black", size = 3) +
  scale_fill_manual(values = arm_col) +
  labs(x = "Baseline SBP (mmHg)", y = "Week 12 SBP (mmHg)")

For shapes 21–25, fill controls the interior and colour controls the border. For most other point shapes, use colour. For bars, fill colours the interior.

Choosing a geom

A geom is a layer’s drawing method: points, lines, bars, text, or another mark. Some geoms also compute a default summary before drawing.

Back to the study: distributions

The catalogue shows the range of available marks. Now we use a small set to answer the study questions.

First question: What is the distribution of baseline SBP?

Compare a histogram’s bins with a density curve’s smoothing.

Distributions: histogram and density

ggplot(trial, aes(sbp_0)) +
  geom_histogram(binwidth = 8,
                 fill = "grey35")
ggplot(trial, aes(sbp_0)) +
  geom_density(fill = "grey80")

binwidth = 8 uses 8-mmHg bins. bins = 30 asks for a number of bins. Either choice needs checking: try alternatives and see whether the pattern persists.

The base R way: hist(trial$sbp_0) · plot(density(trial$sbp_0))

Distributions compared: boxplot and violin

ggplot(trial, aes(arm, sbp_12)) +
  geom_boxplot(width = 0.5)
ggplot(trial, aes(arm, sbp_12)) +
  geom_violin(fill = "grey85")

A boxplot shows the median, quartiles, whiskers, and possible outlying points. A violin shows an estimated density. Neither displays the sample size by default.

The base R way: boxplot(sbp_12 ~ arm, data = trial)

Show the data, not only the summary

ggplot(trial, aes(arm, sbp_12)) +
  geom_boxplot(width = 0.45, outlier.shape = NA) +
  geom_jitter(width = 0.12, alpha = 0.7, size = 2)

outlier.shape = NA stops the boxplot drawing outliers that geom_jitter() already drew. Two marks for one observation is a real error, not a style choice.

Overlap can hide observations

ggplot(trial, aes(arm, sbp_12)) +
  geom_point(position = position_jitter(width = 0.12,
                                        height = 0, seed = 6301),
             alpha = 0.6) +
  labs(x = NULL, y = "Week 12 SBP (mmHg)")

Horizontal jitter separates tied marks. height = 0 preserves the measured outcome, and seed makes the offsets repeatable. Alpha reduces visual overlap.

4 · Adding summaries and uncertainty

Participant values and group summaries

Question: What is the average week-12 SBP in each arm, and how uncertain is it?

  1. Keep the participant-level data visible.
  2. Calculate an arm-level summary table.
  3. Draw a summary layer from that table.
  4. State what its interval means.

The raw data and summary layers have different observation units.

What do the intervals mean?

Interval Describes
Mean ± SD Spread of individual measurements around their mean
Mean ± SE Estimated sampling variability of the mean
Confidence interval Uncertainty about a population parameter under a model
Prediction interval Uncertainty about a new individual observation

The same geom_errorbar() can draw any of these. Its inputs do not tell the reader which one you intended. State the meaning and method in the caption.

The earlier mean ± 1.96 * SE examples use an approximate 95% confidence interval. The longitudinal ribbon gives intervals at each visit, not a model of change.

Uncertainty: an estimate needs an interval

by_arm <- trial |>
  group_by(arm) |>
  summarise(mean_sbp = mean(sbp_12),
            se = sd(sbp_12) / sqrt(n()))

ggplot(by_arm, aes(arm, mean_sbp)) +
  geom_pointrange(aes(ymin = mean_sbp - 1.96 * se,
                      ymax = mean_sbp + 1.96 * se))

A layer can use its own data

ggplot(trial, aes(arm, sbp_12)) +
  geom_point(position = position_jitter(width = 0.1, height = 0,
                                        seed = 6301), alpha = 0.3) +
  geom_point(data = by_arm, aes(x = arm, y = mean_sbp),
             inherit.aes = FALSE, shape = 18, size = 5,
             colour = "#0072B2")

Grey points use participant data. Blue diamonds use the summary table. inherit.aes = FALSE makes the summary layer use only its own mappings.

Relationships: points and a smooth

ggplot(trial, aes(age, sbp_12, colour = arm)) +
  geom_point(alpha = 0.7) +
  geom_smooth(method = "lm", se = TRUE, alpha = 0.15)

method = "lm" specifies a linear fit. With method = NULL, ggplot2 chooses loess or GAM according to the largest group’s size. The band describes uncertainty in the fitted mean, not a prediction interval for an individual.

Layer-specific mappings

ggplot(trial, aes(sbp_0, sbp_12)) +
  geom_point(aes(colour = arm)) +
  geom_smooth(method = "lm", se = FALSE, colour = "black") +
  scale_colour_manual(values = arm_col)

Colour belongs only to the points here. The smooth uses all participants together. Putting colour = arm in the global aes() would fit one line per arm.

5 · Showing repeated visits

A new question needs a different data shape

Question: How does blood pressure change over the three visits?

  • One row in trial: one participant, with visits in separate columns.
  • One row in trial_long: one participant at one visit.
  • Individual lines need id, week, and sbp.
  • Group-average lines need an arm-by-week summary.

Session 7’s wide-to-long reshape makes these plots easier to specify.

Plotting repeated visits uses the long table

trial_long <- trial |>
  select(id, arm, sbp_0, sbp_6, sbp_12) |>
  tidyr::pivot_longer(starts_with("sbp_"),
                     names_to = "week", names_prefix = "sbp_",
                     values_to = "sbp") |>
  mutate(week = as.numeric(week))
id arm week sbp
P001 Placebo 0 160
P001 Placebo 6 146
P001 Placebo 12 144

The first participant contributes three rows. Their shared id tells the plot which measurements belong together.

One line per participant

ggplot(trial_long, aes(week, sbp, group = id, colour = arm)) +
  geom_line(alpha = 0.35) +
  facet_wrap(~ arm) +
  scale_x_continuous(breaks = c(0, 6, 12)) +
  scale_colour_manual(values = arm_col, guide = "none")

colour = arm alone would define only two colour groups. group = id tells the line layer to connect each person’s own measurements.

Optional: line versus path

route <- data.frame(x = c(1, 3, 2), y = c(1, 2, 3))
routes <- rbind(transform(route, display = "geom_line"),
                transform(route, display = "geom_path"))
ggplot(routes, aes(x, y)) +
  geom_point(size = 3) +
  geom_line(data = subset(routes, display == "geom_line")) +
  geom_path(data = subset(routes, display == "geom_path")) +
  facet_wrap(~ display)

geom_line() sorts by x within each group. geom_path() follows row order, which is useful for an ordered route through space.

Uncertainty over time: the ribbon

by_week <- trial_long |>
  group_by(arm, week) |>
  summarise(m = mean(sbp), se = sd(sbp) / sqrt(n()),
            .groups = "drop")

ggplot(by_week, aes(week, m, colour = arm, fill = arm)) +
  geom_ribbon(aes(ymin = m - 1.96 * se, ymax = m + 1.96 * se),
              alpha = 0.2, colour = NA) +
  geom_line(linewidth = 1) +
  scale_x_continuous(breaks = c(0, 6, 12))

Facets: the same plot, split

ggplot(trial, aes(sbp_0, sbp_12, colour = arm)) +
  geom_point(alpha = 0.8) +
  facet_wrap(~ site_f, nrow = 1)

facet_wrap(~ x) wraps one variable into panels · facet_grid(a ~ b) makes a matrix of two · scales = "free_y" lets each panel set its own axis, which breaks comparability.

6 · Refining the display

Display choices after the plot works

Our plot already answers a question. Now consider how readers will interpret it.

  • Would a transformation make a skewed variable easier to see?
  • Do we want to zoom, or intentionally exclude data?
  • Can the reader identify groups and understand the labels?
  • Will the exported figure remain readable at its final size?

Scales: where the transformation belongs

ggplot(trial, aes(arm, crp)) +
  geom_jitter(width = 0.1)
ggplot(trial, aes(arm, crp)) +
  geom_jitter(width = 0.1) +
  scale_y_log10()

scale_y_log10() transforms the scale and keeps the axis in original units. aes(y = log10(crp)) transforms the data and labels the axis log10(crp). Prefer the scale.

Zooming versus removing observations

p <- ggplot(trial, aes(arm, sbp_12)) + geom_boxplot()

p + coord_cartesian(ylim = c(120, 160))  # zoom after calculation
p + scale_y_continuous(limits = c(120, 160))
# Out-of-range values become NA before the boxplot calculation
  • Zooming retains the full data in the statistical calculation.
  • Scale limits can change quartiles, smooths, and other calculated summaries.
  • If exclusion is intentional, filter the data explicitly and explain why.

Optional: a small heatmap

site_summary <- trial |>
  group_by(site_f, arm) |>
  summarise(mean_sbp = mean(sbp_12), .groups = "drop")
ggplot(site_summary, aes(arm, site_f, fill = mean_sbp)) +
  geom_tile(colour = "white") +
  scale_fill_viridis_c() +
  labs(x = NULL, y = NULL, fill = "Mean SBP\n(mmHg)")

Each cell represents a site/arm summary. Heatmaps show patterns across many combinations; a dot plot is easier for precise comparisons of a few estimates.

A debugging checklist for plots

Symptom First check
Unexpected colour legend Did a constant go inside aes()?
One line connects different people Is group = id specified?
Bar heights are unexpected Does the geom count rows or use supplied y?
“Removed rows” warning Missing values or scale limits?
Labels or layers disappear Axis limits, layer data, and inherited mappings
Plot does not appear after assignment Print the saved plot object: p

Read the warning and inspect the relevant data before using na.rm = TRUE to suppress a message.

7 · Critiquing and improving a figure

The perceptual hierarchy

How accurately a reader can decode a quantity, best first:

Rank Channel Use it for
1 Position on a common scale The number that carries your argument
2 Length Second choice; needs a zero baseline
3 Angle, slope Trends, reluctantly
4 Area Rough magnitude only
5 Colour intensity, saturation Broad patterns or a third variable

For precise comparisons, prefer positions on a shared axis. Colour remains useful for group identity and for patterns across large matrices.

Critique: what is wrong here?

Take thirty seconds. Name three things.

The same data, honestly

Pie charts and dual axes need care

Pie charts ask the reader to compare angles and areas — ranks 3 and 4. Rank the four sites from that. Now imagine a bar chart.

Dual axes are worse, because the reader cannot check them:

# do not
p + scale_y_continuous(
  sec.axis = sec_axis(~ . * 3.2, name = "CRP")
)

The crossing point is set by your choice of scaling. Two facets, or two panels, say the same thing without the implied claim.

Colour-blind-safe, on purpose

# categorical - built in to R since 4.0
palette.colors(8, "Okabe-Ito")
#> #000000 #E69F00 #56B4E9 #009E73 #F0E442 #0072B2 #D55E00 #CC79A7
scale_colour_manual(values = palette.colors(3, "Okabe-Ito"))

# ordered or continuous - built in to ggplot2
scale_colour_viridis_d()   # discrete
scale_fill_viridis_c()     # continuous

Then print it in greyscale. If the groups stop being distinguishable, colour was doing work that shape or a direct label should have been doing.

Label the thing, not the legend

A legend makes the reader look away, decode, and look back — for every series. A label next to the line costs them nothing.

Ink that is not information

Every mark on a figure is either carrying information or competing with it.

Remove Because
Heavy grid lines, panel background They are as visually loud as the data
A legend that repeats the x axis Zero information
A third dimension on a 2-D quantity Distorts area and hides marks
Decorative colour Spends the strongest labelling channel on nothing
Gridlines on a categorical axis There is nothing to read off

theme_minimal() gets you most of the way for free. The rest is deletion, and the test is: remove it. Did the figure lose anything?

8 · Exporting the final figure

Finish it: labs() and a theme

p_final <- ggplot(trial, aes(arm, sbp_12)) +
  geom_jitter(width = 0.12, alpha = 0.45, colour = "grey40") +
  geom_pointrange(data = by_arm,
                  aes(y = mean_sbp,
                      ymin = mean_sbp - 1.96 * se,
                      ymax = mean_sbp + 1.96 * se),
                  colour = "#0072B2") +
  labs(x = NULL, y = "SBP at 12 weeks (mmHg)",
       caption = "Mean and 95% CI. n = 30 per arm.") +
  theme_minimal(base_size = 13)
p_final

ggsave(), with the arguments filled in

dir.create("output", showWarnings = FALSE)
ggsave(
  filename = "output/fig-sbp-arm.png",
  plot     = p_final,
  width    = 6.5,     # inches - the column width of your journal
  height   = 4, units = "in",
  dpi      = 300,     # 300 for raster; journals ask for 300-600
  bg       = "white"
)
Argument Leave it out and you get
width, height The last size of your plot pane. Irreproducible by construction
dpi 300 by default, but state it — reviewers ask
bg Background comes from the plot theme and may be transparent
.pdf / .svg extension Vector marks scale without pixelation; embedded raster layers still have finite resolution

Why the plot pane is not a workflow

Export → paste

Right-click, copy, paste into Word.

Nothing records what produced it. The data changes, the figure does not, and no warning appears anywhere.

ggsave() in the document

The figure is regenerated when its code executes during rendering.

The script records the data and plotting steps. Check data versions and caching settings so the figure stays aligned with the analysis.

A pasted figure is the same class of error as a number typed by hand — and it is harder to spot, because a stale figure still looks like a figure.

patchwork: several panels, one figure

library(patchwork)

p_box  <- ggplot(trial, aes(arm, sbp_12)) + geom_boxplot()
p_scat <- ggplot(trial, aes(sbp_0, sbp_12)) + geom_point()
p_time <- ggplot(by_week, aes(week, m, colour = arm)) + geom_line()

(p_box | p_scat) / p_time +
  plot_annotation(tag_levels = "A")

| side by side · / stacked · plot_annotation(tag_levels = "A") labels the panels A, B, C the way a journal wants them.

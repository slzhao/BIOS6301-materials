1 · Resampling targets

Three resampling targets

Method Repeated operation Target
Bootstrap Sample observational units with replacement Sampling uncertainty of an estimate
Permutation Reassign labels under a valid null scheme Null reference distribution of a statistic
Cross-validation Fit on training data; predict held-out data Performance on new observations

Replacement alone does not determine validity. Specify the target, the unit, and which relationships the repeated operation must preserve.

The same line of code, twice

sbp <- c(150, 142, 168, 131, 155)

set.seed(1)
sample(sbp, replace = TRUE)   # bootstrap: some values twice, some not at all
[1] 150 131 150 142 155
sample(sbp)                   # permutation: same values, new order
[1] 168 142 131 150 155
  • With replacement: values may repeat or be omitted.
  • Without replacement: same values, new order. This changes their pairing with labels, arms, or times.

For length(x) > 1, sample(x) permutes the values. To sample positions in code, prefer sample.int(length(x)).

2 · The bootstrap, by hand

Why it works at all

The thing you want is a property of the population: the standard deviation of your estimator across repeated samples from it.

You do not have the population. You have one sample — which is your best available estimate of it.

The plug-in principle. Wherever the formula says population, substitute the empirical distribution of your sample, and compute.

So: resample from your data exactly as nature sampled from the population — same size n, drawn with replacement — and watch how the statistic moves.

Resample, recompute, collect

Three lines of code, and none of them are new. sample() is Session 14, indexing a data frame by a vector of row numbers is Session 4, and replicate() is a functional from Session 13.

The statistic, as a function

We want the difference in median 12-week SBP between arms. There is no convenient formula for its standard error — which is exactly when the bootstrap earns its keep.

# Difference in median sbp_12, Treatment minus Placebo.
# Takes a data frame with `arm` and `sbp_12`; returns one number.
med_diff <- function(data) {
  stopifnot(is.data.frame(data), all(c("arm", "sbp_12") %in% names(data)))
  median(data$sbp_12[data$arm == "Treatment"]) -
    median(data$sbp_12[data$arm == "Placebo"])
}

obs_med <- med_diff(trial)

Statistic first, resampling second. If the function is wrong, 2000 resamples make it wrong 2000 times.

The bootstrap standard error

The standard deviation of the resampled statistics is the estimated standard error. That is the whole definition.

se_boot <- sd(boot_med)

[1] 4.433924

This is bias relative to the empirical distribution of the observed sample. It is not the true bias measured against a known population parameter in Session 14.

Percentile and basic intervals

perc <- quantile(boot_med, c(.025, .975))
basic <- 2 * obs_med - quantile(boot_med, c(.975, .025))
rbind(percentile = unname(perc), basic = unname(basic))
            [,1] [,2]
percentile -18.5 -2.0
basic      -14.0  2.5
  • Percentile: use quantiles of the bootstrap estimates directly.
  • Basic: reflect those quantiles around the observed estimate.
  • Both rely on a suitable bootstrap approximation; neither automatically has 95% coverage in small, biased, or irregular problems.

Compare endpoints and assumptions. Do not choose whichever interval gives a preferred conclusion.

Check it where you know the answer

The bootstrap is most trustworthy when you have first watched it reproduce a result you can verify.

mean_diff <- function(data) {
  mean(data$sbp_12[data$arm == "Treatment"]) -
    mean(data$sbp_12[data$arm == "Placebo"])
}

Bootstrap stability

More resamples reduce computational variation; they do not add participants or repair an inappropriate bootstrap scheme.

boot_interval <- function(seed, B = 1000) {
  set.seed(seed)
  groups <- split(seq_len(nrow(trial)), trial$arm)
  ans <- replicate(B, {
    i <- unlist(lapply(groups, function(j)
      j[sample.int(length(j), replace = TRUE)]))
    med_diff(trial[i, ])
  })
  unname(quantile(ans, c(.025, .975)))
}

3 · When the bootstrap fails

Limits of the ordinary bootstrap

Situation Why extra resamples do not solve it
Very small samples The empirical distribution may poorly represent the population
Extremes or boundary parameters The ordinary bootstrap approximation can fail
Heavy tails Usual finite-variance approximations may fail even though a sampling distribution exists
Dependent rows Independent row resampling destroys the study’s dependence

A smooth histogram is not proof of validity. Simulation in a relevant known-truth setting can evaluate coverage; the sampling design determines the resampling unit.

The maximum, bootstrapped

set.seed(18)
boot_max <- replicate(B, max(trial$sbp_0[sample(nrow(trial), replace = TRUE)]))

length(unique(boot_max))                # distinct values across 2000 resamples
[1] 7
mean(boot_max == max(trial$sbp_0))      # how often the resample max is THE max
[1] 0.634

The resampled maximum can never exceed the observed maximum, and it equals it when a unique largest observed value is drawn at all — probability 1 − (1 − 1/n)n ≈ 0.63.

The bootstrap distribution of a maximum is a spike at the observed value with a short left tail. It can be a poor approximation to sampling a new maximum from the population. Increasing B cannot fix that mismatch.

Two packages you should know exist

Not installed here — this is a pointer, not a demonstration.

# boot: the classical implementation. Statistic takes (data, indices).
library(boot)
b <- boot(trial, statistic = function(data, i) med_diff(data[i, ]), R = 10000)
boot.ci(b, type = c("perc", "basic", "bca"))

# rsample: tidymodels. Resamples as a tibble of splits.
library(rsample)
bootstraps(trial, times = 1000)

boot.ci() gives you BCa intervals — bias-corrected and accelerated — which adjust interval endpoints using bias correction and an acceleration term. They still require a suitable resampling scheme and regularity conditions; they do not repair dependence or an unrepresentative sample.

4 · Permutation tests

The null and the reassignment rule

In a completely randomized trial with fixed arm sizes, a randomization test of the sharp null of no effect for any participant holds outcomes fixed and reassigns treatment according to the actual randomization scheme.

For independent observational samples, unrestricted label permutation instead needs exchangeability under the null, such as identical group distributions.

Equal means alone do not guarantee exchangeability when variances differ. Blocked or paired randomization requires restricted reassignment.

Shuffle the labels

obs_mean <- mean_diff(trial)

set.seed(19)
P <- 999
perm_stat <- replicate(P, {
  shuffled <- sample(trial$arm)                 # permutation, not a bootstrap
  mean(trial$sbp_12[shuffled == "Treatment"]) -
    mean(trial$sbp_12[shuffled == "Placebo"])
})

c(observed = obs_mean, perm_mean = mean(perm_stat), perm_sd = sd(perm_stat))
    observed    perm_mean      perm_sd
-12.43333333   0.05789122   3.82457944

Note what is not shuffled: sbp_12 never moves. Only its label does. Jointly reordering outcome-label rows changes nothing. Breaking their pairing creates the reference distribution; the reassignment rule must match the design.

The null distribution

Figure 2: Permutation null distribution of the mean difference, with the observed value.

Centred at zero by construction. The p-value is the proportion of this histogram at least as extreme as the line.

Exact, or Monte Carlo?

With 4 patients per arm there are only choose(8, 4) = 70 possible label assignments. You can enumerate all of them:

small <- trial[c(1:4, 31:34), c("id", "arm", "sbp_12")]
obs_small <- mean_diff(small)

combos <- combn(8, 4)                    # every way to choose 4 "Treatment"
exact <- apply(combos, 2, function(k) mean(small$sbp_12[k]) -
                                      mean(small$sbp_12[-k]))

ncol(combos)                             # the entire reference set
[1] 70
round(mean(abs(exact) >= abs(obs_small)), 4)    # exact two-sided p-value
[1] 0.0571

With 30 per arm there are choose(60, 30) ≈ 1.2 × 1017. So you sample from them instead — that is all “Monte Carlo permutation” means.

A permutation p-value is never zero

n_extreme <- sum(abs(perm_stat) >= abs(obs_mean))
n_extreme                                        # out of 999
[1] 0
c(wrong = n_extreme / P,
  right = (n_extreme + 1) / (P + 1))
wrong right
0.000 0.001

The observed arrangement is one of the possible arrangements. Counting it in both numerator and denominator is not a fudge to avoid zero — it is the correct count.

With P = 999 and no sampled statistic as extreme, report the adjusted Monte Carlo p-value 0.001 and its limited resolution. Increase P if finer resolution is needed; do not report p = 0.

Interpret a permutation result

  • A p-value measures incompatibility with the specified null and reassignment scheme.
  • It does not by itself quantify the effect or remove confounding.
  • Report the observed mean difference alongside the test result.
  • This class computes tests; confidence intervals by inverting suitable tests are a further method, not an impossibility.

For an observational comparison, do not interpret a significant label-permutation result as evidence of a causal treatment effect.

Monte Carlo p-value uncertainty

extreme <- sum(abs(perm_stat) >= abs(obs_mean))
c(adjusted_p = (extreme + 1) / (P + 1),
  min_reportable = 1 / (P + 1))
    adjusted_p min_reportable
         0.001          0.001 
binom.test(extreme, P)$conf.int
[1] 0.000000000 0.003685763
attr(,"conf.level")
[1] 0.95

The interval describes the tail probability estimated by independent random permutations conditional on the observed data. It is not a confidence interval for the treatment effect. Exact enumeration has no Monte Carlo sampling error.

Practice: which reassignment is allowed?

Treatment was randomized separately within each site. A student permutes all treatment labels across the pooled dataset.

What design feature has been lost? What must remain fixed?

Practice: preserve the assignment mechanism

shuffled <- trial$arm
for (i in split(seq_len(nrow(trial)), trial$site)) {
  shuffled[i] <- trial$arm[i][sample.int(length(i))]
}

Within-site assignment counts stay fixed. Use this rule only when it represents the actual randomization; an arbitrary blocking variable does not establish validity.

Perfectly reasonable code. Runs without complaint. Produces a clean, symmetric histogram. The interval comfortably excludes zero.

The cluster bootstrap

Resample patients, and take all of each patient’s rows with them.

ids <- unique(trial_long$id)
rows_by_id <- split(seq_len(nrow(trial_long)), trial_long$id)   # id -> row numbers

set.seed(22)
boot_clu <- replicate(B, {
  picked <- sample(ids, replace = TRUE)              # 60 patients, with repeats
  diff_long(trial_long[unlist(rows_by_id[picked]), ])
})

c(row_se = sd(boot_row), cluster_se = sd(boot_clu),
  ratio = sd(boot_clu) / sd(boot_row))
    row_se cluster_se      ratio
  1.878739   3.222562   1.715279

Compare the two estimated SEs. With strong within-person dependence, independent row resampling understates uncertainty in this example.

Dependence limits information

The teaching generator uses a participant intercept with SD 12 and visit noise with SD 4. Within each arm, its known correlation is:

rho <- 12^2 / (12^2 + 4^2)
c(rho = rho, design_effect = 1 + (3 - 1) * rho,
  approximate_se_inflation = sqrt(1 + 2 * rho))
                     rho            design_effect approximate_se_inflation
                 0.90000                  2.80000                  1.67332

For equally sized clusters with this correlation structure, the design effect explains why three correlated visits are not three independent participants. This calculation uses the generator’s parameters, not a fitted ICC estimate.

Permuting at the wrong level, too

The same mistake, in the other half of the session:

arm_by_id <- trial_long$arm[match(ids, trial_long$id)]

set.seed(32)
p_rows <- replicate(999, {
  s <- sample(trial_long$arm)                    # shuffles visits, not patients
  mean(trial_long$sbp[s == "Treatment"]) - mean(trial_long$sbp[s == "Placebo"])
})

Permute patient assignments, then carry them to visits

p_pats <- replicate(999, {
  assigned <- sample(arm_by_id)
  s <- assigned[match(trial_long$id, ids)]      # join by ID, not row order
  mean(trial_long$sbp[s == "Treatment"]) - mean(trial_long$sbp[s == "Placebo"])
})

c(p_row_unit = (sum(abs(p_rows) >= abs(obs_long)) + 1) / 1000,
  p_patient_unit = (sum(abs(p_pats) >= abs(obs_long)) + 1) / 1000)
    p_row_unit p_patient_unit
         0.001          0.034

Compare the results and their resolution. Randomisation happened to patients, so the permutation must too.

The resampling unit

Design Bootstrap or validation unit Permutation restriction
Independent participants Participant Allowed participant assignments
Repeated visits Participant with all visits Keep one treatment per participant
Cluster randomized Clinic or other randomized cluster Reassign at cluster level
Matched pairs Pair Swap labels within pairs when justified
Time series Dependence-preserving blocks or temporal splits Requires a justified dependence model

Sampling, randomization, and prediction targets can imply different rules. State the rule before using sample().

6 · Cross-validation

Prediction requires held-out outcomes

The target is error for new participants from a stated population, using predictors available when the prediction will be made.

Training error evaluates data already used to fit the model. Cross-validation instead repeats fitting on training folds and predicting an assessment fold.

We will predict 12-week SBP from baseline variables. A week-12 derived variable would be unavailable at baseline, even if it greatly improved the reported score.

The model interface for this exercise

cv_data <- trial[, c("id", "arm", "age", "sbp_0", "sbp_12")]
fit_demo <- lm(sbp_12 ~ sbp_0 + age + arm, data = cv_data)
head(predict(fit_demo, newdata = cv_data), 3)

lm(response ~ predictors, data = ...) fits a linear regression. predict(fit, newdata = ...) applies its learned coefficients. These predictions are in-sample; Session 16 examines model objects in detail.

Missing predictors require a learned rule

cv_missing <- cv_data
cv_missing$sbp_0[c(2, 8, 17, 32, 46, 55)] <- NA_real_
train <- cv_missing[fold != 1, ]
assess <- cv_missing[fold == 1, ]
replacement <- mean(train$sbp_0, na.rm = TRUE)
train$sbp_0[is.na(train$sbp_0)] <- replacement
assess$sbp_0[is.na(assess$sbp_0)] <- replacement

Learn the replacement from training rows; apply the same value to assessment rows. Mean imputation is a teaching example, not a general recommendation for missing data.

Preprocessing belongs inside the loop

cv_predict <- function(data, fold) {
  pred <- rep(NA_real_, nrow(data))
  for (k in sort(unique(fold))) {
    test <- fold == k
    train <- data[!test, ]; assess <- data[test, ]
    m <- mean(train$sbp_0, na.rm = TRUE)
    if (!is.finite(m)) stop("training baseline entirely missing")
    train$sbp_0[is.na(train$sbp_0)] <- m
    assess$sbp_0[is.na(assess$sbp_0)] <- m
    fit <- lm(sbp_12 ~ sbp_0 + age + arm, data = train)
    pred[test] <- predict(fit, newdata = assess)
  }
  pred
}

The same principle applies to scaling, feature selection, and tuning.

Verify the prediction contract

A deliberately leaky version

leaky_data <- cv_missing

The assessment covariates influenced the imputation rule. The scores may be close, and leakage need not improve every realization. Validity follows the information flow, not which score happens to be smaller.

Diagnose leakage before comparing scores

Step Valid location
Fixed, prespecified unit conversion Can be applied to all rows
Mean imputation or scaling estimated from data Training fold
Choose features using outcome associations Training fold, with selection validated
Select a model or tuning parameter Inner validation, separate from final evaluation
Compute RMSE Held-out outcomes after predictions are fixed

A fixed rule is different from a rule estimated using assessment data.

Stratified folds

make_folds <- function(arm, k = 5) {
  fold <- integer(length(arm))
  for (i in split(seq_along(arm), arm)) {
    fold[i] <- sample(rep(seq_len(k), length.out = length(i)))
  }
  fold
}

Grouped and temporal validation

Deployment question Appropriate split idea
Predict a new participant Keep all visits of a participant together
Predict at a new clinic Hold out clinics
Predict future outcomes Train on earlier observations; assess later observations

Random row folds answer the wrong question if the same participant appears on both sides.

Selection and final evaluation

Trying many models and reporting the lowest CV error uses the evaluation data to make a selection. The selected score can be optimistic.

Use a prespecified candidate, an untouched test set, or nested cross-validation:

  1. An outer split reserves data for evaluation.
  2. Inner training splits choose features and tuning parameters.
  3. Refit the selected procedure on outer training data; predict outer assessment data.

After evaluation, a final model can be fitted to the intended full training set.

Lab route and exit check

  1. Bootstrap a treatment-minus-control mean difference within arms.
  2. Compare Monte Carlo and exact permutation calculations.
  3. Build checked folds and held-out predictions with fold-specific imputation.
  4. Compare valid and leaky preprocessing, then repeat the fold assignment.
  5. State how the procedure changes for repeated visits or a new clinic.

Explain: Which uncertainty shrinks with more bootstrap draws? What makes a prediction held out?

Summary

  • Bootstrap, permutation, and cross-validation answer different questions.
  • The resampling unit must preserve the design’s dependence structure.
  • Permutation validity rests on exchangeability under the null.
  • Preprocessing learned outside a training fold leaks information.
  • Finite resampling adds Monte Carlo variability that should be recorded.

A familiar analysis question

Among patients aged 60 or older with a recorded week-12 blood pressure:

  1. Keep the eligible observations.
  2. Calculate change from baseline.
  3. Find the mean change in each treatment arm.

You already have the base-R tools to do this.

One answer using base R

eligible <- trial[trial$age >= 60 & !is.na(trial$sbp_12), ]
eligible$change <- eligible$sbp_12 - eligible$sbp_0
base_summary <- aggregate(change ~ arm, data = eligible, FUN = mean)
base_summary
        arm    change
1   Placebo  -1.00000
2 Treatment -14.33333

Keep rows → add a column → summarize by group.

The same answer using dplyr

tidy_summary <- trial |>
  filter(age >= 60, !is.na(sbp_12)) |>
  mutate(change = sbp_12 - sbp_0) |>
  group_by(arm) |>
  summarise(mean_change = mean(change), .groups = "drop")
tidy_summary
# A tibble: 2 x 2
  arm       mean_change
  <chr>           <dbl>
1 Placebo          -1  
2 Treatment       -14.3

Read |> as “and then.” We will unpack each step today.

Why develop another set of tools?

Base R already supports data analysis. The tidyverse aims to make common workflows easier to express and read:

  • consistent interfaces across related tasks;
  • names that describe the operation;
  • small steps that work together;
  • shared conventions for tabular data.

These are design goals, not a promise that one style is always best.

What is the tidyverse?

A coordinated collection of R packages for data science.

It is not another programming language, and it does not replace R.

Use base R, tidyverse, or a clear combination. The goal is correct, understandable analysis.

History 1 · Plotting and reshaping

In the 2000s, Hadley Wickham developed tools for two practical problems:

  • reshape: getting data into a useful arrangement;
  • ggplot, then ggplot2: expressing plots through a grammar of graphics.

So ggplot2 is a major early foundation—but the story also begins with data preparation.

History 2 · A broader analysis workflow

Other needs led to more packages: text, dates, grouped calculations, and import.

  • plyr preceded dplyr in group-wise data manipulation.
  • reshape and reshape2 preceded tidyr.
  • The collection received the tidyverse name in 2016.

The ecosystem developed gradually; it was not designed all at once.

History 3 · From individual packages to a community

Hadley Wickham played a central early role. Development expanded through collaborators, the RStudio/Posit team, and open-source contributors.

The packages share ideas, but do not all have the same authors.

Why this matters: familiar conventions can carry from one package to another.

2 · The pipe

The pipe, mechanically

x |> f(y) is exactly f(x, y). Nothing more.

round(mean(trial$sbp_0), 1)
[1] 149.5
trial$sbp_0 |> mean() |> round(1)
[1] 149.5

Read |> as “and then”. It moves the innermost thing in a nested call to the front, where you read first.

%>% — because you will read it everywhere

# magrittr / tidyverse pipe — needs library(magrittr) or library(dplyr)
trial %>% filter(age > 70) %>% summarise(m = mean(sbp_0))

# native pipe — base R since 4.1, nothing to load
trial |> filter(age > 70) |> summarise(m = mean(sbp_0))

Two pipe styles

%>% |>
Comes from the magrittr package base R, since 4.1 (2021)
Bare function name x %>% mean works x |> mean is an error; needs mean()

Write |>. Read %>%. Both appear frequently in R examples.

A consistent pattern for dplyr verbs

  • The table is the first argument.
  • Function names describe the task.
  • Most common verbs return another table.
  • Column names can be used directly inside these verbs.

This makes step-by-step pipelines convenient. Still check what each step does to rows, columns, and grouping.

if_else(): first, a working example

flag <- c(TRUE, FALSE)
if_else(flag, 1, 0)
[1] 1 0

The arguments are condition, value if true, value if false.

Both output branches can be combined into one numeric type.

Incompatible output types are a separate issue

ifelse(c(TRUE, FALSE), 1, "x")
[1] "1" "x"
if_else(c(TRUE, FALSE), 1, "x")
Error in `if_else()`:
! Can't combine `true` <double> and `false` <character>.

Base ifelse() converts to character here; if_else() rejects the numeric/character combination.

Adding an NA condition does not fix incompatible output types.

Missing conditions: decide explicitly

flag <- c(TRUE, FALSE, NA)
if_else(flag, 1, 0)
[1]  1  0 NA
if_else(flag, "yes", "no", missing = "unknown")
[1] "yes"     "no"      "unknown"

By default, an unknown condition gives a missing result. missing = specifies an alternative of a compatible type.

case_when()

trial |>
  mutate(bp_cat = case_when(
    is.na(sbp_12) ~ "missing",
    sbp_12 <  120 ~ "normal",
    sbp_12 <  140 ~ "elevated",
    .default      = "hypertensive"
  )) |>
  count(bp_cat)
# A tibble: 4 x 2
  bp_cat           n
  <chr>        <int>
1 elevated        17
2 hypertensive    35
3 missing          3
4 normal           5

Read top to bottom: the first TRUE wins. Put is.na() first, or the missing values fall through into whichever category comes last.

The base R category assignment

bp_cat <- rep("hypertensive", nrow(trial))
bp_cat[trial$sbp_12 < 140] <- "elevated"
bp_cat[trial$sbp_12 < 120] <- "normal"
bp_cat[is.na(trial$sbp_12)] <- "missing"

table(bp_cat)
bp_cat
    elevated hypertensive      missing       normal 
          17           35            3            5

The base version initializes an output vector and replaces values in sequence. The order still matters—but here later assignments overwrite earlier ones.

Before across(): repeat the same operation

demo |> summarise(
  sbp_0 = mean(sbp_0, na.rm = TRUE),
  sbp_12 = mean(sbp_12, na.rm = TRUE)
)
# A tibble: 1 x 2
  sbp_0 sbp_12
  <dbl>  <dbl>
1  147.    135

Two columns, the same calculation. What if there were twenty?

across(): columns plus an operation

demo |> summarise(across(c(sbp_0, sbp_12), mean))
# A tibble: 1 x 2
  sbp_0 sbp_12
  <dbl>  <dbl>
1  147.     NA

Select the columns with the first argument; apply mean to each.

The missing follow-up makes its mean NA. Next we specify how to handle it.

Supply arguments through a small function

demo |> summarise(
  across(c(sbp_0, sbp_12),
         function(x) mean(x, na.rm = TRUE))
)
# A tibble: 1 x 2
  sbp_0 sbp_12
  <dbl>  <dbl>
1  147.    135

Here x is one selected column at a time.

function(x) mean(x, na.rm = TRUE) is a function without a separate name.

\(x) is shorthand for function(x)

demo |> summarise(
  across(c(sbp_0, sbp_12), \(x) mean(x, na.rm = TRUE))
)
# A tibble: 1 x 2
  sbp_0 sbp_12
  <dbl>  <dbl>
1  147.    135

Same operation, same result. Both are base-R function syntax.

Full function writing comes in Session 11; either spelling is fine here.

Reuse the selection helpers inside across()

demo |> summarise(
  across(starts_with("sbp"), \(x) mean(x, na.rm = TRUE))
)
# A tibble: 1 x 2
  sbp_0 sbp_12
  <dbl>  <dbl>
1  147.    135
demo |> summarise(
  across(where(is.numeric), \(x) sum(is.na(x)))
)
# A tibble: 1 x 3
    age sbp_0 sbp_12
  <int> <int>  <int>
1     0     0      1

all_of(wanted) also works when column names are stored in a vector.

Summary

  • The tidyverse connects packages through shared conventions.
  • Tibbles and pipes support step-by-step data analysis.
  • The dplyr verbs express row, column, ordering, derivation, and summary operations.
  • Grouped metadata changes the meaning of later verbs.
  • n() and observed n answer different denominator questions.
  • Base R and dplyr can express the same statistical inclusion rule.

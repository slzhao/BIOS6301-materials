1 · Pseudorandom numbers

How R makes random numbers

A random-number generator is a recipe that produces numbers that behave like random draws. We use them to simulate data, such as patients’ blood pressures.

set.seed(42)
rnorm(3, mean = 120, sd = 10)  # simulate 3 blood pressures
[1] 133.7096 114.3530 123.6313
  • R follows a fixed recipe, so we call these pseudorandom numbers.
  • Think of a long sequence of numbers: each random call moves forward in it.
  • A seed chooses a starting point. The same starting point and the same calls give the same results.

This lets us share an example and get exactly the same simulated data.

The seed picks your starting point

set.seed(42)
rnorm(3)
[1]  1.3709584 -0.5646982  0.3631284
set.seed(42)
rnorm(3)
[1]  1.3709584 -0.5646982  0.3631284

New calls advance the random stream

set.seed(42)
rnorm(3)
[1]  1.3709584 -0.5646982  0.3631284
rnorm(3)
[1]  0.6328626  0.4042683 -0.1061245

Reproducible randomness is not a contradiction. The same seed, RNG settings, and sequence of random calls reproduce a run in the same computational environment. Changing the calls changes the stream used downstream.

.Random.seed remembers where R is

R stores its current generator state in .Random.seed, an integer vector. Think of it as a bookmark: set.seed(42) resets it, and random calls update it.

Original code

set.seed(42)
round(rnorm(3), 3)
[1]  1.371 -0.565  0.363
round(rnorm(3), 3)
[1]  0.633  0.404 -0.106

Rerun this block: both outputs repeat.

An unrelated random call inserted

set.seed(42)
round(rnorm(3), 3)
[1]  1.371 -0.565  0.363
unused <- runif(1)  # moves the bookmark
round(rnorm(3), 3)
[1] -1.105  0.539  0.580

The first output matches. The second changes.

Even unused random draws change later results. Calculations such as 2 + 2 do not.

A seed before each result you want to reproduce

Place set.seed() immediately before each simulation or analysis block whose output should stay the same when earlier code changes.

The result we want to reproduce

set.seed(99)
round(rnorm(3), 3)
[1] 0.214 0.480 0.088

Earlier random work can change

unused <- runif(100)
set.seed(99)  # reset just before this result
round(rnorm(3), 3)
[1] 0.214 0.480 0.088

Both blocks give the same result because set.seed(99) resets .Random.seed immediately before rnorm(3).

For a simulation loop: set the seed once before the loop. Resetting the same seed inside every replicate repeats the same draws.

3 · ADEMP — a protocol for a simulation

A simulation is an experiment

We create data under known conditions, apply a statistical method, and check how well it works across many simulated datasets.

Before running it, write down:

  • What question are we asking?
  • How will we generate the data and analyse each dataset?
  • How will we judge the results?

ADEMP gives us five headings for this plan.

Optional background: Morris, White & Crowther (2019), “Using simulation studies to evaluate statistical methods”, Statistics in Medicine, 38:2074–2102.

ADEMP

You must be able to write down
A Aims The question, in one sentence
D Data-generating mechanism Exactly how one dataset is produced. Every parameter, every value
E Estimands The quantity being estimated — a number that exists before any method touches it
M Methods The procedures being compared, including the naive one
P Performance measures How you decide which method won, and with what precision

Five headings, and the discipline is that you fill them in before you write any code.

ADEMP for an SBP trial

Our simulated trial measures SBP reduction = baseline minus 12-week SBP (mmHg). A larger reduction means a larger drop.

  • A · Aim: How reliably can we estimate the treatment’s additional mean SBP reduction when group sizes and variability differ?
  • D · Data: Generate independent normal SBP reductions. Control: mean 0, SD 12. Treatment: mean δ\delta, SD 4. Group sizes: 25/25, 10/40, or 40/10.
  • E · Estimand: δ=\delta = treatment minus control mean reduction. A value of 6 means an additional 6 mmHg drop with treatment.
  • M · Methods: Difference in sample means, with Welch or pooled t procedures for the confidence interval and p-value.
  • P · Performance: Bias, 95% interval coverage, and detection of an effect. When δ=0\delta = 0, check false positives.

Estimand: the quantity we want to learn

For the same SBP trial, suppose mean reduction is 0 mmHg under control and 6 mmHg under treatment. How much additional reduction does treatment provide?

Term Meaning Example in our simulation
Estimand The true additional mean SBP reduction δ=6−0=6\delta = 6 - 0 = 6 mmHg
Estimator The rule applied to sampled patients Mean reduction in treatment minus mean reduction in control
Estimate The result from one simulated trial For example, 7.2 mmHg additional reduction

We set the population means, so we know the truth is 6. New samples give different estimates, but the target stays 6.

If the estimates average 6.3 over many replicates, estimated bias is 6.3−6=0.36.3 - 6 = 0.3 mmHg. One estimate’s error, 7.2−67.2 - 6, is not the bias.

4 · Building the simulation

Data generation starts with assumptions

A data-generating model describes the population and how we sample from it. We choose this model before choosing an R random-number function.

  • Outcome: each patient’s SBP reduction, baseline minus 12-week SBP. Values can be positive or negative. A negative value means SBP increased.
  • Distribution: what shape, spread, and extreme values are plausible within each treatment group?
  • Structure: are patients independent? Repeated visits or patients within clinics may require a model for their dependence.
  • Parameters: use previous studies, pilot data, or subject-matter knowledge to choose plausible means and SDs. Explore a range when these are uncertain.

Our means and SDs are invented teaching scenarios, not clinical estimates.

Why use a normal distribution here?

We start with normal SBP reductions as a simple reference scenario. This lets us study unequal group sizes and SDs while keeping the distribution’s shape fixed.

For a real project, examine relevant prior or pilot data: group-specific histograms, Q–Q plots, outliers, and plausible ranges. Rough symmetry and modest tails may support a normal approximation. They do not prove it.

A normal model allows any real value. It may be unsuitable if it generates implausible changes, strong skewness is present, or extreme values are common.

Sensitivity check: repeat the study with skewed errors while preserving the population means and SDs. Report whether the conclusions change.

From the SBP model to rnorm()

For one teaching scenario, assume independent reductions within each arm:

Ycontrol∼N(0,122),Ytreatment∼N(6,42). Y_{\mathrm{control}} \sim N(0,12^2), \qquad Y_{\mathrm{treatment}} \sim N(6,4^2).

The treatment group’s population mean is 6 mmHg and SD is 4 mmHg. In the formula the second quantity is variance. R’s sd argument takes the SD.

set.seed(1425)
reduction <- rnorm(n = 5, mean = 6, sd = 4)
round(reduction, 1)
[1] 3.5 9.0 1.1 7.1 1.9

rnorm() implements our assumption. These five patients need not have a sample mean of exactly 6 or a sample SD of exactly 4.

Before a large run, inspect simulated ranges, plots, and group summaries. That checks the generator’s implementation; real-world plausibility needs evidence.

The shape of every simulation

Generate one dataset

# One SBP trial: y is baseline minus 12-week SBP (mmHg).
# Assumptions: independent patients, normal reductions within each arm.
simulate_trial <- function(n_ctrl, n_trt, sd_ctrl, sd_trt, delta = 0) {
  stopifnot(n_ctrl >= 2, n_trt >= 2, sd_ctrl > 0, sd_trt > 0)
  data.frame(
    arm = rep(c("ctrl", "trt"), c(n_ctrl, n_trt)),
    y   = c(rnorm(n_ctrl, mean = 0,     sd = sd_ctrl),
            rnorm(n_trt,  mean = delta, sd = sd_trt))
  )
}

Analyse one dataset

analyse_trial <- function(data, pooled = FALSE) {
  x <- data$y[data$arm == "trt"]
  y <- data$y[data$arm == "ctrl"]
  fit <- t.test(x, y, var.equal = pooled)
  c(est = mean(x) - mean(y), se = fit$stderr,
    p = fit$p.value, lo = fit$conf.int[1], hi = fit$conf.int[2])
}
set.seed(6301)
round(analyse_trial(simulate_trial(20, 20, 12, 4, delta = 8)), 3)

One replicate, then ten thousand

run_scenario <- function(n_sim, n_ctrl, n_trt, sd_ctrl, sd_trt,
                         delta = 0, pooled = TRUE) {
  out <- replicate(n_sim, {
    d <- simulate_trial(n_ctrl, n_trt, sd_ctrl, sd_trt, delta)
    analyse_trial(d, pooled = pooled)
  })
  as.data.frame(t(out))          # n_sim rows, one per replicate
}

analyse_checked <- function(data, pooled = FALSE) {
  tryCatch({
    value <- analyse_trial(data, pooled)
    if (any(!is.finite(value))) stop("nonfinite result")
    list(value = value, error = NA_character_)
  }, error = function(e) list(value = NULL, error = conditionMessage(e)))

Why simulation results have uncertainty

Monte Carlo means using repeated random draws to answer a question.

Suppose a test really rejects 5% of the time under the null. In 1,000 simulated trials, we expect about 50 rejections, but we will not always get exactly 50.

  • A run might give 52 rejections: 52 / 1,000 = 5.2%.
  • A new seed gives new datasets, so the rejection count may change.
  • This variation from using a finite number of replicates is Monte Carlo uncertainty.

A fixed seed reproduces the same answer. More replicates make the answer less sensitive to the particular random draws.

Two kinds of uncertainty

Sampling uncertainty Monte Carlo uncertainty
What varies? A treatment effect estimate across trials A rejection rate across full simulation runs
Example Each trial has 50 patients Each simulation run contains 1,000 trials
What helps? More patients per trial More simulated trials per run

Increasing patients per trial changes the study we are evaluating. Increasing replicates helps us evaluate that same study more precisely.

One calculation for a simulated percentage

The Monte Carlo standard error (MCSE) describes how much a simulated proportion varies across repeated runs of the simulation.

For independent replicates, MCSE=p̂(1−p̂)/B\mathrm{MCSE} = \sqrt{\hat p(1-\hat p)/B}, where p̂\hat p is the observed proportion and BB is the number of replicates.

p_hat <- 52 / 1000
n_sim <- 1000
mcse <- sqrt(p_hat * (1 - p_hat) / n_sim)
round(100 * c(rate = p_hat, MCSE = mcse,
              lower = p_hat - 1.96 * mcse,
              upper = p_hat + 1.96 * mcse), 2)
 rate  MCSE lower upper
 5.20  0.70  3.82  6.58

The rate is 5.2%, with MCSE 0.70 percentage points and an approximate 95% Monte Carlo interval of 3.82% to 6.58%. This run gives little evidence that the true rejection rate differs from 5%.

6 · Type I error and power

The question, restated

Two arms. Different variances — 12 vs 4 mmHg. Different sizes — and it is the combination that does the damage.

The pooled t-test assumes a common variance. It estimates one sps_p from both arms, weighting by degrees of freedom, and gets n1+n2−2n_1 + n_2 - 2 df. Welch estimates each arm’s variance separately and adjusts the df downwards.

t.test() defaults to var.equal = FALSE. The pooled and Welch procedures use different standard-error formulas; neither corrects a wrong sampling unit or a biased dataset.

Four scenarios, δ=0\delta = 0, nsim=10,000n_{\text{sim}} = 10{,}000. If the test is behaving, an individual rejection estimate is typically within about 0.0044 of 0.05. This is an approximate simulation uncertainty range, not a guarantee for every scenario.

Inspect the null p-value distribution

Figure 1: Null p-values, 10,000 replicates, n = 10 / 40, sd = 12 / 4.

For an exact continuous null p-value, the expected count is 500 per bin. Welch is approximate; discrete valid tests may be conservative rather than uniform. Excess near zero can reveal inflated Type I error.

Interpret the method comparison

Welch uses s12/n1+s22/n2\sqrt{s_1^2/n_1+s_2^2/n_2} with approximate degrees of freedom.

  • In this normal unequal-variance scenario, compare its rejection rate with 0.05 using the reported MCSE.
  • The pooled test uses a common variance estimate and can be badly calibrated when the smaller group has the larger variance.
  • This study has not yet measured the cost of Welch under equal variances.

Add an equal-variance scenario before making a claim about that tradeoff.

Power: detecting a specified treatment effect

Suppose treatment truly produces 6 mmHg more mean SBP reduction than control. Our test still asks whether the population mean difference is zero.

Power is the probability that the planned test rejects that null when the specified effect is real. Power of 80% means about 80 of 100 repeated trials would reject it. The remaining 20 would miss the effect (type II error).

To estimate power by simulation:

  1. Specify the effect, distributions, sample sizes, and analysis in advance.
  2. Generate one complete trial under that nonzero effect.
  3. Apply the planned test and record whether p < 0.05.
  4. Repeat independently and calculate the proportion of rejections.

Here we use a two-sided Welch test at 5%. At a true effect of zero, the same calculation estimates type I error instead of power to detect a nonzero effect.

Estimated power for one SBP design

Assume independent normal reductions, 40 patients per arm, SDs 12 and 4, and a true additional reduction of 6 mmHg.

set.seed(1456)
power_run <- run_scenario(2000, 40, 40, 12, 4,
                          delta = 6, pooled = FALSE)
stopifnot(nrow(power_run) == 2000, all(is.finite(power_run$p)))
detected <- power_run$p < 0.05
power_hat <- mean(detected)
power_mcse <- sqrt(power_hat * (1 - power_hat) / nrow(power_run))
round(c(power = power_hat, MCSE = power_mcse), 3)

0.838 0.008

We detected the effect in 1676 of 2,000 trials. The estimated power is 83.8%, with MCSE 0.82 percentage points.

Each replicate contains 80 patients. The MCSE denominator is 2,000 trials.

Power, coverage, and Monte Carlo uncertainty

For the same true effect of 6 mmHg, each simulated trial gives a p-value and a confidence interval for the treatment effect.

Quantity What we count or calculate
Power Fraction of trials rejecting the null effect of zero
Coverage Fraction of treatment-effect intervals containing the true value 6
MCSE of power Uncertainty in the power estimate because we simulated a finite number of trials

An interval [2, 10] mmHg covers 6 and excludes 0: it covers and detects. An interval [−2, 14] mmHg covers 6 but includes 0: it covers but does not detect.

The worked design’s approximate 95% Monte Carlo interval for power is 82.2% to 85.4%. These endpoints describe a probability of detection, not a treatment effect in mmHg.

Simulation for study planning

  • Choose a meaningful effect: justify the difference worth detecting and examine smaller effects too. Do not substitute the observed effect after a trial.
  • Specify plausible variability: larger SDs generally reduce power with the other assumptions fixed. Check a range supported by prior information.
  • Compare sample sizes and allocations: for our mean difference, sampling variance is 122/nctrl+42/ntrt12^2/n_{\mathrm{ctrl}} + 4^2/n_{\mathrm{trt}}. More patients in the noisier control arm can help when total size and per-person costs are fixed.
  • Keep the test rule fixed: a higher significance threshold can raise power but also permits more false positives. Check null calibration first.
  • Refine promising designs: use more replicates near the desired power, report MCSE, and assess sensitivity to the model assumptions.

More patients can raise power. More simulation replicates estimate that power more precisely. Neither 80% nor a single simulated crossing is a universal rule.

What the simulation actually told us

  • The pooled test rejected far more than 5% of null datasets when the smaller arm had the larger variance.
  • Bias estimates were small relative to their Monte Carlo uncertainty in these scenarios.
  • Welch was better calibrated in the unequal-variance scenarios examined.
  • With fixed total size and equal per-person costs, the illustrated allocations favor more observations in the noisier arm; real design constraints also matter.

These conclusions apply to the data-generating scenarios we studied. More replicates improve precision within a scenario. They do not establish that its distribution or independence assumptions describe a real trial.

This is the general move: when you do not know whether a method works under your conditions, build your conditions and find out.

A skewed error with known mean and SD

draw_error <- function(n, target_sd, dgm = "normal") {
  if (dgm == "normal") return(rnorm(n, 0, target_sd))
  if (dgm != "skewed") stop("unknown dgm")
  a <- 0.7
  mu <- exp(a^2 / 2)
  sigma <- sqrt((exp(a^2) - 1) * exp(a^2))
  target_sd * (rlnorm(n, 0, a) - mu) / sigma
}

Subtract the theoretical log-normal mean and divide by its theoretical SD. Centering every generated sample by its own mean would remove sampling variation.

Practice: audit a simulation claim

“The new method has 95% coverage: 950 of 1,000 successful fits covered. Another 200 fits failed. We stopped when coverage first reached 95%.”

Identify the denominator problem, the stopping problem, and the evidence needed before comparing this method with another procedure.

Practice: interpretation

  • There were 1,200 attempts: failure rate is 200 / 1,200.
  • 95% is coverage conditional on successful fitting.
  • Successful coverage per attempt is 950 / 1,200 if failures count as unsuccessful.
  • Stopping on a desired result selects the reported estimate.
  • Predefine replication precision and report both failures and Monte Carlo uncertainty.

  2. Compare both tests on the same dataset, then repeat under null and alternative.
  3. Summarize bias, SE, coverage, rejection, width, and failures.
  4. Add a skewed scenario and report the limits of the comparison.

Summary

  • A seed identifies a pseudorandom stream; it does not make a design valid.
  • Write ADEMP before writing the repetition.
  • Test one simulated replicate before running thousands.
  • Report Monte Carlo uncertainty with every simulated probability.
  • Type I error and power differ by the data-generating parameter, not by the code skeleton.
  • Power calculations support study planning only for the specified effects, designs, and assumptions.
